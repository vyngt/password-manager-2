# VEdge 1.0.0

**The first public release.** VEdge is a local-first password manager for Windows: your
vault is an encrypted folder on your own machine. There is no VEdge account, no cloud
sync, and no server that ever sees your data — nobody can hand over, subpoena, or leak
what they never hold.

That design has a cost, and it's stated plainly below: **you hold the only keys.** Please
read [Before you rely on it](#before-you-rely-on-it) before putting real passwords in.

📖 **[Full User Guide](https://github.com/vyngt/vedge/blob/main/docs/guide/README.md)**

## Install

Download `VEdge_1.0.0_x64-setup.exe` (NSIS) or `VEdge_1.0.0_x64_en-US.msi` (MSI) below.

### 1. Verify the download (recommended)

VEdge 1.0 is an **unsigned** open-source build, so the SHA-256 checksum is your proof the
file is exactly what was published. In PowerShell:

```powershell
Get-FileHash .\VEdge_1.0.0_x64-setup.exe -Algorithm SHA256
```

Compare against `SHA256SUMS.txt` (attached to this release):

```
<PASTE SHA256SUMS.txt CONTENTS HERE AT PUBLISH TIME>
```

If it doesn't match, **delete the file and download it again** — don't run it.

### 2. Expect a SmartScreen warning

Because the build isn't code-signed, Windows will show a blue *"Windows protected your
PC"* dialog on first run: click **More info → Run anyway**.

This is normal for unsigned software — but you should never take that on faith for a
program that will hold all your passwords, which is exactly why step 1 exists. A signing
certificate was deliberately deferred for 1.0 (cost + key custody for a hobby project);
the checksum is the honest substitute.

**Requirements:** Windows 10/11 (64-bit). The Microsoft WebView2 runtime is installed
automatically if you don't already have it.

## What's in 1.0

**Vault & entries**
- Eight entry types: **Login, Card, Identity, SSH Key, API Key, Environment Variables,
  Secure Note, Document** (files encrypted at rest).
- Folders, tags, instant search, filters, saved "smart folder" views, and a command palette.
- **Entry history** — every save keeps the previous version, and you can restore one.
- Trash with restore, so a delete isn't immediately final.

**Passwords & 2FA**
- Generator with three modes: **Random** (length + character classes), **Passphrase**
  (dictionary words), and **PIN** — plus bulk generation.
- Built-in **TOTP**: store the 2FA seed and read the rotating code right on the entry.
- **Password health**: finds weak, reused, and ageing credentials.
- **Breach check** against Have I Been Pwned using k-anonymity — only a partial hash
  prefix ever leaves your machine, never the password. **Off by default; opt-in.**

**Security controls**
- Unlock with **Windows Hello** (biometric) after enrolling with your password.
- Auto-lock on idle, lock on window blur, a hard maximum session length, and OS
  screen-lock detection.
- Clipboard auto-clear on a delay you choose.
- **Audit log** that distinguishes *browsing* an entry from actually **copying or
  revealing** a secret — so you can see what really left the vault.

**Backups & recovery** (three distinct things — the guide explains why that matters)
- **Snapshots** — point-in-time restore points kept inside the vault. Undo a bad change.
- **`.vbk` backups** — the whole vault in one portable file you keep somewhere else.
- **Export / import** — move entries in or out (encrypted archive, or CSV for migrating
  to another product).

**Credential operations**, separated by intent
- **Change master password** · **Rotate Secret Key** · **Recovery Key** (reset a forgotten
  password) · **Re-key** (re-encrypt everything under brand-new keys if you think your
  vault file was copied).

**Interface**
- English and Vietnamese. Light/dark and custom themes. Keyboard-driven throughout.
- Manual **update check** — no auto-install, no account, no identifier, no telemetry. The
  automatic check is **off by default**.

## Security model

- **Two secrets unlock the vault:** your master password *and* a 16-byte **Secret Key**
  (on your Emergency Kit). A leaked or guessed password alone is not enough.
- Both are combined and stretched with **Argon2id (256 MiB)** into a key-encryption key.
- **Every entry gets a fresh data key on every write**, wrapped with AES-KW and sealed
  with **XChaCha20-Poly1305**, bound to the entry's identity and version.
- Keys live only in `mlock`ed, zeroize-on-drop memory while unlocked.
- The database file itself is plain SQLite holding **only ciphertext columns** — the
  encryption is per-entry, at the application level.
- Decrypted secrets **never cross into the UI layer** unless you explicitly copy or reveal
  one — and that action is written to the audit log.

## Before you rely on it

These are the honest, load-bearing facts. They are not fine print.

- 🔴 **Save your Emergency Kit.** It carries your Secret Key, is shown **once**, and cannot
  be regenerated from nothing. Master password + Emergency Kit are what get you back in
  after a reinstall or on a new machine.
- 🔴 **A forgotten password is unrecoverable by default.** The optional **Recovery Key**
  is the cure — but it's a *separate* document, and **neither document opens the vault
  alone**. Keep them apart. Losing your password *and* both kits is unsurvivable; no one
  can recover it for you.
- 🔴 **A snapshot is not a backup.** Snapshots live *inside* the vault folder — they
  protect you from mistakes, not from losing the disk. For that, make a `.vbk` and store
  it somewhere else.
- 🔴 **Keep your old Emergency Kit after rotating your Secret Key.** Local snapshots are
  automatically re-secured to the new key, but external `.vbk` backups are not — the old
  kit stays their only key.
- 🔴 **Re-key protects you going forward; it cannot un-leak the past.** If someone already
  copied your vault *and* had your credentials, re-keying stops future opens of that copy
  — it can't retract what was already read. After a suspected compromise, also change the
  passwords stored inside.

## Known limitations

- **Windows only.** No macOS or Linux build, no mobile app, no browser extension.
- **Unsigned installer** — see the SmartScreen note above.
- **No cloud sync.** Moving a vault between machines is a deliberate, manual `.vbk` step.
- **No auto-update.** VEdge can tell you a new version exists; it will never install code
  by itself. (A silent updater in a process holding your vault keys was rejected on
  purpose.)
- Automated **drag-and-drop** coverage is thin — reordering and drag-to-folder are
  verified by hand.
