# Slice 2.9.1 — Layout, Forms & Scrollbars

The layout/form-ergonomics/scrollbar half of polish (sibling to 2.9's feedback/a11y). Fixes the rough
edges a 2026-07-07 audit found: entry **edit** was squeezed into the 320px detail rail, the SSH private
key was an unusable single-line masked input, there was no minimum window size (the three-pane
overflowed), long table cells forced a horizontal scrollbar, and scrollbars were the native OS ones.
Spec: `.../Specs/2.9.1 - Layout Forms and Scrollbars`. Mockup: `2.9.1 - Roomy Edit Form`.

## Spec-vs-reality corrections (recorded as DRIFT in the tracking note)

- **`DialogSize::Lg` already existed** (`tokens.rs`, CSS `max-width:720px` in `dialog.css`) and
  `.dialog__body` already scrolls internally — the spec's "add `DialogSize::Lg`" work was already done.
  We just pass `size=DialogSize::Lg`.
- **`Textarea` has no reveal/mask** (a `<textarea>` can't use `type="password"`) and its callback is
  `on_change`, not `on_input`. The PEM reveal is net-new (a `masked` prop + `-webkit-text-security`).
- **`Input`'s root is a wrapper `<div>`** with the native `<input>` as a child bound to a *private*
  ref + `on:input:target`. So `node_ref`/`autofocus` had to be **explicit props** bound to the
  `<input>` (spreading them onto `<Input>` would hit the wrapper `<div>`).
- **The spec's create/edit ambiguity** (item #1/module-spec say both open the dialog; item #6 caps the
  create panel width → stays inline) was resolved in favour of **#6**: create stays an inline
  (width-capped) panel, only **edit** moves into the dialog; both consume one extracted `EntryFormBody`.

## What shipped

### vedge-ui

- **`Input` gains `input_ref` + `autofocus`** (`form/input.rs`): an optional external
  `NodeRef<html::Input>` (reconciled with the private clear-focus ref — search-clear still refocuses the
  same element) and an `autofocus` flag, both bound to the native `<input>`. Default-omitted = today's
  behaviour, so the existing call sites are untouched. (Prerequisite for the deferred inline-field
  conversions — see Deferred.)
- **`Textarea` gains a reactive `masked` prop** (`form/textarea.rs` + `.textarea--masked` in
  `textarea.css`): toggles `-webkit-text-security: disc` on the inner `<textarea>` (honoured by both
  target webviews). The masked class is a `class=(…, move || …)` directive on the element, so it doesn't
  fight the component's imperative auto-resize (which owns the `style` attribute, not `class`).
- **Custom scrollbars** (`styles/scrollbar.css`, imported in `index.css`): a thin, token-driven
  `::-webkit-scrollbar` (thumb = `--color-border-strong`, hover = `--color-text-tertiary`, transparent
  track, inset via a padding-box border) that follows whatever theme Rust injects at `:root`. Scoped to
  `::-webkit-scrollbar` only — deliberately **no** `scrollbar-width`/`scrollbar-color`, which in recent
  Chromium disable the pseudo-elements and would drop the styling.

### vedge-app — roomy shared create/edit surface

- **New `EntryFormBody`** (`features/vault/entry_form_body.rs`): the shared form surface = an optional
  type picker (create only — an entry's type is immutable after create) + `<EntryForm>` + `<FolderSelect>`
  + a Cancel/Save footer. It owns no persistence; the host passes `on_save`/`on_cancel` (`Callback<()>`)
  and a `saving` flag (the footer disables + spins Save while saving or the name is blank).
- **`VaultCreateForm`** renders `<EntryFormBody show_type_picker=true>` inline and is now width-capped
  (`max-w-2xl`) so the 2-col form doesn't stretch full-monitor-wide.
- **`VaultDetail`'s Edit** opens `<EntryFormBody show_type_picker=false exclude_id=…>` inside a large
  `Dialog` (`DialogSize::Lg`) instead of mounting the same form in the 320px read rail. Save/Cancel are
  now `Callback<()>`; the dialog's scrim/Escape close routes to cancel. While editing, the compact read
  aside collapses to just its header (the modal is the focus). The command-palette edit path
  (`ui.edit_request` Effect) is unchanged. The reveal-to-edit path (`get_entry`) is untouched — no new
  plaintext crosses to WASM.

### vedge-app — SSH PEM textarea

- **`entry_form.rs`**: the SSH `private_key` field is now a `col-span-2` monospace `<Textarea rows=4
  max_rows=12>` with a reveal `IconButton` header, replacing the single-line masked `secret_field!`.
  The model field stays a `String` and its payload mapping is unchanged, so `to_payload`/`from_payload`
  tests stay green. The reveal is display-only (`masked` toggle) over the already-revealed model value.

### vedge-app — layout guards

- **`tauri.conf.json`**: `minWidth: 960`, `minHeight: 600` — the three-pane no longer overflows.
- **`vault_table.rs`**: Name and URL cells truncate (`max-w-[…] truncate` + `title` tooltip, matching
  the folder/tag pattern); the scroll container gets `min-w-0` so one long URL can't force a horizontal
  scrollbar and shove the Actions column off-screen.
- **`vault_detail.rs`**: the read aside yields on narrow (`w-80 min-w-0`, dropping the hard `shrink-0`).
- **`vault_setup.rs`**: the onboarding container gets `overflow-y-auto` so the Emergency-Kit step can't
  clip at 600px height.

### vedge-app — accessibility

- **The 4 `window_panel` chrome icons** 2.9 left un-hidden (min/max/restore/close) are now wrapped in
  `<span aria-hidden="true">`, completing the 2.9 icon sweep. The wrapping-element pattern sidesteps the
  Leptos RPIT capture bound that `attr:aria-hidden` on an `<Icon>` (passed through `TooltipIconButton`'s
  boxed children) trips; the button's tooltip/label names each control.
- `type="button"` added to the locale toggle and the two unlock text links (were defaulting to submit).

## Deviations (recorded in the tracking note)

1. **The raw-`<button>`/`<input>` → design-system conversions were largely kept raw, with per-site
   reasoning** — a substantive spec-vs-reality finding. The design-system `Button`/`IconButton` are
   sized/styled for standard primary/secondary actions (28px squares, chunky variants, a ghost
   hover-background), which don't cleanly fit the specific controls the spec listed:
   - **Dense hover-reveal icon clusters** (`folder_tree`, `smart_folders` row actions, `vault_list`
     pencil): three 28px `IconButton`s in the ~192px folder pane would crowd out the folder name on
     hover. `vault_table` uses `IconButton` because it has a dedicated `w-[80px]` action column — these
     inline clusters don't.
   - **`tag_assign` chip `×`**: a micro-affordance inside a `text-xs` pill; an `IconButton` would blow
     out the pill.
   - **`vault_unlock_panel` "use master password" + secondary biometric**: intentionally *link-styled*
     text (`text-primary hover:underline`), not chunky buttons.
   - **`folder_customize` icon grid**: a single-select *toggle* swatch with `aria-pressed` and a
     border-only hover — `IconButton` has no pressed prop and adds a `bg-surface-2` ghost hover.
   - **`window_panel` locale toggle**: title-bar chrome text; a `<Button>` would clutter the bar.

   All of these already carry the correct `aria-label`/`aria-pressed`/`type="button"` (a11y is
   complete). The design-system fit + the visual result need the `cargo tauri dev` eyeball the spec
   designates as the gate, which is unavailable headless. The **`Input` `input_ref`/`autofocus`
   prerequisite is delivered** (workstream A), so a GUI-verified follow-up (or a new "compact"
   `IconButton` variant) can complete them without re-doing the prerequisite.
2. **The inline-`<input>` → `<Input>` conversions were deferred** for the same reason plus a functional
   risk: the rename fields commit on blur (blur doesn't bubble to `<Input>`'s wrapper `<div>`, so it
   would need `on:focusout`), and `vault_list`'s search/rename need `NodeRef` `.select()` + arrow-key
   list-nav — converting risks focus/keyboard regressions that need the GUI smoke to confirm.
3. **`DialogSize::Lg` already existed** — the spec's "add `Lg`" premise was stale (no enum/CSS change
   needed).
4. **PEM reveal masks via `-webkit-text-security`** (both target webviews honour it) rather than a
   two-textarea swap; the reveal is display-only over the already-revealed model value.
5. **Create stays an inline width-capped panel; only edit moved to the dialog** (resolving the spec's
   internal #1-vs-#6 contradiction in favour of #6 + the mockup, which only depicts edit-in-dialog).
