# Slice 1.5 — Wire Entry List / Detail / Delete

**Scope:** `vedge-app` only. Closes the `TODO(UI adaptation)` in `pages/v/manage/vault.rs`.

The vault view now reads **live `IndexEntryDto`s** from the backend for the active vault, renders them, and supports **view / copy / delete** — completing the store-data loop with slice 1.4. Secrets are copied by the backend onto the OS clipboard (30 s auto-clear); plaintext never enters the renderer.

## Changed

- **`pages/v/manage/vault.rs`** — `VaultPage` rewired to live data:
  - `items: RwSignal<Vec<IndexEntryDto>>` fetched via `api::vault::list_entries` for `expect_context::<ActiveVault>()`'s path; a `refresh` closure re-runs on mount (Effect on `active.path`), after delete, and on the create-form's `on_created` ping.
  - Client-side instant search via a pure `matches(&IndexEntryDto, &str)` predicate (name/url, case-insensitive) — host-tested.
  - `on_delete` → `api::entry::soft_delete_entry` then re-fetch (and clears the selection if it was the deleted row).
  - `on_copy(FieldSelectorDto)` → `api::entry::copy_field(.., Some(30))` for the selected entry; inline status line reports success/errors.
- **`features/vault/vault_table.rs`** — `VaultTable` retargeted to `Signal<Vec<IndexEntryDto>>`; columns **Name · Type · URL · Updated · Actions** (the old username column is gone — not in the metadata DTO). Row click → `on_select`; the Delete `IconButton` stops propagation so it doesn't also select.
- **`features/vault/vault_detail.rs`** (new) — `VaultDetail` panel: renders metadata (name, type, URL as external link, created/updated) + **Copy Username / Copy Password** buttons for Login entries. No revealed secrets.
- **`features/vault/entry_view.rs`** (new) — pure `type_label` + `short_date` presentation helpers shared by table/detail, host-tested.
- **`locales/{en,vi}/vault.yaml`** — added `col_name`, `col_type`, `col_updated`, `copy_username`, `copy_password`, `copied`, `detail_title`, `close`, `delete`; dropped the now-unused `col_title`/`col_identifier`; retuned `search_placeholder` to "name or URL". (`src/i18n.rs` regenerated.)
- **`features/vault/types.rs`** — retired the legacy `VaultItem` / `VaultItemData` / `VaultItemDataCredential` trio (fully unused after the rewire); `Pagination*` types kept.

## Security boundary

The renderer only ever holds `IndexEntryDto` (metadata — no secret fields, no `username`). Copy goes through the backend `copy_field` command → OS clipboard with a 30 s auto-clear. No reveal, no plaintext in WASM, no client-side `CopyButton` for secrets.

## Deviations from the spec (see slice tracking note)

1. **Client-side search filter** (name/url) instead of server-side `api::vault::search`; placeholder retuned since `username` isn't client-visible. Server-side search (which can match decrypted fields) is the scale follow-up.
2. Copy/delete feedback is an **inline status line** (no `ToastProvider` wired) — consistent with 1.3/1.4.
3. **`VaultItem` retired in 1.5**, not 1.9 — the rewire left it unused; deferring would only add a dead-code warning. 1.9 keeps the end-to-end smoke + docs.
4. Detail is a **metadata + copy-buttons panel** (no edit form — out of scope); Login is the only type with copy actions today.
5. Entry-type labels + the "Created" label are English literals for now (i18n follow-up); the rest of the table/detail is localized (en + vi).
