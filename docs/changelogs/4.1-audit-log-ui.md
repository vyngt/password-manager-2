# Slice 4.1 — Audit-log UI

Lights up the audit read path that the core has been *writing* since Phase 1 but that nothing consumed
(`recent_audit` / `audit_by_entry` were called only from tests). Adds a SQL-filtered, paged repository
query → one **audit-silent** use case → Tauri command → `api::` wrapper → an **Audit page** (`/v/audit`)
with action / entry / date-range filtering, offset pagination, and entry names resolved from `VaultIndex`
**with zero decryption**. Touches no secrets and no crypto. Spec:
`.../Phase 4 - TOTP & Security Hygiene/Specs/4.1 - Audit-log UI`.

## What shipped

### `vedge-core` — query + audit-silent use case + index migration
- `domain/vault/entities/audit_event.rs`: new `AuditQuery { entry_id, actions, since, until, limit, offset }`
  + `AuditPage { events, total }`. Re-exported from `entities.rs` and the crate root (`AuditAction` /
  `AuditEvent` were reachable only via `domain::vault::entities::…` before — closed that gap).
- `application/vault/ports/repository.rs`: new `query_audit(&AuditQuery) -> AuditPage`. The three existing
  audit methods are untouched.
- `infrastructure/sqlite/vault/repository.rs`: `query_audit` builds a SQL `Condition` (entry / action-`is_in`
  / `occurred_at` `gte`..`lt`), `COUNT(*)`s for `total`, then `ORDER BY occurred_at DESC LIMIT/OFFSET`.
  Timestamp range compares as **string** SQL — safe only because `occurred_at` is written exclusively via
  `format_rfc3339_millis` (fixed-width millis-`Z`, pinned by `timestamps.rs`; the invariant slice 3.0
  hardened). The row mapper is **lenient**: an `action` string this build can't parse is skipped + `warn!`ed,
  not propagated (a downgraded build meeting a 4.2/4.3 action degrades one row, not the whole page).
- `application/vault/use_cases/list_audit.rs`: **audit-silent by construction** — reads `audit_log` and
  nothing else; writes no `Viewed`, bumps no `accessed_at`. Clamps `limit` to `1..=AUDIT_PAGE_MAX` (200).
  First deliberate audit-silent read in the codebase (mirrors the unaudited `list_history`).
- Migration `m20260711_100007_create_audit_occurred_index` — `idx_audit_occurred` on `occurred_at` alone
  (the existing `idx_audit_entry (entry_id, occurred_at)` has the wrong leading column for the page's global
  newest-first sort). Idempotent (`if_not_exists`); old vaults gain it on next open.

### `vedge-ipc` / `vedge-tauri` — wire + command
- `vedge-ipc/src/audit.rs`: `AuditQueryDto` / `AuditEventDto` / `AuditPageDto` (snake_case by field naming,
  `#[serde(default)]` optionals) + serde round-trip tests. `action` crosses as the raw `PascalCase` string
  (`AuditAction::as_str`) — inherently forward-compatible; the app owns localization.
- `vedge-tauri`: `dto/audit.rs` converters (`audit_event_to_dto`, `audit_query_from_dto` → a `filter` naming a
  nonexistent action is `CommandError::Invalid`, unlike a *stored* unknown action) + a totality test over all
  15 `AuditAction` variants (compile-time tripwire on a new variant). `commands/audit.rs::list_audit` mirrors
  `list_history` (`&guard` → `&VaultSession`); registered in the handler.

### `vedge-ui` — localizable table headers
- `ColumnDef::header: &'static str` → **`TextProp`** so `DataTable` headers relocalize on a language switch
  without rebuilding the `columns` Vec (every other component already takes `TextProp`; this was an outlier).
  Blast radius one file (`pg_data_table.rs`, `.into()` on 24 literals — `DataTable` had zero production call
  sites). 4.1 is its first production use.

### `vedge-app` — page + feature
- `api/audit.rs`: `list_audit` wrapper (house inline-`Args`).
- `features/audit/filters.rs`: pure, host-tested `AuditFilters` + `AuditView` (filters + offset; **any filter
  mutation resets offset to 0**) + `to_query` (dates → RFC-3339 day boundaries; `until` is inclusive-of-day →
  exclusive next-day). `features/audit/audit_table.rs`: the `DataTable` composition — action (severity
  `Badge`), entry (resolved name / `(deleted entry)` for a dangling id / `—` for a vault-level event), time
  (absolute `long_date` + `clock_time`). Rows are pre-resolved into a plain `AuditRow` inside a
  `Signal::derive` so the `Send + Sync` cell closures never capture signals or call `t_string!`.
- `features/vault/entry_view.rs`: new pure `clock_time(rfc3339) -> "%H:%M:%S"` (host-tested; the app had no
  time-of-day formatter, and audit events are dense in time).
- `pages/v/manage/audit.rs` (`AuditPage`): RwSignal + refresh + `spawn_local` + `Effect` idiom (not
  `Resource`/`Action`); loads the index once via `list_entries` for name resolution; `Select` (action + entry)
  + `DatePicker` (since/until) filters; a **localized** "showing X–Y of N" summary rendered above the table
  (Pagination's own summary is hardcoded English — passed `total_items: None`, localized prev/next/nav labels).
- Route `/v/audit`, sidebar entry + the `layout.rs` label match arm (the `_ => "Vault"` footgun), `data-testid`
  on the sidebar nav rows / page / filters / table / summary / pagination, `audit` i18n namespace (en + vi) +
  `nav.audit`.

## Decisions

- **Plaintext audit columns — accept & document, don't encrypt.** Encrypting `action`/`occurred_at` would
  destroy the `(entry_id, occurred_at)` index *and* the new `occurred_at` index the page's filtering/paging
  depend on, and the exposure class (access-pattern metadata, no secrets) is already accepted for
  `entries.created_at/updated_at/accessed_at/is_trashed`. Threat-model paragraph added to
  `03 Specs/10 Core/10.3 - Key Hierarchy`. Re-open only if the threat model gains "an attacker with the file
  must not learn access patterns".
- **SQL-side filtering + offset pagination**, not in-memory + load-more: the log is unbounded (retention never
  runs) and in-memory filtering breaks pagination (a page of 100 filtered to 3 is not a page of 3).
- **`action` stays a raw `String` on the wire** — no standalone `AuditActionDto` enum (it would be unused →
  trips the workspace `dead_code` deny; a raw string is forward-compatible and makes the "unknown → muted
  chip" path fall out for free). The 15-variant totality guard lives in `vedge-tauri` where the core enum is
  importable.
- **Time column shows an absolute datetime** (`long_date` + `clock_time`), not relative-time-with-tooltip:
  audit events are dense in time (a date alone is useless), it matches the DataTable spec's own audit-log
  example, and it avoids localizing the `RelTime` buckets. Deviation from the spec's "relative + tooltip".
- **`data-testid` on the page / filters / table / summary / pagination wrappers**, not per-row: `DataTable`
  renders `<tr>`s internally and has no row-attr hook. The e2e asserts on the entry **name** (user data →
  locale-independent), so per-row testids aren't needed; a row-attr passthrough is a design-system follow-up.

## Security

No secret handling. Audit rows are plaintext metadata; the listing decrypts nothing, ships no plaintext to
WASM, and (verified by `list_audit_is_audit_silent`) writes no audit rows and bumps no `accessed_at`. Entry
names come from the already-in-memory `VaultIndex` (built at unlock), never a decrypt. The plaintext-columns
exposure is documented in the threat model (above).

## Tests (+21 → 544)

- **core** (`tests/audit.rs`, +8): order-newest-first, filter-by-action (with `total` = matches only — the
  regression test), filter-by-entry (NULL excluded), date-range (since inclusive / until exclusive), paginate
  (120 → limit 50 offset 50 → 20 on the last page, `total==120` every page), **skips-unparseable-action**
  (hand-inserted `FutureAction` via a 2nd connection → other rows returned, page doesn't error, `total` still
  counts it), clamp-limit, and **`list_audit_is_audit_silent`** (the load-bearing one).
- **ipc** (+4): DTO serde round-trips + partial-JSON defaults.
- **tauri** (+3): reject-unknown-action-filter, parse-timestamps, 15-variant totality.
- **app** (+6, pure): `to_query` offset-reset / none-filters / date-bounds / offset-preserved; `clock_time`
  format / degrade.
- **e2e** (`audit_page_shows_copy_event`, `#[ignore]`): create → add Login → reveal (audited `Viewed`) → open
  `/v/audit` → the entry's resolved name renders + a `Viewed` event exists for it (`list_audit` invoke).

- `cargo fmt --all -- --check` + `leptosfmt --check` — clean. `cargo test --workspace --exclude vedge-e2e` —

- Adversarial self-review — reactive-context: localized row strings resolved inside the `rows` `Signal::derive`
  (owner present, relocalizes) with `Send + Sync` cells reading plain data; every `t_string!` in `refresh` /
  `show_error` `untrack`ed or hoisted before `spawn_local` (the `vault.rs` idiom); Select options / labels via
  reactive closures / `Signal::derive`. Migration is idempotent + additive. Timestamp range stays on the
  fixed-width invariant (never a lexical compare of a variable-width DTO string).
- **Human GUI smoke (`cargo tauri dev`) pending, not blocking:** `/v/audit` lists newest-first; the action /
  entry / date filters constrain the SQL query; the entry name resolves (and a hard-deleted id shows the muted
  "(deleted entry)" chip); the console stays warning-free; en ⇄ vi relocalizes the headers + labels.
