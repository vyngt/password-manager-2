# Slice 4.3b — Password Health (UI)

The frontend half of Password Health: the `/v/health` page that runs the
audit-silent bulk scan (shipped callable in 4.3a) and renders the findings —
weak / reused / old — with a summary header, a findings table, and a reuse-groups
view. All wiring is in `vedge-app`; **no new core/ipc/tauri types**. Spec:
`.../Phase 4 - TOTP & Security Hygiene/Specs/4.3 - Password Health` (§UI).

## What shipped

### The page + feature modules (`vedge-app`)
- **`pages/v/manage/health.rs`** (NEW): the `/v/health` page. On-demand scan via a
  **Run scan** button (a full-vault decrypt is user-initiated), the house
  `RwSignal` + `spawn_local` + `Effect` idiom with a **`req_gen` stale-response
  token** (not `Resource`/`Action`), a `Spinner` while scanning, **"last scanned"**
  free from the audit trail (`list_audit(actions=["HealthScanned"], limit=1)`),
  entry-name resolution from the in-memory index (**zero decrypt**), and
  click-through to the entry (sets `VaultUiState.selected_id` → navigate `/v/vault`).
- **`features/health/summary.rs`** (NEW): the summary header — `Badge` counts for
  weak / reused / old **plus an "exempt, not scored" badge** (exemptions shown, not
  hidden) and an overall-health `ProgressBar` (0–100). **No new `vedge-ui`
  component** (spec Decision 5).
- **`features/health/health_table.rs`** (NEW): the findings `DataTable` — columns
  entry / field / issue (badge) / detail (score·`N`/4 · reuse count · age +
  confidence) / severity (badge). Rows are pre-resolved into a `HealthRow`
  (all-final strings) inside a `Signal::derive` **before** the table, because a
  `DataTable` cell closure is `Send + Sync` and can't call `t_string!` (the audit
  table's pattern). `SecretFieldDto::EnvVar` renders its **key**;
  `LoginRecoveryCode` its 1-based index — never a secret.
- **`features/health/context.rs`** (NEW): `HealthReportCtx` — an app-root
  `RwSignal<Option<HealthReportDto>>` holding the ephemeral report (survives
  navigation), mirroring `GeneratedHistoryCtx`.
- **`api/health.rs`** (NEW): the `scan_health` `invoke` wrapper (inline-`Args`
  `call(...)`, mirroring `api/totp.rs`).

### Wiring
- **Wipe on lock** (`app.rs`): `HealthReportCtx` is provided above the router and
  cleared inside the **existing** prev-guarded wipe-on-lock `Effect` (a second
  `health.clear()` line beside `history.clear()` — no new Effect; the 3.5
  precedent). The report is derived data (which entries are weak) → wiped like the
  generator history.
- **Nav triple-edit** (`pages/v/layout.rs`): `SIDEBAR_ITEMS` (a `/v/health` item,
  shield icon, between Audit and Generator) **plus** the `nav_testid` arm
  (`nav-health` — the two silent catch-alls both resolve to the *vault* identity)
  **plus** the label arm (`nav.health`). Route in `routes.rs`; module in
  `manage.rs` / `features.rs` / `api.rs`.
- **Audit catch-up for the 17th action**: the backend already emits
  `HealthScanned` and the tauri totality test is already 17 — the app UI catches
  up: `AUDIT_ACTIONS [&str;16] → 17` (+ doc), and an `action_label` arm.
  `severity()` is left alone (its `_ => Default` is correct; an explicit arm trips
  `match_same_arms`).

### i18n
- **`locales/{en,vi}/health.yaml`** (NEW, 47 keys each), `nav.yaml` (`health:`),
  `audit.yaml` (`action_health_scanned:`), `build.rs` (`"health"` namespace).
  Detail strings are composed with `format!` + plain-key labels — this codebase
  uses no `t_string!` interpolation.

### e2e
- **`scan_health_shows_findings`** (`daily_loop.rs`): two logins share a password
  → run the scan from `/v/health` → the findings table renders the resolved entry
  name (DOM, locale-independent) → assert a **Reused** finding + a `HealthScanned`
  audit row via `invoke` (backend, locale-independent). Console-clean guard passes.

## DRIFT carried from 4.3a
The shipped age model is **2-tier** (`AgeConfidenceDto` is `Exact | Estimated`
only; the spec's history middle tier was dropped in 4.3a self-review). The UI
renders exactly those two confidence chips. **No new ipc DTOs this slice → the 4.2
wasm-wire-test trap does not apply.**

## Self-review outcomes
Three adversarial finder angles (reactive-context, cross-file/i18n parity,
e2e/wire shapes). Cross-file/i18n came back clean (50 health keys parity-matched
across both locales; nav triple-edit + audit catch-up + wipe-on-lock all correct).
Four fixes applied:
- **Panic-after-disposal:** the scan future read `req_gen.get_value()` (a
  component-scoped `StoredValue`); the scan is the app's slowest op, so navigating
  away / auto-locking mid-flight disposes it and the read would panic. → guarded
  with `try_get_value()`.
- **Misleading health gauge:** `health_pct` summed `weak + reused + old`, which
  double-counts an entry hit by several dimensions (and `old` is entry-level vs a
  field-level denominator) — a 50%-healthy vault could read 0% red. → the gauge is
  now **entry-level**: distinct entries with any finding, over `entries_scanned`.
- **Reuse-group double-name:** `reuse_groups` deduped members by display name (two
  entries can share a name), undercounting a group's card vs the row's `count`. →
  deduped by `entry_id`.
- **Confounded e2e audit assertion:** the `HealthScanned` check ran *after* the
  test's own `scan_health` invoke (which writes its own row). → moved **before** it
  and tightened to **exactly one** row, so it verifies the *UI* path audited.

**Accepted:** the reactive-context paths (`untrack`-hoisted reads, `Signal::derive`
owners) are clean; the e2e name-based table-wait couples to the index load, but
that is inherent to testing the zero-decrypt name resolution (20s budget, low risk).
