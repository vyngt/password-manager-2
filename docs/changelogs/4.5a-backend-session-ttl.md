# Slice 4.5a — Backend Session TTL

Move the auto-lock timer out of the renderer. Until now the backend held the
unlocked `VaultSession` — **KEK mlock'd and live** — until something *asked* it to
lock, and the only thing that asked was a 1 Hz timer **in WASM**. A hung,
detached, or suspended WebView kept the KEK hot indefinitely; the configured
"auto-lock" was a renderer promise, not an enforced invariant. 4.5a makes it a
**backend-enforced hard ceiling**: an absolute wall-clock TTL, a background reaper
that actually zeroizes the KEK on time, and a frontend teardown that wipes the
decrypted material the renderer holds. Spec:
`.../Phase 4 - TOTP & Security Hygiene/Specs/4.5a - Backend Session TTL`.

**One PR, zero new dependencies** (one tokio *feature*, `time` — not a new crate),
zero migrations, zero new `AuditAction` variants (reuses `Locked`).

## 🔴 The hazard this slice had to avoid

All three existing lock paths end at `active.path.set(None)`, and `app.rs` hangs a
prev-guarded `Effect` off that transition which **wipes the generator session
history (`Zeroizing` plaintext passwords) and the last health report from WASM**. A
backend lock that doesn't drive that transition would zeroize the KEK in Rust while
leaving decrypted secrets in the renderer's heap — making the app *less* safe. So
every mechanism below terminates at `active.path.set(None)`, and the e2e asserts the
**DOM** (back at `/`, history empty on re-unlock), not just `is_unlocked`.

## What shipped

### Core (`vedge-core`)
- **`use_cases/lock_vault.rs`**: factored out `pub async fn record_lock(session: &VaultSession)`
  — appends the `Locked` row via a cloned `repo` `Arc` **without** consuming the
  session. `lock_vault(session)` now calls it then drops. This is the shape that lets
  a caller holding only a `&VaultSession` (behind an `Arc<Mutex<…>>` it can't move
  out) still land the audit row and then zeroize on last-clone drop.

### Shell (`vedge-tauri`)
- **`state.rs`**: the session registry value is now `SessionSlot { handle, expires_at: Option<DateTime<Utc>> }`
  (wall-clock deadline, **not** `Instant` — `Instant` doesn't advance across suspend
  on Windows). `get_session` is TTL-aware (expired ⇒ evict + `SessionExpired`);
  `is_unlocked` is TTL-aware (present **and** not expired) — it must be, the e2e
  asserts lock state exclusively through it. `insert_session(id, session, ttl)` stamps
  the deadline; `touch_deadline(id, ttl)` re-stamps on re-auth; `sessions_handle()`
  hands the reaper a clone of the map `Arc` without exposing the whole `AppState`;
  `drain_expired_sessions` removes past-deadline slots for the reaper. Pure
  `deadline_passed` / `deadline_from_ttl` (overflow-safe `checked_add_signed`).
- **`scheduler.rs`** (NEW): a `tauri::async_runtime::spawn`'d 5 s loop started in
  `lib.rs .setup`. Each tick drains expired slots and, per slot, `handle.lock().await`
  → `record_lock(&guard)` → drop — **audit-then-drop**. The lock wait behind a slow
  command is correct (the KEK can't zeroize until it finishes). Built as the in-process
  periodic task the (never-existent) Elixir sidecar was imagined to be; 4.5b bolts the
  screen-lock poll onto the same tick.
- **`commands/vault.rs` `lock_vault`**: rewritten onto the same `remove → lock().await →
  record_lock → drop` shape. **Deleted the `Arc::try_unwrap` × 256 spin**, which on
  timeout dropped the `Locked` audit row silently (an opportunistic bug fix the reaper's
  design forced).
- **`CommandError::SessionExpired`** — the 5-hop unit-variant pattern mirroring
  `DocumentTooLarge`: `error.rs` variant · `envelope.rs` `SESSION_EXPIRED` const ·
  `api/error.rs` variant + `from_envelope` arm · `locales/{en,vi}/unlock.yaml` ·
  wire-shape test (`{"kind":"SessionExpired"}`, no message).
- **`setup/services.rs` `session_ttl(state)`**: two-gate seam mirroring `resolve_breach`
  — under a debug build **and** a numeric `VEDGE_E2E_SESSION_TTL_SECS`, a forced short
  TTL wins; otherwise the ceiling comes from `security.prefs.session_max_minutes`
  (default **480** = 8 h; `0` ⇒ `None`, disabled). Threaded into every `insert_session`
  (unlock / create / biometric / recovery). `change_password` calls `touch_deadline`
  after success (re-auth resets the deadline — Decision 6; otherwise a password change
  followed by a reap would bounce the user to a screen where the *old* password fails).
- **`Cargo.toml`**: tokio gains the `time` feature (for `tokio::time::sleep`). No new
  crate.

### App (`vedge-app`)
- **`api/vault.rs`**: `is_unlocked(vault_path) -> Result<bool, ApiError>` wrapper (the
  backend command existed but had no frontend wrapper).
- **`features/vault/auto_lock.rs`**: an **always-on** 1 Hz backend-lock poll (set up in
  the component body, cleared on unmount) that `spawn_local`s `is_unlocked` and, on
  `false`, bumps the **same** `lock_trigger` the idle timer uses — reusing the existing
  lock `Effect` (→ `active.path.set(None)` → nav), so the WASM-wipe teardown is reused
  verbatim. `api::vault::lock` on an already-backend-locked vault returns `VaultNotOpen`
  (ignored); the teardown still runs.
- **`security_prefs.rs`**: `session_max_minutes` (`#[serde(default)]`, default 480) + the
  `Default` line; both round-trip / missing-fields tests extended.
- **`settings.rs`**: a Security `<Select>` row (Off / 1 h / 4 h / 8 h / 24 h) mirroring
  the auto-lock control; new `settings.session_max*` i18n in **en + vi**.

### Tests
- Tauri unit/integration (`state.rs`): `deadline_from_ttl_none_never_expires`,
  `ttl_uses_wall_clock_not_instant`, `get_session_expired_evicts_and_errors`,
  `is_unlocked_is_ttl_aware`, `session_max_zero_disables_expiry`,
  `touch_deadline_resets_expiry`, `reaper_audits_locked_even_under_contention` (a held
  clone during the drain — the exact case the old `try_unwrap` spin dropped the row on).
  Wire-shape test in `error.rs`; `maps_session_expired` in `api/error.rs`;
  `security_prefs` tests extended.
- **e2e `ttl_expiry_wipes_wasm_plaintext`** (`VEDGE_E2E_SESSION_TTL_SECS`, per-scenario
  via the new `Session::launch_with_env`): seed the generator history → wait out the
  TTL → assert `is_unlocked == false` **AND** DOM back at `/` **AND** history empty on
  re-unlock.

## Deviations / DRIFT from the spec
- **Scheduler is a concrete periodic task, not a `dyn ScheduledJob` trait.** The spec
  sketched a `ScheduledJob` trait with an `async fn run`. A `dyn`-dispatched async trait
  needs `async_trait`, which is **not** a `vedge-tauri` dependency, and "zero new deps"
  is a 4.5a acceptance criterion. All current (and 4.5b's) jobs share one 5 s tick, so
  the trait's value (heterogeneous intervals, dyn dispatch) isn't needed yet; the
  "one task, multiple sweeps" intent is honored structurally. The trait can land in 4.6
  if a third, differently-timed job (`run_maintenance`) genuinely needs it.
- **Backstop C realized via the poll + typed error, not a separate global interceptor.**
  The app has no single seam through which every command's `ApiError` flows, and the B
  poll drives DOM teardown within ≤1 s of expiry (B ⊇ C in practice). The `SessionExpired`
  kind still ships end-to-end so a command that races expiry degrades to a typed,
  localized error rather than a generic transport failure.
- **The always-on poll is independent of the idle timer**, not folded into it. The idle
  interval only exists when `auto_lock_minutes > 0`; the backend TTL must be enforced
  even when idle auto-lock is disabled, so the poll runs on its own interval.
- **`get_session` eviction is audit-silent.** On the rare path where a command hits an
  expired-but-not-yet-reaped session, `get_session` evicts + errors without an audit row
  (it's sync, can't `await` an append). The reaper (≤5 s) and the frontend-poll→`lock_vault`
  path both land the `Locked` row first in the normal case; the security property
  (zeroize) still holds via `Drop`.
- **Settings control is a `<Select>` (minutes), not a `<Toggle>`.** A 0-disables minutes
  value is structurally the auto-lock Select, not the lock-on-blur boolean toggle.

## Self-review outcomes
Three adversarial finder angles (backend correctness, frontend reactive-context,
cross-file/e2e parity). Verified clean: no deadlock (the `StdMutex` guard is never
held across an `.await`), audit-then-drop + KEK-zeroize ordering, TTL overflow-safety,
`session_ttl` fail-safe-to-480, scheduler sharing the same map `Arc`, the frontend
poll's owner-safety (untracked reads + writes only), interval teardown, i18n parity,
`insert_session` ripple, and the "one tokio feature, not a new crate" claim.
**Six fixes applied:**
- **Spurious lock on a transient IPC error (frontend).** The poll's
  `!is_unlocked(..).unwrap_or(false)` mapped any `Err` (Transport / (de)serialize) to
  "locked" → ejected the user mid-task. Now locks **only** on a definitive `Ok(false)`.
  *(This is what the pre-fix e2e caught: `lock_on_blur_respects_dialog_guard` flaked
  because a blur-time invoke error spuriously locked the vault.)*
- **Repeated teardown during the async lock window (frontend).** Added a `checking`
  guard (one probe in flight) + a `locking` latch (disarm after the first detected
  lock) so the teardown + toast fire exactly once — mirroring the idle path's
  synchronous deadline disarm.
- **Dead `session_expired` copy (both reviewers).** The localized string + typed error
  were provisioned but never displayed. Now the backend-lock poll shows a Warning toast
  with `unlock.session_expired` — realizing backstop C's visible cue on a TTL lock.
- **`insert_session` rejected an expired-but-unreaped slot (backend).** A re-unlock in
  the expiry-before-reap window failed "already unlocked" (+ a wasted KDF). Now it
  overwrites an expired slot and only rejects a genuinely **live** one; pinned by
  `insert_session_overwrites_expired_but_rejects_live`.
- **`change_password` could be reaped mid-KDF (backend).** If the deadline fell in the
  ~1-2 s KDF window, the reaper could lock the user out from under a successful change
  (violating Decision 6 unconditionally). Now the deadline is refreshed **before** the
  KDF as well as after success.
- **e2e DOM selector.** The teardown assertion waited for `launch-new-vault` (the
  empty-launch CTA), but a post-lock screen shows the **populated** vault picker →
  wait for `[role='option']` instead.
**Accepted (documented DRIFT, not fixed):** `get_session` evicting an expired session
is audit-silent — the scheduler doc was softened from "records **every** timer-driven
lock" (the reaper is the *normal*, not sole, audit path; the rare `get_session`-wins
race skips the row, but zeroize still holds via `Drop`). The Settings `<Select>` blanks
on an out-of-band `session_max_minutes` — unreachable in normal use (only this Select
writes it), consistent with the sibling auto-lock / clipboard Selects.
