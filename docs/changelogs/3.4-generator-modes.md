# Slice 3.4 — Generator Modes

Ships the four remaining generator modes the phase promised — **passphrase (EFF 7776) / PIN /
pronounceable / pattern** — each returning `(Zeroizing secret, entropy_bits)` from **one code path**
behind a new `GenSpec` dispatch, plus a **mode picker** in the panel. The defining constraint is
**honest per-mode entropy**: the meter reports the entropy of the *generation process*, never a
property of the output string (per `05 Research/Core Hardening/07 - Generator Entropy Notes`). Almost
all work is in the pure, host-testable `vedge-generator` crate; the app side is a picker + per-mode
controls that reuse the shipped shared Output row and entropy meter, so the meter's "cannot disagree"
guarantee holds across every mode. Spec: `.../Phase 3 - Password Generator/Specs/3.4 - Generator Modes`.

## What shipped

### Engine — `vedge-generator` split into per-mode modules

The single `lib.rs` became a facade over submodules — `charset` (shared class pools + `sample`),
`entropy` (all float/int math under one allow-scope), `random` (the slice-3.1 mode moved **verbatim**,
its tests proving parity), `passphrase`, `pin`, `pronounceable`, `pattern`, and `wordlist`. New public
API, additive:

```rust
pub enum GenSpec { Random(RandomConfig), Passphrase(PassphraseConfig), Pin(PinConfig),
                   Pronounceable(PronounceableConfig), Pattern(PatternConfig) }  // Clone
pub fn generate(spec: &GenSpec) -> Result<GeneratedSecret, GenError>;
pub fn entropy_bits(spec: &GenSpec) -> Result<f64, GenError>;
pub enum Separator { Hyphen, Space, Dot, Underscore, None }   // Copy
```

`generate_random` / `random_entropy_bits` are **retained** as the `Random` arm's delegates (3.1/3.3
unaffected). `GenError` gained three payload-free variants (`WordCountOutOfRange`, `EmptyPattern`,
`InvalidPattern`) and stays `Copy`. Each mode has an `*_entropy(cfg)` preview fn and an
`*_with<R: Rng>(cfg, rng)` generate fn; the generate fn calls its own entropy fn for the number, so a
`preview == generate` test passes per mode (the one-code-path invariant).

**Honest per-mode entropy** (all math centralized in `entropy`):

| Mode | `entropy_bits` |
| --- | --- |
| Passphrase | `words × log2(7776)` (+ `log2(10)` when a digit is appended) |
| PIN | `length × log2(10)` (6-digit ≈ 19.9 bits → correctly *weak*, with a context caption) |
| Pronounceable | `⌈len/2⌉·log2(20) + ⌊len/2⌋·log2(6)` (CV-alternation, a structured subset) |
| Pattern | `Σ log2(pool)` over non-literal tokens; literals contribute 0 |

The **pattern grammar** (`a A 9 # *` + `\x` escape + literal-else) parses once into a `Vec<Token>` that
both generate and entropy consume, so they can't disagree. Validation order: dangling `\` →
`InvalidPattern`; no random token (empty or all-literal) → `EmptyPattern`; `> MAX_LEN` output →
`LengthOutOfRange`.

### Wordlist — the repo's first embedded asset

`crates/vedge-generator/src/wordlists/eff_large.txt` — the **EFF Large Wordlist** (7776 words, dice
column stripped, one per line, LF-pinned via a new `.gitattributes`). Pulled in with `include_str!` and
parsed once into `static WORDS: LazyLock<Box<[&'static str]>>`. A `sha2` **dev-dependency** (test-only,
matches vedge-core's version) lets `wordlist_sha256` assert the committed file's SHA-256
(`abae4976…67ba`, hashed as `WORDS.join("\n")` to dodge CRLF drift); `wordlist_count_and_unique` asserts
exactly 7776 unique entries. Compiles for `wasm32` (`LazyLock` is fine single-threaded).

### App — mode picker + per-mode controls

`GeneratorPanel` gained a `SegmentedControl` first section (Random · Passphrase · PIN · Pronounceable ·
Pattern). The **Output row and entropy meter stay shared** — both read the active `GenSpec` built by a
`build_spec(prefs, pattern)` helper, repointed from `random_entropy_bits`/`generate_random` to
`entropy_bits`/`generate`. The config controls swap by mode (`EitherOf5` over a `mode` `Memo`, so the
section only rebuilds on a mode switch, not on every field edit): random keeps length + classes;
passphrase gets word-count + separator `Select` + capitalize/number toggles; PIN a length slider + the
honest caption; pronounceable a length slider; pattern an `Input` + token legend. A mode switch
regenerates from the picker's `on_change` **event handler** (not an Effect), giving fresh output while
the meter tracks every edit live. Every `GenError` variant maps to an i18n key in the meter's error
readout. Both mount sites inherit the picker (the popover widened `w-80` → `w-96`). New en + vi keys.

### Shared preset — `GeneratorPrefs` extended, still `Copy`

`GeneratorPrefs` gained `mode` + the per-mode `Copy` fields (`words`, `separator`, `capitalize`,
`include_number`, `pin_length`, `pron_length`), all `#[serde(default)]`, via two app-side serde mirrors
(`GenMode`, `SeparatorPref`) that keep `vedge-generator` serde-free. The struct **stays `Copy`** — the
free-text **pattern string is a session-local `RwSignal` in the panel, not persisted** (persisting it
would force non-`Copy`; documented deviation). So mode + every mode's config restore across restart. The
random fields are untouched, so `RandomConfig::from(prefs)` and the **3.3 inline Login wand stay random**
(product decision, confirmed).

## Decisions

- **Module split** over one file — the shipped random mode moved verbatim (its tests are the parity
  gate); every new mode is co-located with its own `preview == generate` test.
- **Passphrase `include_number` appends to a fixed word (the last)** — the position is deterministic, so
  the process entropy is exactly `+log2(10)` (matching the spec formula + the "don't credit the position"
  directive). A random target word would require `+log2(10·words)`.
- **`sha2` as a dev-dep**, not a runtime dep — keeps the engine dep-free and off the wasm surface while
  still asserting asset integrity.
- **PIN reuses `MIN_LEN..=MAX_LEN`** (4..=128); the UI slider caps each mode's range sensibly (words
  3..=12, PIN 4..=12, pronounceable 6..=32).

## Security / memory hygiene

All secrets stay `Zeroizing<String>`; nothing is persisted (session history is 3.5). No secret crosses
IPC (the engine runs in the renderer; copy still routes through the hardened 3.2 `copy_text`). No secret
logging. The wordlist is public data (~64 KB), not a secret. Passphrase draws are CSPRNG-uniform (no
modulo bias, guarded by `word_sampling_is_broad`).

## Tests (+26)

`vedge-generator` now has **32 tests** (was 8): per-mode closed-form entropy, `preview == generate` per
mode, format (passphrase word-count/separator/capitalize/fixed-digit; PIN all-digits/exact-len;
pronounceable CV-alternation; pattern tokens/literals/escape/unicode), errors, wordlist count/uniqueness/
SHA-256, unbiased word-sampling, and cross-mode dispatch parity. `generator_prefs` gained per-mode
builder + value-round-trip tests. Panel wiring is UI (no host tests, as in 3.1/3.3).

## Out of scope

Bulk generate + session-only history → **3.5** (the modes feed it). Driving the inline Login button by a
persisted non-random mode → deferred by the product decision (inline stays random). `zxcvbn` scoring for
user-entered passwords → Phase 4. Pronounceable add-on digit/symbol + extra pattern tokens → follow-ons.
Persisting the free-text pattern string across restart → trivial follow-up (would drop `Copy`).
