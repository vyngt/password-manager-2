# Slices 2.5.1 / 2.5.2 / 2.5.3 — Folder extensions

The three owner-requested extensions deferred from slice 2.5 (Folders UI). Each is one commit on the
branch `feature/2.5.x-folder-extensions`; one PR. Unlike 2.5 (which was `vedge-app`-only), 2.5.1 and
2.5.2 touch the encrypted payload and the DTO layers, and 2.5.2 adds a Tauri command — but **no SQLite
migration is required**: `IndexEntry` (`vedge-core/.../domain/vault/index.rs`) is an **in-memory**
projection rebuilt from the decrypted payload on unlock, not a DB-column projection, so new metadata
fields ride entirely inside `CommonMeta` (serialized into the ciphertext) and are re-projected in
`IndexEntry::from_payload`. 2.5.3 is fully frontend-only.

Precedent mirrored throughout: `TagPayload` / `TagMeta` already ship `color: Option<String>` +
`sort_order: u32` with the exact serde shape, and `set_favorite` is the template for the new metadata
mutation command.

## 2.5.1 — Folder color & icons (commit 1)

A folder can carry a **color** + a **curated icon**, rendered in the tree, breadcrumb, and detail;
set from a small "Customize" dialog opened from the tree. **No new command** — a folder's payload is
meta-only (no secrets), so persistence reuses the existing `get_entry → update_entry` round-trip
(already used by folder rename).

- **`vedge-core`** — `color`/`icon: Option<String>` on `CommonMeta`
  (`#[serde(default, skip_serializing_if="Option::is_none")]`); projected into `IndexEntry`
  (`from_payload`) and cleared in `zeroize_entry`.
- **`vedge-ipc`** — `color`/`icon` on `CommonMetaDto` + `IndexEntryDto` (`#[serde(default)]`).
- **`vedge-tauri`** — mapped in `common_meta_to_dto`/`from_dto` + `index_entry_to_dto`.
- **`vedge-app`** — `EntryFormData` carries `color`/`icon` through `meta()`/`from_payload`/`new`/
  `switch_type` (required so a rename round-trip doesn't drop them). `folder_tree`: `FolderNode` /
  `FlatFolder` gain `color`/`icon` (built from the index); a curated `FOLDER_ICONS` map +
  `folder_icon_from_key` + `folder_style`; tree rows render the resolved icon tinted by the color,
  with a hover **Customize** button. New `folder_customize` dialog (vedge-ui `ColorPicker` + a preset
  icon grid). Detail folder row + breadcrumb render the icon/color. i18n: `folder_customize`(+`_title`
  /`_apply`), `folder_color`(+`_clear`), `folder_icon`, `err_folder_customize`.
- **Tests** — core color/icon roundtrip + `IndexEntry` projection; host `folder_icon_from_key` +
  `build_tree_carries_color_and_icon`; `vedge-ipc` wire-codec roundtrip.

## 2.5.2 — Reorder within a folder (commit 2)

A **Manual** sort key + drag-to-reorder rows within a folder view. The ordering rides on the encrypted
payload via a **new server-side `set_sort_order` command** — because `sort_order` is on shared
`CommonMeta`, a reorder can target a secret-bearing entry, and reusing `update_entry` would pull that
entry's plaintext to the renderer just to bump an integer. `set_sort_order` mirrors `set_favorite`:
decrypt → set → re-encrypt server-side, no plaintext out.

- **`vedge-core`** — `sort_order: u32` on `CommonMeta` + `IndexEntry`; new `set_sort_order` use-case
  (re-exported from the prelude).
- **`vedge-ipc` / `vedge-tauri`** — `sort_order` on the DTOs + conversions; `set_sort_order` command
  registered in `generate_handler!`.
- **`vedge-app`** — `api::entry::set_sort_order` wrapper; `EntryFormData` carries `sort_order`;
  `SortKey::Manual` orders by `(sort_order, name)`; pure `reorder_within` renumbers the affected run
  and returns only the changed `(id, order)` pairs. `vault_table` rows become reorder drop targets
  (active **only under Manual sort**, so a move-to-folder drag isn't hijacked) with an insert-above
  indicator; `sort_order` added to the `<For>` key. `vault.rs` `on_reorder`: optimistic `items`
  reorder → `set_sort_order` per changed id (sequential), revert on error. i18n: `sort_manual`,
  `err_reorder`.
- **Wire-format note** — the payload gains `"sort_order":0` on every entry: an additive
  `#[serde(default)]` field, backward/forward compatible (old payloads read as `0`), consistent with
  the already-always-serialized `is_favorite`/`tag_ids`. **No `payload_schema` bump** — an additive
  optional field doesn't require one. The `payload_wire_format` expectations were updated to match.
- **Tests** — core `set_sort_order` roundtrip + version bump; host `reorder_within` (up / down /
  no-ops) + `sort_manual`; wire-codec roundtrip.
- **Cost note** — dragging across the whole folder renumbers up to N entries (N `set_sort_order`
  writes). Fine for typical folder sizes; gap-based fractional ordering is a deferred optimization.

## 2.5.3 — Smart / saved folders (commit 3, frontend-only)

Save the current search/filter/sort view as a named **preset**; list, apply, rename and delete presets
from a "Smart" sidebar section. **No backend change** — presets persist per-vault in the existing
generic `app_settings` KV JSON store (key `smartfolders.<vault_path>`), **not** the encrypted vault (a
preset references vault-local tag/folder ids, so it's keyed by vault path).

- **`vedge-app`** — new `smart_folders.rs`: `SmartFolder` model (Serialize/Deserialize) = the toolbar's
  filter + sort state + id/name; pure `capture_preset` / `apply_preset` helpers; the `SmartFolders`
  sidebar component (compact `+` to save the current view, hover rename/delete, click to apply —
  mirroring the folder tree's affordances). `FolderScope` + `SortKey` gain `Serialize`/`Deserialize`
  (and `SortKey` a `Debug`). `FolderTree` gains an optional `children` slot so the section renders
  inside the same resizable aside, below the folder list. `vault.rs`: a `smart_folders` signal loaded
  on vault-switch from `app_settings` (the load effect tracks only the path, so a save never clobbers
  it); apply/save/rename/delete handlers persist via `set_app_setting`; ids minted with
  `uuid::Uuid::new_v4` (kept out of the pure capture helper). i18n: `smart_folders_label`,
  `smart_save`, `smart_name_placeholder`, `smart_rename`, `smart_delete`, `smart_empty`.
- **Tests** — host `capture`→`apply` round-trip, `SmartFolder` serde round-trip, and
  missing-optional-fields default-on-load.
