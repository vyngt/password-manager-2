# Slice 4.9a — UX Polish (Phase-4 close-out, part 1 of 2)

The visible-polish half of the final Phase-4 slice: a calendar that renders in the
active locale, an audit page whose table scrolls under a sticky header instead of the
whole page scrolling away, a clear-filters affordance, the last three un-swept
`Select`s made relocalizable, and the removal of a dead `Pagination` prop. The
close-out gates (4.9b) run **after** this merges, over the final tree.
Spec: `.../Phase 4 - TOTP & Security Hygiene/Specs/4.9 - Phase-4 Close-out` (§§P1–P6).

**No new crate.** One new `calendar` i18n namespace (5 keys × en/vi), five new
`DatePicker` aria-label props, and a `Pagination` prop-surface **reduction**. The
pickup scan re-verified every anchor and corrected the spec/plan on three points
(🔴 below).

## P1 — DatePicker locale + panel aria-labels

The `locale: Signal<String>` prop and a full `Intl`-backed formatter (month names,
weekday headers, first-day-of-week) already existed — **nothing in the app passed
`locale=`**, so the calendar rendered English months/weekdays under `vi`.

- **`locale=` wired at all 3 real call sites** (`audit.rs` since/until, `entry_form.rs`
  card-expiry) via a shared `features/date_i18n::locale_tag(i18n)`.
- 🔴 **Correction (scan):** `Locale::as_str()` yields bare `"en"`/`"vi"`; feeding a bare
  tag into `first_day_of_week` hits its *unknown-region → Monday* branch, which would
  **silently flip en's week-start from Sunday**. `locale_tag` maps `en → "en-US"`,
  `vi → "vi-VN"` — en stays Sunday-first, vi is Monday-first (correct for Vietnam).
- **The 5 panel aria-labels are localized** (`Choose date`, prev/next month, prev/next
  year). They became `TextProp` props on `DatePicker`, bundled into a `Copy`
  `PanelLabels` struct threaded through `CalendarPanel` → `render_day_view` /
  `render_month_view`, each with an English `text_or` fallback (the vedge-ui i18n rule).
  A shared `features/date_i18n::calendar_labels(i18n)` builds the reactive `Signal`s;
  keys live in a new `calendar` namespace (en/vi). The labels are reactive, so a locale
  switch relocalizes an open calendar with no remount.
- ⚠️ **`locales/{en,vi}/date_picker.yaml` is the playground's namespace, not the
  component's** — new `calendar.yaml` keys were required (spec's red-herring note).
- **DEFERRED (backlog):** `TimePicker`'s hardcoded `AM`/`PM` — the scan confirmed
  `TimeFormat::H12` has **no real (non-playground) consumer**, so the strings never
  render in the app. `DateTimePicker` (playground-only) keeps English panel labels for
  the same reason; its inner `DatePicker` uses the English defaults.

## P2 — Audit page → flex column (sticky header, zero new CSS)

The page was one scroll root (`h-full overflow-y-auto p-6`), so the filter bar, summary,
table and pagination scrolled away together.

- ✅ **Premise verified against the code (not just the spec):** `AuditTable` **is** a
  `DataTable` (design-system), whose wrapper is `.data-table-wrapper { overflow:auto }`
  with a `position:sticky` `<thead>` — both **dormant** only because nothing bounded the
  height. *(An early scan conflated this with the entries table `vault_table.rs`, a
  hand-rolled raw `<table>` — a different page, correctly out of scope, see P6.)*
- **Restructured** to the shape `vault.rs` already uses: outer `h-full p-6 flex flex-col`
  → one centered column `max-w-5xl w-full mx-auto flex-1 min-h-0 flex flex-col gap-4`
  holding the fixed h1 / filter bar / summary `<p>`, the table band, and the pagination
  footer.
- 🔴 **The height chain is the whole trick.** `min-h-0` at every link lets the flex
  child shrink below its content: band → `AuditTable`'s (previously classless)
  `data-testid="audit-table"` wrapper (`flex-1 min-h-0 flex flex-col`) → `DataTable`'s
  `class="flex-1 min-h-0"` on `.data-table-wrapper`. The wrapper's built-in
  `overflow:auto` then becomes the bounded scroller and the sticky header engages —
  **no new hand-written CSS** (Tailwind utilities only).

## P3 — Clear-filters (audit page)

The audit filter state is one struct (`AuditView`, `Default` also zeroes `offset`), so
clear is a single assignment. Added a `vedge-ui` `Button` in the (now fixed) filter bar
→ `view_state.set(AuditView::default())`, an `is_dirty` derived signal
(`view_state.get() != AuditView::default()`, `AuditView: PartialEq`), 2 locale keys
(en/vi), and `data-testid="audit-clear-filters"`.

- 🔴 **`Button::disabled` is not reactive** (`bool`, captured once), so the button is
  **hidden** when clean via `<Show when=is_dirty>` rather than disabled — the spec
  explicitly allows "disable/**hide**", and hiding is fully reactive.

## P4 — Finish the `Select` sweep (3 mechanical edits)

`vault_filters.rs`'s type / tag / sort `Select`s were still wrapped in the old
`{move || …}` closure that **remounted** the component on every locale switch and
tag-list change (dropping open/highlight/type-ahead state). Converted each to
`options=Signal::derive(move || …)` — the pattern 4.6b applied to the audit page.
*(The 10 sibling sites — settings ×3, folder_move ×2, tag_assign, entry_form_body —
stay backlogged as a mechanical follow-up.)*

## P5 — Remove the dead `Pagination` summary override

4.6b added `summary` / `summary_empty` `TextProp`s taking a **pre-interpolated
`String`**. The app can't produce one (`t!` returns a view; `interpolate_display` was
reverted for the `rust-lld` crash), so they had **no viable consumer** — dead API
surface in a design-system component.

- 🔴 **Scope refinement vs the plan's line-range:** the plan said delete the whole
  center-summary render zone. On reading the code, that zone holds **two** things: the
  4.6b **override** (dead) *and* the original **built-in numeric summary**
  (`total_items` → "start–end of total"), a working English-defaulted feature the
  playground still demonstrates (`OffsetFull`, `Disabled`). P5 therefore **surgically
  reverts only 4.6b's addition** — the two override props + their two branches in
  `summary_view` + the playground's `SummaryOverrideSection` — and **keeps** the
  built-in summary + `total_items`. Deleting the whole zone would have removed a live,
  consumable capability. The now-idle `text_or` import was dropped.
- The audit page keeps its own localized `<p>` result-count (rendered via `t!`), now in
  P2's fixed band. Its comment was updated to record that Pagination's summary is
  English-only.

## P6 — NOT done on purpose

The audit table was **not** downgraded to match the entries table. Audit is the
accessible `DataTable` (`role="grid"`, `aria-sort`, focus rings, sticky header — better
still after P2); the entries table is the hand-rolled raw `<table>`, the exact §7
anti-pattern. The real fix is the **reverse** migration (`vault_table` → `DataTable`,
8–12h + drag-drop risk) → backlogged.

## Tests — reality vs. the spec's test plan

**DRIFT:** vedge-ui has no component-test harness and the e2e suite is deliberately
locale-independent (`data-testid`, never asserts translated text), so
`select_relocalizes_without_remount` and calendar-locale behaviors can't be in-process
unit tests without new infra (its own slice). They fall to the **manual smokes**; the
`en` `daily_loop` (which drives audit pagination + Select + the date filters via
`data-testid`) is the no-regression bar. The existing pure host tests
(`build_page_window`) are kept.

## Self-review (`/code-review high` — 5 finder angles + clippy)

**Fixed before the PR:**
- 🔴 **The `rust-lld` wasm-link crash came back** (`0xC0000005`) — 4.9a's ordinary cumulative
  binary/DWARF growth re-crossed the Windows `rust-lld` threshold that bit 4.6b (which had dodged it
  by reverting `interpolate_display`; I added no such lever). `mise ci`'s wasm **check** was blind to
  it (a check never links); the full-debuginfo `cargo build`/`trunk`/`mise e2e`/`cargo tauri dev`
  **link** crashed. Fixed durably with a **target-scoped** `.cargo/config.toml`:
  `[target.wasm32-unknown-unknown] rustflags = ["-C", "debuginfo=0"]` — drops debuginfo for the wasm
  target only (HOST builds keep full debuginfo), dodging the crash for every local wasm link. It does
  **not** touch `debug_assertions` (profile-controlled), so the DEBUG wasm the e2e suite builds still
  compiles in the Leptos reactive-context console-clean guard. Verified: the full wasm link now
  finishes (exit 0) and `mise e2e` builds + runs. **DRIFT/new:** this is a build-infra change outside
  4.9a's UX scope, but 4.9a's tree does not link the wasm locally without it; it also durably
  inoculates future slices against this recurring trap.
- 🔴 **clippy `too_many_arguments`** — `render_day_view` hit 8/7 args after adding `labels`.
  Rather than an `#[allow]`, moved `labels` **into `PanelContext`** (already threaded to both
  render helpers) — removed the extra param *and* the `CalendarPanel` `labels` prop.
- **clippy `doc_markdown`** — bare `DatePicker` in two `date_i18n.rs` doc comments → backticked.
- **Convention gap (vedge-ui playground rule):** the 5 new `DatePicker` aria-label props had no
  playground demo → wired them on `pg_date_picker.rs`'s Locale-demo instance (invisible a11y
  strings; one wired instance documents the capability).

**Verified clean (0 findings across 3 angles):** the Leptos reactive-context pass confirmed every
`t_string!`/`get_locale` read introduced is deferred into a `Signal::derive`/attr-closure/handler
(no owner-less body reads, no `spawn_local` reads — `calendar_labels`/`locale_tag` only *construct*
lazy derives); the removed-behavior + cross-file pass confirmed no dangling `text_or`/`total_items`
reference, `PanelContext` has one construction site, `CalendarPanel` has no stray `labels=` caller,
and both `calendar.yaml`s carry the same 5 keys.

**Accepted / deferred, documented (not changed):**
- **Audit summary can show a reversed range** (`"101–100 of 40"`) if the retention job prunes the
  trail below the current page's offset *and* the vault is re-selected (offset not reset on that
  path). **Pre-existing** (unchanged by this slice — only the comment moved), out of 4.9a scope →
  **backlog** (a Phase-4 close-out disposition item).
- **The flex column has no page-scroll fallback**, so on a *pathologically short + narrow* window
  the wrapping filter bar + fixed bands could exceed the viewport with the table shrunk to zero.
  **Accepted** — this is the exact shape `vault.rs` (the entries page) already uses, and a sane
  desktop min-window fits the fixed bands. (Audit's filter bar wraps where vault's is one row, so
  it's marginally more prone — noted for backlog if an app-wide safety-net is ever wanted.)
- **DatePicker exposes 5 flat aria props + an app-side `CalendarLabels` mirror of `PanelLabels`.**
  A single `labels: PanelLabels` bundle prop was weighed and **declined** — the crate's convention
  is flat per-string `TextProp` props (`Pagination`, `Button`, `DataTable` all do this), and a
  bundle would export a panel-internal type. Uniformly passing all 5 labels per call site (even the
  2 the variant never renders) is honest, allocation-free (unread derives never subscribe), and
  variant-change-safe.
- **`DateTimePicker`'s inline `DatePicker` keeps English panel aria-labels** — it has no app
  consumer (playground only), consistent with the P1 `TimeFormat::H12` scope call.
