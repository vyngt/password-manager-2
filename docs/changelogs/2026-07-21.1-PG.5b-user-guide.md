# Slice PG.5b — External User Guide (2026-07-21)

The **writing half** of the split PG.5, and the **last slice of Pre-Gate Hardening** — after it, Gate 1.0 is a
pure verification pass. Ships a sectioned, task-oriented user guide in `docs/` (GitHub-rendered markdown,
never in the app — that's the injection path PG.2b closed), automated screenshots of the frozen UI, and one
folded-in in-app copy-fix so the guide and the app state the same facts. 🔴 **One source of truth per fact:**
in-app help = decision-point (PG.5a); this guide = task manual.

## The guide (`docs/guide/`)

A landing `README.md` (what VEdge is + install & verify) plus four topic pages, all transcribing the Phase-5
specs' own hard-won framings rather than softening them:

- **`README.md`** — local-first framing, contents, and the whole unsigned-release integrity story: the
  **SmartScreen warning** (why it appears, why it's expected) **and** the **SHA-256 checksum verification**
  step (`Get-FileHash … -Algorithm SHA256` against the value on the release page — the integrity substitute
  for a signature).
- **`getting-started.md`** — first vault (the three wizard steps + the Secret Key / Emergency Kit), the eight
  entry types, viewing/copying secrets (browse ≠ extract), the generator, TOTP, folders/tags/search.
- **`backup-and-recovery.md`** — the three verbs kept distinct: **snapshot = TIME** (*a snapshot is **not** a
  backup*), **backup = SPACE** (*you don't restore a `.vbk`, you **open** it*; open refuses an occupied
  destination; Replace auto-snapshots first), **export = ROWS** (never a merge; VEdge never claims a plaintext
  file can be securely wiped).
- **`keys-and-credentials.md`** (the highest-stakes doc) — the Emergency Kit + the *separate* Recovery Kit
  (**neither document opens the vault alone; losing both is unsurvivable**); the three credential operations by
  intent (change password · rotate Secret Key · **re-key**), including *re-key protects forward and **cannot
  un-leak the past***.
- **`health-and-settings.md`** — health/breach (k-anonymity, opt-in), the audit log's browse-vs-extract
  distinction, and the six settings tabs (Security · Credentials · Appearance · Maintenance · Backup · About,
  incl. the manual/private update posture).
- **`screenshots.md`** — the figure manifest + the refresh command.

The root `README.md` gained a User-Guide link and had two stale facts corrected (**MIT**, not "Not yet
licensed"; the Status block, which still said "Next up is Phase 3").

## The in-app copy-fix (Part A — the PG.5a carry)

`settings.rotate_keep_old_kit` (en + vi) wrongly said the old Emergency Kit is "the only key to the backups
**and snapshots**." Verified against `change_password.rs:142-162` + `rewrap_snapshots.rs`: a rotation
**rewraps local snapshots forward** to the new key, so the old kit is needed only for external `.vbk` backups.
Corrected in both locales (snapshots are auto-re-secured; the old kit is the only key to `.vbk` backups) and
in the file's doc comment. 🔴 One key drives **two** surfaces — the rotate dialog and PG.5a's Secret-Key `?`
popover both read from it — so the single string fix corrects both, and the app now matches its own already-
correct 5.9 nudge (`credential_nudge_secret_key`, "backups" only) and `rekey_warning`. `credential_nudge_*`
and `rekey_warning` were already correct and left untouched.

## The screenshot harness (Part C — the refresh process ④)

Screenshots are **automated, not a manual manifest**: new `crates/vedge-e2e/tests/screenshots.rs` drives the
real app through the existing `tauri-driver` + `thirtyfour` harness, walks ~22 documented states with curated
throwaway sample data, and writes a PNG per figure to `docs/guide/images/` (override via `VEDGE_SHOTS_DIR`).
New **`mise screenshots`** task; re-running it *is* the refresh process, so shots can't silently drift from the
shipped UI. VEdge is frameless with an in-webview titlebar, so each capture is the whole window as the user
sees it. Best-effort per section — a drifted selector logs and the run continues, so one issue never costs the
whole (expensive) capture; only create-and-unlock is fatal. 🔴 The **SmartScreen** figure is OS-level (not a
webview element) → described in text, not captured; the 1180×600 window is widened via `set_window_rect` at
capture time (best-effort).
