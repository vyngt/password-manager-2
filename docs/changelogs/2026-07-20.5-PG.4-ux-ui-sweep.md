# Slice PG.4 — UX/UI Sweep (2026-07-20)

The fourth **Pre-Gate Hardening** slice, and **the last UI change before PG.5 screenshots it** — after this the
UI is visually frozen. The pre-flight audit (2026-07-20) already measured the drift, so this was the fix pass,
not a discovery task. One PR, green-per-commit; acceptance for the dialog + scroll work is a **human visual
pass** (the user's), since e2e asserts behaviour, not spacing.

🟢 **What it could not break — and a test proves it:** PG.3's `attack_surface.rs` pins the 8 capability grants +
the exact CSP. The About button (⑤) reuses PG.3's existing `app_version` command, so nothing here moved a
capability or the CSP. PG.1's `assert_vault_coherent` is untouched — no vault state changed.

## Dialog padding — fix the component, not the 24 consumers (C1 + C2)

**The root cause:** `.dialog__body` was `padding: 0 var(--space-6)` — zero vertical — so all 24 dialog sites
invented their own bottom spacing. The drift followed **copy-paste lineage** (settings → `pb-4`, vault →
`pb-6`), so fixing 24 consumers would leave the 25th to re-drift. And it ran deeper: the `pb-*` was a *symptom*
of cramming action buttons into the body instead of the `DialogFooter` the component already provides.

**C1 — the footer-safe component fix (atomic).** Each region now owns its spacing so a dialog is correct with or
without a footer, and a footer never doubles the gap:

- `.dialog__body { padding: 0 var(--space-6) var(--space-6) }` — the body owns the **bottom** gap; the header
  still owns the top gap (top stays `0`).
- `.dialog__footer` drops its `space-4` **top** padding — the body owns the gap above it, so moving an action row
  into a footer is padding-neutral (this is what makes C2 safe).
- `DialogBody` gains a `flush` prop (`.dialog__body--flush { padding: 0 }`) for edge-to-edge list bodies. 🟢
  `flush` (not `padded`) → the `bool` default `false` **is** the safe padded case, structurally — forgetting it
  can't produce a broken dialog (the `SecretUpdateDto::Unchanged` "safe default" principle).
- Deleted all **23** per-instance `pb-*` (12 `pb-6` + 11 `pb-4`). The three dialogs that were *flush against the
  footer* (`import_dialog`, `vault_create_form`, `entry_form` — they delegate to a child body) inherit the new
  bottom padding. A `flush` demo added to the playground.

**C2 — migrate the clean button-bar dialogs to `DialogFooter` (the anatomy fix).** Because C1 made it
padding-neutral, each migration is a pure reparent — buttons keep their `data-testid`/text/handler, so e2e
selectors still resolve (low risk, verified by the full suite). **15 dialogs** migrated: the confirmations (trash
permanent + empty, folder delete/move/customize, bulk trash/move/tag, recovery-reset) and the single-bar forms
(export, change-password, biometric, theme-editor, theme-delete, the show-once new-kit dialog). The footer's own
`justify-end` + gap + danger-separation now give consistent button alignment.

🔴 **Left in-body deliberately** (documented, not clean single bars): the phase-wizard credential dialogs
(**rekey, rotate-SK, recovery-key**) swap their whole body on a busy/phase `<Show>`, so their buttons are
per-phase contextual, not a persistent footer bar; **vault-manage** — `VaultDetails` is prose-with-inline-actions
by design, `DeleteVault`'s confirm bar is nested in a per-row reactive map; and the list/mixed dialogs
(**tag_manager**, **entry_history**) and the child-delegating / `DialogBody`-bypassing dialogs (`command_palette`,
`backup_open_dialog`). All keep correct body padding from C1.

## Page scroll — one owner per page (C3)

`VLayout`'s outlet has no overflow handling, so every page owns its scroll, and two patterns had drifted by
copy-paste. Named them in `layout.rs` (**A**: the page scrolls; **B**: fixed shell + a `flex-1 min-h-0` band) so
the next page picks deliberately.

- **health** was pattern A while its main content is a `DataTable`, so the table header scrolled away with the
  page. Now pattern B — a fixed header (title + run-scan) above a single `flex-1 min-h-0` scroll band holding the
  report. The table grows naturally inside the band → **one** scrollbar, no nested/whole-page scroll. (Not
  audit's table-owns-height variant: health's summary + reuse-groups sections must scroll with the table.)
- **generator** stays the single scroll owner (pattern A). Dropped the two inner `max-h-56 overflow-y-auto` list
  regions (bulk results + history) that trapped the wheel, and bounded the previously-unbounded output `<code>`
  with `max-h-40 overflow-y-auto` so a long/bulk output scrolls in place instead of pushing controls off-screen.

## The stale sidebar brand block (C4)

The sidebar rendered `ui_icon::Pm` — a **pre-VEdge** "password manager" mark, different from the real
`ui_icon::VEdge` the window panel shows — duplicating chrome the titlebar already owns. Collapsed by default (the
rail's normal state) that row was only the icon, so removing just the icon would leave an empty gap → removed the
whole block and reclaimed the rail height. `Pm` then had zero consumers, so retired it (dropped the re-export,
deleted `icon/pm.rs`).

## About button in the window panel (C5)

🟢 The window panel is app-level chrome rendered **outside `/v`**, so it is visible **pre-unlock** — a locked-out
user can't reach Settings ▸ About, and *"what version are you on?"* is the first support question. A
`TooltipIconButton` (info icon, `Size::Lg`/`Shape::Square`) sits **left of the locale toggle, outside the
`pointer-events-none` brand block** so it stays clickable, and opens a small app-level `Dialog` with the VEdge
mark, the version (PG.3's offline `app_version` — no capability, no CSP change), and the MIT licence + copyright
(reusing the `settings.about_*` keys). A subtle **dot** appears when the opt-in launch update-check
(`UpdateStatusCtx`) found a newer release — the non-nagging home for that signal (the spec's nav-badge decision).
New `window.about` key (en + vi).

## The flex-1 + Input overflow (C6)

A flex child defaults to `min-width: auto`, so a `flex-1` wrapper refuses to shrink below its Input's content
width and overflows the row (the manage-tags rename bug). Swept **all 7** sites the idiom was copied to
(`min-w-0` added): tag_manager (create + rename), tag_assign, vault_search, entry_form (TOTP), backup_open_dialog
(×2).

## Typography — Inter made honest (C7)

`--font-sans` named `"Inter"` but **no `@font-face` for it was ever bundled**, so every user has always seen the
platform fallback (Segoe UI on Windows), not the designed face. Named the system stack that actually ships
instead of an absent font — **zero visual change**, no new asset right before the screenshot freeze. `--font-mono`
(JetBrains Mono) is bundled and unchanged; secret-bearing surfaces stay pinned to it (a correctness property).

## Declarations — the no-code decisions (C8)

- **⑨ a11y (Gate §F):** `DateTimePicker`/`TimePicker`'s inline-picker aria, hardcoded AM/PM and missing `locale`
  prop are **deferred** — verified to have **zero production consumers** (playground-only, and the playground is
  gated out of release), so revisit when a feature adopts them. The audit-log `action_label` raw fallthrough is
  **intentional forward-compat** (documented in code). `command_palette`'s native `<input>` is the **blessed 2.9
  exception**. No code changed.
- **⑦ Six Settings tabs — no change.** `Tabs` already handles overflow (hidden horizontal scroll); six fit at
  `max-w-2xl`.
- **⑩ Gap-scale — dropped.** The spec's premise (a few one-offs) was stale: the audit measured `gap-3` ×48 and
  `gap-5` ×17 — established conventions (settings-row `gap-5`, vault-row/playground `gap-3`), not stragglers.
  Normalizing them is churn + regression risk for ~zero value.

## Follow-up found in the smoke pass — console-guard.js path

The owner's visual pass surfaced `Uncaught SyntaxError: Unexpected token '<' at console-guard.js:1:1` after a
webview reload at a nested route. PG.2b's external console-clean seam (`<script src="console-guard.js">`) is
**not** Trunk-managed, so unlike the Trunk-injected WASM/CSS it stayed a **relative** path — on a reload at
`/v/health` it resolved to `/v/health/console-guard.js` → 404 → the asset fallback returned `index.html` → the
browser parsed HTML as JS. Fixed with a **root-absolute** `/console-guard.js`; still same-origin, so the CSP +
`attack_surface.rs` pin are unchanged and root-boot is byte-identical (e2e console-clean unaffected). 🟢 The
"auto-refresh on low network" is **Trunk's dev-only live-reload** — the shipped app doesn't do it; the fix just
makes any reload (WebView2 recovery, F5) clean. *(Lesson: any **hand-added** `index.html` `<script>`/`<link>`
must be root-absolute — Trunk only rewrites its own `data-trunk` assets.)*

## Follow-up found in the smoke pass — three more UI fixes

The owner's visual pass caught three more:

- **Open-backup dialog had no padding.** It **bypassed `DialogBody`** (its content was a raw `<div>` child of
  `<Dialog>`), so C1's component fix never reached it — it had been flush against the edges even before PG.4.
  Wrapped it in `DialogHeader` (title) + `DialogBody`. Its actions are a **`justify-between`** row (Advanced-left
  / action-right), not a right-aligned bar, so they stay in the body, not `DialogFooter`.
- **Snapshots page → pattern B** (like health): a fixed header (title + Take-snapshot) above one `flex-1 min-h-0`
  scroll band holding the list + recover panel, so a long snapshot list scrolls cleanly with the header fixed.
- **Settings tab bar scrolled away on a long tab** (About). Made `.tabs__list` **sticky** (`top: 0` + background +
  `z-index`) so the tab nav stays pinned while the panel scrolls. `sticky` is still a positioned element, so the
  absolute `.tabs__indicator` keeps its containing block — a global Tabs improvement, harmless where there's no
  scroll ancestor.
