# Slice 2.9 — UX/UI Polish & Feedback

Make the shipped screens (2.1–2.8.1) feel finished: replace the hand-rolled inline status/error
lines with proper Success/Danger **toasts** (the `ToastProvider` was already mounted, just unused),
give empties a shared **`EmptyState`** and loaders a **`Spinner`** so the two stop looking identical,
add real load/save-in-flight states, and close the three concrete **a11y gaps** the audit found
(`Select` naming, the command-palette combobox, decorative icons). **Not** a CSS motion/focus pass —
focus rings + `prefers-reduced-motion` were already ~100 % done. Spec:
`.../Specs/2.9 - UX Polish and Feedback`. Mockup: `2.9 - Polish Before After`.

## Spec-vs-reality corrections (slice 2.8.1 shipped after the 2026-07-07 audit)

- **`vault_launch.rs` was already fully on toasts** (its `show_error` Danger helper) **and already
  used `Spinner`** for loading — it's the *reference implementation*, not a conversion target. The
  spec listed it under both; skipped.
- **`vault_filters.rs` has 4 `<Select>`** (type / tag / view / sort), not 2 → **10** Select call
  sites total, not 8.
- **No `<Icon>` had `aria-hidden`** (the "~3 existing" were on `<span>`/`<div>`), and **neither
  `Select` nor `leptos_icons::Icon` exposes the prop needed** — `Select` got a new `aria_label`
  prop; `Icon` (v0.7.1, props `icon`/`style`/`width`/`height` only) takes it via attribute
  spreading `attr:aria-hidden="true"`.
- **`crates/vedge-ui/CLAUDE.md` overrides the root**: every user-visible string incl. `aria_label`
  is a **`TextProp`**, not `&'static str`.
- **Two feature files the audit's site list missed** (found in self-review) — `entry_history.rs`
  (converted) and `biometric_setting.rs` (kept inline — see deviations).

## What shipped

### vedge-ui

- **New `EmptyState`** foundation component (`components/foundation/empty_state.rs` +
  `styles/empty-state.css` + playground page): decorative `icon: Option<icondata_core::Icon>`
  (wrapped in an `aria-hidden` span) + `title: TextProp` + optional `description: TextProp` + an
  optional CTA `children` slot (consumers pass a `<Button>`). BEM + tokens, no motion.
- **`Select` `aria_label`** (`form/select/component.rs`): a new `TextProp` prop bound
  `aria-label=move || …` on the combobox trigger (`Select` was already `role="combobox"` +
  `aria-expanded`; it only lacked a name).

Replaced every inline status/error line with `use_toast()` + a per-component `show_error` (Danger)
/ `show_success` (Success) helper (the 2.8.1 `vault_launch` pattern; dismiss label read via `untrack`
so it's safe from `spawn_local`). Sites: `pages/v/manage/vault.rs` (the worst — one muted-gray

### vedge-app — accessibility

### Design critique (recorded — spec acceptance criterion)

A critique of the shipped screens drove the scope. Findings closed this slice: (1) success and errors
were visually identical (one muted-gray line) → correct-variant toasts; (2) empty ≡ loading (both
gray text) → `EmptyState` vs `Spinner`; (3) Settings flashed default security values on open → load
gate; (4) the command palette / `Select`s / decorative icons were unlabelled for AT → named +
`aria-hidden`. Ticketed / deferred items are under **Deferred** below.

## Manual smoke (human — `cargo tauri dev`, Windows)

Copy a field → **Success** toast; delete-not-found → **Danger** toast (was gray); an empty list →
`EmptyState` (icon + title + CTA); a loading list → `Spinner` (visually ≠ empty); Tab/arrow the
palette → the active option is announced; every `Select` is labelled; Settings no longer flashes
defaults; a save shows an in-flight spinner; no inline status/error `<p>` remains; the settings tabs
are keyboard-navigable; **the console stays warning-free** (the i18n reactive-context backstop).

## Deviations (recorded in the tracking note)

1. **Component-consistency raw→design-system conversions deferred to 2.9.1 (Layout/Forms).** The
   spec's "raw `<button>`/`<input>` → `IconButton`/`Button`/`Input`" conversions
   (`folder_tree`, `smart_folders`, `vault_list`, `layout` `LockButton`/toggle, the `tag_assign`
   chip ×) were **not** done here. Every one already carries an `aria-label` or visible text, so
   a11y is unaffected — these are purely visual/consistency changes that need `cargo tauri dev`
   verification, which belongs with the 2.9.1 Layout/Forms pass. **Done here** were only the
   clean, a11y-relevant or central conversions: Settings tabs → `Tabs`, the `theme_editor` name
   `<Input>`, and adding the missing `aria-label`/`aria-pressed`/keyboard to the raw controls that
   had a genuine a11y gap.
2. **`entry_history` + `biometric_setting` were not in the audit's site list.** `entry_history` was
   converted (same stopgap pattern + the copy success/error one-line bug). `biometric_setting`'s
   error was **kept inline** — it's contextual master-password validation shown directly under the
   password field in the enroll dialog (a form error, not a transient status line); a toast would
   vanish before the user re-reads it.
3. **`vault_setup` keychain warning + `tag_manager` delete-confirm kept inline** — both are
   persistent contextual UI (the keychain warning must stay visible while the user reads the
   Emergency Kit; the delete-confirm reports a live `ref_count`), not action-result feedback.
4. **Four `window_panel` window-chrome icons left un-hidden.** `attr:aria-hidden` on an `<Icon>` at
   a top-level-returned / `TooltipIconButton`-child position trips a Leptos RPIT capture bound
   (`Output<(Attr<AriaHidden, &str>,)> may not live long enough`). Those icons sit inside labeled
   `TooltipIconButton`s (the button carries the name), so leaving them decorative-but-unhidden is
   a11y-safe. The VEdge logo (also top-level) is hidden via its wrapping `<div aria-hidden>`.
5. **Icon-grid `aria-label` is the icon key** (`folder_customize`) — there is no localized
   per-icon name set, so the identifier is the best available label for that visual picker.
6. **Errors surface as toasts, not an inline error signal** (spec acceptance criterion), adding a
   `dismiss` i18n key per toasting namespace.
