# Slice 1.1 — Create Vault (Core)

**Scope:** `vedge-core` only (no IPC/Tauri — slice 1.2; no UI — slice 1.3).

## Added

- **`create_vault` use case** (`application/vault/use_cases/create_vault.rs`) — the
  mirror of `UnlockVault`. Generates a fresh 16-byte Secret Key + 32-byte salt,
  derives key material through the identical 2SKD → Argon2id → HKDF chain on
  `spawn_blocking`, pins the KEK in `mlock`'d memory, writes the initial
  `vault_config` row (`id = "default"`, magic `VEDG`, schema 1), provisions the
  `.vdb` + blob store, stores the Secret Key in the OS keychain, appends an
  `AuditAction::Created` event, and returns an unlocked `VaultSession` plus the
  Emergency-Kit display string.
  - `CreateVault` / `CreateVaultInput` / `CreateVaultOutput` re-exported from
    `use_cases.rs` and the crate root.
  - A keychain-store failure is non-fatal (`keychain_stored: false` +
    `keychain_error`) — the vault file is valid and recoverable via the kit,
    mirroring `RecoverVault`.
- **`CryptoProvider::generate_secret_key` / `generate_vault_salt`** — two
  infallible CSPRNG methods (trait + `XChaCha20CryptoProvider` impl), matching
  the existing `generate_dek` / `generate_nonce` style.
- **`VaultError::VaultAlreadyExists`** — returned when the target path already
  exists (guarded before `open`, which uses SQLite `mode=rwc`).
- **`tests/vault_create.rs`** — 7 integration tests (create→unlock round-trip,
  overwrite refusal, wrong-password rejection, Secret-Key display round-trip,
  config-field assertions, `Created` audit event, keychain-failure resilience).

## Deviations from the spec (see slice tracking note)

1. `CreateVaultOutput` uses a hand-written `Debug` impl (`VaultSession` is
   `!Debug`), printing only the keychain status — never the session or the
   Emergency-Kit string.
2. Added `kdf_params: Option<KdfParams>` to `CreateVaultInput` (spec hardcoded
   `argon2id_default()`). `None` → production params; tests pass
   `Some(fast_kdf_params())` to stay fast. Mirrors the spec's own
   `secret_key: Option<…>` override.
