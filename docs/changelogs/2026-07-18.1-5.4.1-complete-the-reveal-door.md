# Slice 5.4.1 — Complete the Reveal Door

Two regression fixes plus the env-set copy the seal made necessary. 5.4 sealed
**eleven** credential field-classes out of `get_entry` (correct — the point), but
**copy and reveal both dispatch on `FieldSelector`, which had only seven usable
arms.** The six that fell through were **write-only** — stored but unreadable
except by exporting the whole vault. And 5.4's placeholder change **ate the form
labels**. Spec: `.../Phase 5 - Data Safety & Recovery/Specs/5.4.1 - Complete the
Reveal Door`. Counts verified from `vedge-ipc/src/entry.rs`: 11 sealed, 7 arms,
**6 write-only**, 6 new arms.

## 🔴 ③ is the deliverable: a test that makes the class impossible again

`every_sealed_field_has_a_working_selector` (`copy_field.rs` tests) walks every
sealed field via a **no-`..` destructure** — the same discipline 5.4's
`resolve_secrets` uses — and fails, naming each field, if a selector does not
resolve. Watched it fail SIX times (recovery×3, pin, private_key, passphrase,
api_secret, national_id) before the arms landed. The seal, the resolver, and the
door now share one enumeration; the next seal cannot outrun the door in silence.
*(Fourth §2 under-count in this phase — the first fix that leaves a guard, not a
lesson.)*

## ① The six arms — one `extract_field` match, both doors

`FieldSelector` gained `Pin`, `PrivateKey`, `Passphrase`, `ApiSecret` (**not**
`Secret` — the sibling `ApiKey` arm already names the entry's other credential),
`NationalId`, `RecoveryCode(u32)`. Each is one arm in the single `pub(super)`
`extract_field` match, so **`copy_field`, `reveal_field`, `copy_history_field`,
and `reveal_history_field` all inherit them at once**. The wire (`FieldSelectorDto`)
and the tauri converter (`field_selector_from_dto`) gained the matching variants.
Optional secrets return `FieldNotApplicable` when `None`; `RecoveryCode` is indexed
and **out-of-range errors, never returns `""`** (a blank code is one a user writes
down).

## ② Recovery codes are a LIST — a whole-list reveal, ONE audit row

`RecoveryCode(i)` drives per-code copy; the new `reveal_recovery_codes(entry_id)`
returns the **whole** list in one call, audited as a **single** `SecretRevealed`
row (you read recovery codes to print them, not one at a time — N rows would be
noise). A read-only `RecoveryCodesField` on the Login edit form shows the stored
count and, on Reveal, lists each code with a `Badge` index + a copyable
`SecretDisplay`. Non-Login → `FieldNotApplicable`.

## ④ The SSH private key is multi-line PEM

`SecretDisplay`'s `<code>` block gained `whitespace-pre-wrap` — the default
`white-space: normal` collapsed a revealed PEM's newlines into spaces (the
*copied* value was always fine; `CopyButton` copies the `Signal<String>`, not the
DOM selection). Harmless for the single-line Secret-Key it also renders. The edit
form fills the key into a `Textarea`, which preserves newlines natively.

## ⑤ FormField — 5.4's placeholder-as-label regression, fixed

5.4 rendered every field's label **as the input placeholder**; when sealed fields'
placeholder became *"Unchanged — type to replace"*, they lost their only label (an
SSH form showed two identical fields, Card three). Fixed via **`FormField`** — its
first feature adoption (playground-only until now), **not** a new `Input` prop. The
two field macros (`text_field!` / `secret_field!`) now wrap their `Input` in
`<FormField label id>`; the locale key that was the placeholder moves to the label,
and the placeholder becomes the sealed hint or nothing. A new `RevealableField`
composes label + masked input + a per-field Reveal button for every sealed field
(card number/cvv/pin, api key/secret, ssh passphrase, national_id); the SSH private
key gets a Reveal button in its (already-labeled) header. `RevealButton`'s
`data-testid` is now per-field so multiple buttons don't collide (password keeps
`reveal-field` — the 5.4 e2e stays green). `EnvVarsFields` uses a column header +
per-input `aria_label` (per-row `FormField` ids would force a leak).

## ⑥ EnvVars — copy the SET, in two shapes

`copy_env_vars` / `reveal_env_vars` (+ `EnvExportFormat { DotEnv, Json }`) render an
entry's whole keyed set, from a `⋯` `DropdownMenu` on the edit form. **One
`SecretRevealed` row per call.**

- 🔴 **Copy formats server-side and never round-trips the blob through WASM** — it
  calls `place_text_on_clipboard` directly (the same hardened path 3.2's `copy_text`
  uses). Only `reveal` returns the blob to the renderer, by design. Sealing the set
  and then copying it *via* WASM would have defeated the seal.
- **`.env` single-quotes**: `KEY='value'`, embedded `'` → `'\''`. Round-trips
  **byte-exact AND inert** — `$(rm -rf ~)` and backticks are literal under single
  quotes. Never strips a character (5.3's ⑤).
- **JSON**: a flat `{"KEY":"value"}`, **every value a string** (env is a
  `string→string` map — no `value_type`), keys in vars order (assembled by hand;
  default `serde_json` sorts). Lossless.
- **Newline honesty**: a value with `\n`/`\r` has no portable `.env` encoding → the
  DotEnv path returns a typed `VaultError::EnvValueNotDotEnvSafe { key }` so the UI
  points at JSON, rather than silently truncating on paste.

New `domain/vault/env_export.rs` holds the pure, session-free formatter (5 unit
tests). No new dependencies (`serde_json` + `indexmap` already core deps).

## Follow-up correction — reading lives in the read drawer, not the edit form

Review feedback: the reveal/copy affordances belong in the **detail drawer** (the
read rail you get on click / `get_entry`), where copy already lived
(`copy_buttons` + `TotpReveal`) — **not** in the edit Dialog. The edit form is
write-only: every field is a plain labeled input.

- **Edit form (`entry_form.rs`)** — stripped: removed the per-field `RevealButton`
  (incl. the password one), `RecoveryCodesField`, the EnvVars `⋯` menu, and
  `RevealCtx`. Sealed fields are `secret_field!` (label + masked input) with no
  reveal button; empty = keep, type = replace.
- **Detail drawer (`vault_detail.rs` + new `detail_secrets.rs`)** — the read
  surface: `DetailSecrets` renders, per type, a per-field row with a secure **Copy**
  (the `copy_field` path — never crosses to WASM) and a **Reveal** toggle that shows
  the value in a `SecretDisplay`. Recovery codes reveal as a list; env vars via the
  `⋯` `.env`/JSON set menu; the SSH private key reveals its full PEM (newlines
  intact). Presence isn't known from the list projection, so every field of the
  type is offered and reveal/copy handle absence as "not set" (mirrors `TotpReveal`).
- The `reveal_an_ssh_private_key_via_ui` e2e now reveals in the **drawer**.

## Documented deviations (see the tracking note's Gotchas)

- **`SshPrivateKeyField` already had a real `<label>`** — the spec said "no
  `<label>` anywhere"; it kept its label (FormField can't host its inline mask
  toggle) and only gained a Reveal button. Intentional, not an oversight.
- **Identity is out of *history* reveal** — `national_id` is optional, so a version
  without one would error; SSH (required primary) is in. The live form still reveals
  the current `national_id`.
- **No per-row env reveal in the form** — env values are read via the set
  copy/reveal (⑥); the per-var clipboard copy stays on `FieldSelector::EnvVar(key)`.
- **The env copy-all clipboard e2e is deferred** — reading the OS clipboard headlessly
  isn't supported in this harness, and the set copy/reveal is fully covered at the
  host level (formatter + session audit-count tests). The reveal UI wiring mirrors
  the e2e-proven `RevealButton` pattern.
- **DatePicker / Note content keep their placeholders** — ⑤'s scope is the two field
  macros + sealed fields; those two are single, unambiguous fields (a Gate-1.0 a11y
  item, not this slice).
