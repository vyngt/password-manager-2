# Slice 1.2 — Create Vault Shell (IPC + Tauri)

**Scope:** `vedge-ipc` + `vedge-tauri` (shell only — no UI, that's slice 1.3).

Exposes slice 1.1's `create_vault` core use case to the frontend via a Tauri command that leaves the new vault **unlocked in `AppState`** and returns the Emergency-Kit Secret-Key string. Mirrors the existing `unlock_vault` command.

## Added

- **`vedge-ipc`** — `CreateVaultInputDto` (`vault_path`, `master_password`, `#[serde(default)] secret_key_b64: Option<String>`) + `CreateVaultOutputDto` (`secret_key_display`, `keychain_stored`); exported from the crate root. +3 serde round-trip tests.
- **`vedge-tauri`**:
  - `dto/misc.rs` — re-export both DTOs + `decode_create_secret_key` (mirrors `decode_unlock_secret_key`). +2 decode tests.
  - `error.rs` — `CommandError::AlreadyExists` + `VaultError::VaultAlreadyExists => AlreadyExists` mapping.
  - `state.rs` — `AppState.create_vault: CreateVault` field + `AppState::new` parameter; wired into all three constructor call sites (`compose`, `compose_test_state`, `state_fixture`). +2 behavior tests.
  - `commands/vault.rs` — `create_vault` command: runs the use case (`kdf_params: None`), stores the unlocked session via `insert_session`, returns `CreateVaultOutputDto`.
  - `lib.rs` — registered `commands::vault::create_vault` in `generate_handler!`.

## Fixed

- **Workspace build.** Slice 1.1 added `VaultError::VaultAlreadyExists`; `error.rs`'s `impl From<VaultError>` is exhaustive (no `_` arm), so `cargo build -p vedge-tauri` was failing (non-exhaustive match) until this slice's mapping was added.

## Deviations from the spec (see slice tracking note)

1. Command passes `kdf_params: None` (spec snippet predates 1.1's added `CreateVaultInput.kdf_params` field). `None` → production `argon2id_default()`.
2. No inline recents — mirrors `unlock_vault`, which doesn't touch recents (that's a separate command the UI calls). The onboarding UI (1.3) will call `add_recent_vault`.
3. Behavior tests live in `state.rs`'s `#[cfg(test)]` module and drive `state.create_vault.execute(...)` + `insert_session(...)` directly (command fns can't be invoked with a `tauri::State` in unit tests) — this also resolves the deferred real-session TODO in the existing `is_unlocked` test.
4. `out.keychain_error` isn't surfaced in `CreateVaultOutputDto` (spec DTO has only `secret_key_display` + `keychain_stored`); the detail is logged in core.
