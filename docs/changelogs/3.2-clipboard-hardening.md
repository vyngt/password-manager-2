# Slice 3.2 — Clipboard Hardening

Copied secrets leaked into OS **clipboard history** (Win+V), **cloud clipboard** sync, and third-party
clipboard managers — all of which capture **at set-time**, so the Phase-2 30 s auto-clear removed
nothing from them. This slice marks every secret we place on the clipboard with the platform's
**exclusion hints**, and routes the renderer-side copies (which can't set OS hints from WASM) through the
same hardened native provider. No new user feature — it hardens an existing path and unifies a second.
Spec: `.../Phase 3 - Password Generator/Specs/3.2 - Clipboard Hardening`.

## Key discovery — arboard 3.6 exposes the hints natively (no shims)

The spec anticipated per-platform `windows`/`objc2`/`x11rb` shims "a few dozen lines each." **They were
not needed.** The resolved `arboard 3.6.1` already exposes the exclusion builders on all three platforms,
reachable **under `default-features = false`** (target-cfg-gated, never feature-gated). So Part A is a
cfg-branched one-liner per platform on arboard's `Set` builder — **zero new crates, zero version bump,
zero shims**. `[DRIFT]` from the spec's shim plan, recorded in the spec + tracking note.

## What shipped

### Part A — hardened `ArboardClipboardProvider::set` (`vedge-core`)

`set` (the single native chokepoint; only ever handed secret values) now writes via the builder with a
cfg-branched hint, unconditionally:

| Platform | arboard call | Effect |
|---|---|---|
| Windows | `SetExtWindows::exclude_from_monitoring()` | `ExcludeClipboardContentFromMonitorProcessing` — the documented superset (Win+V history **and** cloud clipboard) |
| macOS | `SetExtApple::exclude_from_history()` | writes `org.nspasteboard.ConcealedType` |
| Linux/X11 | `SetExtLinux::exclude_from_history()` | writes the concealment targets (incl. `x-kde-passwordManagerHint`) |

`copy_field` / `copy_history_field` inherit the hints with **no call-site change** — they already route
through the provider. `clear()` is unchanged: hints stop *capture*, the 30 s clear shrinks the *live*
window; they're complementary.

### Part B — unify the frontend copy through the hardened provider

- **Core:** extracted `pub fn place_text_on_clipboard(clipboard, text: Zeroizing<String>, secs)` from
  `place_field_on_clipboard` (which now delegates to it) — one write-then-detached-clear path shared by
  entry-field copies and the new generic copy. `MemoryClipboardProvider` gained a `set_count` test hook.
- **Tauri:** new `copy_text` command (`commands/clipboard.rs`) using the app-global `AppState.clipboard`
  — **no vault session required**, so it works pre-unlock too. The secret crosses IPC once and is
  zeroized native-side after the write (same discipline as `copy_field`). Registered in `generate_handler!`.
- **App:** `api::clipboard::copy_text` wrapper mirroring `api::entry::copy_field`.
- **vedge-ui:** `CopyButton` gained an optional `copy_with: Option<CopyWriter>` strategy prop
  (`CopyWriter = Callback<String, CopyFuture>`, `CopyFuture = Pin<Box<dyn Future<Output = bool>>>`). When
  set, the write goes through the caller's async strategy instead of the browser Clipboard API, and the
  check-mark swaps **only when the returned future reports success** — so the indicator can't disagree
  with the real outcome. Default (`None`) keeps the existing browser path unchanged.
- **Repointed both frontend copy sites** to `copy_with` → `api::clipboard::copy_text`:
  - `generator_panel.rs` (the 3.1 generated secret), and
  - `secret_display.rs` — which copies the Emergency-Kit **Secret Key** *and* revealed **entry-history**
    secrets (used by both `vault_setup.rs` and `entry_history.rs`). A highly sensitive, long-lived
    secret; closing its browser-clipboard leak is a small, principle-aligned scope addition (`[DRIFT]`
    beyond the spec's enumerated generator + future-3.5-bulk sites).

New i18n: `generator.copy_failed` + `vault.copy_failed` (en + vi).

## Decisions

- **D1 — all three platform arms implemented.** Windows verified locally (build + clippy + the Win+V
  smoke below); macOS/Linux arms are single arboard calls, **compile-verified by inspection only** (no CI
  matrix; Windows-only dev). Recorded honestly in the tracking note.
- **D2 — `secret_display` repointed** (see above) — deliberate, principle-aligned scope addition.
- **D3 — reusable `copy_with` strategy prop** on the shared `CopyButton` (vs. a bespoke button) — reused
  by the generator + Secret Key now, and available to 3.5 bulk-copy later.
- **D4 — `tauri-plugin-clipboard-manager` kept.** No first-party code invokes it after the repoint
  (`CopyButton`'s default path uses web-sys `navigator.clipboard`, not the plugin), so it is a removal
  candidate — but the spec says "flag, don't necessarily remove," and dropping it churns capabilities.
  Kept this slice; removal is a low-risk hygiene follow-up.

## Tests (+2, in `vedge-core`)

- `place_text_on_clipboard_routes_through_provider` — a far-future clear delay keeps the value live;
  asserts `peek() == Some(value)` and `set_count() == 1` (the write went through the port, not a browser
  path).
- `place_text_on_clipboard_schedules_clear` — `clear_after_secs = 0`; polls until `peek() == None`
  (the detached clear still schedules + fires).

OS hints are platform side-effects, **not host-testable** — they're covered by cfg-compile (Windows arm
type-checks locally) + the manual Win+V smoke.

## Residual risk (honest)

Hints are **cooperative** — a malicious clipboard monitor ignores them; kernel/user-space malware in an
unlocked session is out of the threat model. **Wayland** has no universal hint and arboard's Wayland
exclusion is behind the `wayland-data-control` feature (off under `default-features = false`) — documented
residual. The plaintext that reaches the DOM for display and crosses IPC once for the copy is outside
Rust's zeroize control — the pre-existing documented residual, not a regression. This slice defends the
realistic bulk of the exposure: default OS history/cloud sync + well-behaved managers.

## Out of scope

Auto-paste / type-instead-of-copy / clipboard-free autofill (a Phase-10 browser-extension concern).
Dropping the clipboard-manager plugin (hygiene follow-up per D4). 3.5 bulk-copy UI doesn't exist yet —
this slice ships the `copy_with` + `copy_text` seam it will reuse.
