# Slice 2.5 — Folders UI

**Scope:** `vedge-app` only. Client-side folder navigation over the already-loaded index — a folder
is an `EntryType::Folder` entry; other entries (and sub-folders) reference it via `meta.folder_id`, so
the whole hierarchy is derived from the loaded `Vec<IndexEntryDto>`. The persist paths already existed
(`move_entry`, `create_entry`, `soft_delete_entry`) — **no `vedge-core` / `vedge-ipc` / `vedge-tauri`
change**.

Two commits: **(1)** the tree / filter / breadcrumb / create / move / empty-first delete; **(2)**
drag-and-drop move.

## Added / changed

### new modules (`features/vault/`)

- **`folder_tree.rs`** — the pure, host-tested core plus the nav components:
  - `build_folder_tree` (**cycle-safe** — a folder whose parent chain loops is grafted to root),
    `flatten_tree`, `folder_path`, `descendants_of`, `subtree_contents` (recursive contents of a
    folder, root excluded), `available_move_targets` (excludes self + descendants),
    `folder_display_name`, and `FolderScope { All, Unfiled, Folder(id) }` + `scope_matches`.
  - `FolderTree` — the sidebar: an **All items** node, an **Unfiled** node (`folder_id == None`), the
    nested folders (indented, collapsible via a per-tree collapsed set + chevrons, with per-folder
    entry counts), and an inline **"+ New folder"** input that creates into the current folder.
  - `FolderBreadcrumb` — `All › … › current`, each segment navigable.
- **`folder_move.rs`** — `FolderMove` (a page-level dialog opened from the row action, the detail
  button, or the palette command; picks "No folder (root)" or a valid target) and `FolderSelect`
  (the create/edit form's folder field, bound to `EntryFormData.folder_id`). Both build their option
  list from `available_move_targets`, so a folder can never be moved into its own subtree.
- **`folder_delete.rs`** — `FolderDelete`, a **two-stage empty-first** confirm. An empty folder is
  deleted directly by the page; a non-empty folder opens this dialog, which reports the recursive
  content count and offers **"Empty folder"** (soft-deletes every descendant entry + sub-folder via
  `subtree_contents`). Because the count is read reactively, once empty the dialog flips to **"Delete
  folder"** — "empty first, then delete", in one dialog.

### edits

- **`vault_filters.rs`** — `Filters.scope: FolderScope`; `filter_and_sort` gains a `scope_matches`
  predicate. `filter_by_folder` host test (All / Unfiled / Folder).
- **`entry_form.rs`** — `switch_type` now preserves `folder_id` (the folder field is shared across all
  types, so switching type shouldn't discard it).
- **`vault_table.rs`** — a per-row **"Move to…"** action (opens `FolderMove`); `folder_id` added to
  the `<For>` key so an optimistic move repaints; rows are **`draggable`** (commit 2), stashing the
  entry id on `dataTransfer`.
- **`vault_detail.rs`** — a read-view **Folder** row (resolved via a new `folders` prop) + a **"Move
  to…"** button (works for any type, Document included); the edit branch mounts `FolderSelect`
  (excluding self + descendants when editing a folder).
- **`vault_create_form.rs`** — mounts `FolderSelect`.
- **`ui_state.rs`** — `move_request: RwSignal<u32>` ticket. **`command_palette.rs`** — an
  `ActionId::MoveToFolder` ("Move to folder…") command (any selected entry) that bumps it.
- **`pages/v/manage/vault.rs`** — a `current_scope` signal + a `folders` `Memo` (rebuilt from
  `items`); the `Filters` literal gains `scope`; the tree sidebar + breadcrumb mount (hidden in
  trash, and `current_scope` resets to `All` on trash toggle); `move_target` / `folder_delete_target`
  signals + the `FolderMove` / `FolderDelete` mounts; an `on_move` (optimistic `folder_id` flip →
  `move_entry` → revert), `on_new_folder` (`EntryFormData::new(Folder)` → `create_entry`), delete
  routing (folder-with-contents → dialog; else direct), `on_empty` (sequential recursive
  soft-delete), `on_delete_folder`, and a `move_request` effect that opens the picker for the
  selected entry (palette).
- **drag-and-drop (commit 2)** — the tree's nodes are drop targets: a dragged row onto a folder moves
  it there, onto **All**/**Unfiled** moves it to root; folder drops validate against
  `available_move_targets` (a folder can't be dropped into its own subtree); a drag-over ring
  highlights the active target. The menu / detail / palette moves stay the accessible path.
- **`locales/{en,vi}/vault.yaml`** — `folders_label`, `folder_root`, `folder_unfiled`, `folder_new`,
  `folder_new_placeholder`, `folder_toggle`, `folder_none`, `folder_label`, `folder_move`,
  `folder_move_title`, `folder_move_here`, `folder_delete_title`,
  `folder_delete_not_empty` (`{{ count }}`), `folder_empty_action`, `folder_delete`,
  `folder_delete_empty_confirm`, `cmd_move_folder`, `err_move`, `err_folder_create`,
  `err_folder_delete` (both locales, key-aligned; `src/i18n.rs` regenerated).

### review fixes (post-open, same PR)

- **Folder entries are no longer listed as rows.** `filter_and_sort` drops `EntryType::Folder`, the
  type facet no longer offers `Folder`, and the tree counts exclude folders — folders are navigated in
  the tree only. This also fixes a drag confusion: a sub-folder used to appear in its parent's list
  (not a drop target), so dropping an item there did nothing; now the only folder target is the tree
  node. (+`folders_are_never_listed` test.)
- **Folder management moved into the tree.** Each tree folder row gains hover-revealed **rename**
  (inline input; persists via `get_entry` → set name → `update_entry`, no secrets since a folder has
  none) and **delete** (routes through the same empty-first `on_delete`). Deleting the currently-scoped
  folder falls back to `All`.
- **Sidebar polish.** The folder panel is **resizable** — a right-edge drag handle (pointer-capture,
  no window listeners) sets its width as a viewport fraction clamped to **20–40vw**. Long folder names
  stay single-line with an ellipsis and a `title` tooltip (**hover to see full**). The always-visible
  "New folder" input/button collapsed into a compact **`+` toggle** in the panel header that reveals an
  inline input (Enter creates, Escape cancels).

## Deviations from the spec (see the 2.5 slice tracking note)

1. **Navigation scope = `FolderScope { All, Unfiled, Folder }`** (spec used a bare
   `current_folder: Option<String>`). `All` (default) shows everything — non-breaking, and matches the
   spec's *"'Root/All' clears it"* — while the requested dedicated **"Unfiled"** node covers the
   root-only (`folder_id == None`) view. The spec's *"Root = folder_id == None"* is the move-to-root
   target (moving an entry out).
2. **Delete rule = empty-first, not reparent-to-root** (the spec recommended reparenting children to
   root). Per the owner's call: an empty folder deletes directly; a non-empty folder blocks with a
   dialog whose **"Empty folder"** recursively soft-deletes the contents (nested sub-folders
   included), then flips to **"Delete folder"**. No silent orphans, and children aren't silently
   relocated.
3. **Move reachable four ways** (spec listed a row/detail "Move to…"): row action, detail button,
   palette command, and drag-and-drop — all through the one `on_move` (optimistic + `move_entry`).
4. **Three new files, not two** — `folder_delete.rs` split out from the two the spec named
   (`folder_tree.rs`, `folder_move.rs`) to keep each focused.
