The last slice of Phase 2 — pure close-out, no new features. Fixes the one medium review bug, finishes
the raw-`<button>` accounting, reconciles the docs, tickets/routes the rest of the review ledger, and
flips the roadmap to Phase 3. The DoD is ticked against 2.9.2's green `mise e2e` daily-loop.
Spec: `.../Specs/2.10 - Phase 2 Close-out`.

## Headline decision — the lint adoption is carved out to 2.10.1

The spec folded in the 1.9 `TODO(lint-adoption)` debt: turn on `[lints] workspace = true` for
`vedge-app` + `vedge-ui` so the whole workspace passes `cargo clippy --all-targets -- -D warnings`.
The spec estimated ~408 (app) + 66 (ui) ≈ **~474** warnings and **pre-authorized splitting the lint
work "if it genuinely balloons mid-slice."** Measured reality:

- **459 production deny-lint errors** — vedge-ui **381**, vedge-app **78** — dominated by
  float/integer arithmetic on presentation/color/geometry math (~334) + `let_underscore_must_use`
  (~83), with a small `indexing_slicing` (~28) / `unwrap`/`expect`/`panic` (~15) tail.
- **~1,700 pedantic/nursery warnings** (app ~818 led by `must_use_candidate` ~407; ui ~914). The
  spec's "vedge-ui 66" was the *default*-clippy count — vedge-ui has **no** `[lints]` opt-in at all,
  same as vedge-app.
- Total ~2,000+ diagnostics across 55+ files — **~4× the estimate.**

Honoring the tracking-note guidance ("per-line `#[allow]` with a reason, **not a blanket disable**")
for that load is a large, review-worthy effort; cramming crate-level blanket allows into a close-out
to force-green it would violate that preference *and* silently weaken the gate. So the full lint
adoption is carved into a dedicated follow-up **2.10.1** (per-scope allows + its own review). Phase 2
closes on substance; the lint gate follows as hardening. Captured in the Phase-3 backlog.

## What shipped

### Fixed — lock-on-blur during our own native dialogs (2.6, medium)

`features/vault/auto_lock.rs` locked the vault on the DOM `window` `blur` event, which fires whenever
the app opens a **native OS file dialog** (Document attach/export, Emergency Kit, vault picker) — so
the vault locked mid file-pick. Guarded at the single chokepoint both dialogs funnel through:

- `api/dialog.rs` — a `thread_local! Cell<u32>` dialog-in-progress counter (WASM is single-threaded)
  with an RAII `DialogGuard` spanning the `dialog_open`/`dialog_save` await in both `open()` and
  `save()`, cleared on every exit path (including a dropped/cancelled future). New
  `pub fn dialog_in_progress()`.
- `auto_lock.rs` — the `blur` handler and the idle-tick lock both return early when a dialog is in
  progress, read **untracked** (owner-less JS callbacks touch only the `thread_local`, no reactive
  owner). Real alt-tab / minimize still fires blur with no dialog open and locks as before.
- Host unit test for the guard set/clear/nesting. Covers all 6 dialog sites (2 live under `/v/vault`
  today, 4 future-proofed) with no new IPC and no context plumbing.

### Raw-`<button>` sweep — resolved as documented exceptions

The 3 files 2.9.1 left (5 raw `<button>` sites) were investigated: **all 5 regress** on a
`Button`/`IconButton` conversion (size 32/40/64px vs the DS 28/36/44, 8px radius vs 6px-max,
primary-tint hover vs surface-2, or a variant that doesn't exist). Per the spec ("or kept with a
documented exception"), each now carries a one-line in-code exception comment: the 64px circular
biometric tap-target (`vault_unlock_panel.rs`), the full-width sidebar collapse bar + the two Lock nav
rows (`pages/v/layout.rs`, which must stay pixel-identical to their `role="button"` siblings), and the
titlebar locale toggle (`window_panel.rs`, inherits the computed chrome foreground). Building the
missing `vedge-ui` variants is routed to a Phase-3+ follow-up.

### Gates — fmt drift fixed

Pre-existing `fmt-check` drift (accumulated across ~48 files) cleared with a tree-wide `cargo fmt` +
`leptosfmt`; the `.into_any()` / comment rustfmt↔leptosfmt non-convergence was resolved by iterating
leptosfmt to its fixpoint. Both `cargo fmt --all -- --check` and `leptosfmt --check` are clean.
