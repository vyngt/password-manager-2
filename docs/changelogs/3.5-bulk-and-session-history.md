# Slice 3.5 — Bulk + Session History

Closes the generator track. Two conveniences that share one security concern — **live secrets in
renderer memory**: **bulk-generate N** (produce up to 50 secrets from the active spec and pick/copy one)
and a **session-only history** of panel-generated secrets you can re-copy/re-use. Both are held in
`Zeroizing`, capped, **never persisted** to `app.db` or the vault, and the history is **wiped when the
vault locks** — the app's **first explicit session-secret wipe**, implementing
`05 Research/Core Hardening/04 - Memory Hygiene Gaps` ("get the types right first"). Spec:
`.../Phase 3 - Password Generator/Specs/3.5 - Bulk and Session History`.

## What shipped

### Engine — `generate_many` over `GenSpec`

3.4 shipped first, so bulk operates on the whole `GenSpec` (all five modes), not just `RandomConfig`
(the spec's forward-compat branch). Additive, in `lib.rs` over the existing `generate_with_spec` dispatch:

```rust
pub const MAX_BATCH: u32 = 50;
pub fn generate_many(spec: &GenSpec, count: u32) -> Result<Vec<GeneratedSecret>, GenError>;
```

Mirrors the `generate` / `generate_with_spec` split with a `pub(crate) generate_many_with<R: Rng>` so
tests inject a seeded `StdRng`. The RNG is fetched **once** and looped, each item an independent CSPRNG
draw; the config is validated **once** up front (`entropy_bits(spec)?`) so an invalid spec fails fast
without allocating a partial batch. `GenError` gained a payload-free `BatchOutOfRange` (`count ∉ [1,50]`)
and stays `Copy`. For a fixed spec every item carries the same `entropy_bits` (a property of the process)
but a distinct secret.

### App — session history context + wipe-on-lock

`GeneratedHistoryCtx { items: RwSignal<Vec<HistoryItem>>, next_id: RwSignal<u64> }` (new
`features/generator/history.rs`), provided once in the **durable `App` body** (above the router, so it
survives the `/v` unmount that fires on lock — mirrors `GeneratorPrefsCtx`). `HistoryItem { id, secret:
Zeroizing<String>, entropy_bits }` is **`Clone`-only — deliberately not `Serialize`/`Debug`**, so it can
neither be written nor logged. A Leptos-free `push_history(buf, item, cap)` (prepend + truncate) is
host-tested; the ctx's `push` stamps a monotonic `id` (for stable `<For>` keys) and calls it.

**Wipe on lock** is a single prev-guarded `Effect` in `app.rs` watching `ActiveVault.path`: all three lock
paths (idle auto-lock, sidebar Lock, palette Lock) drive it `Some→None`, so one `true→false` transition
empties the buffer — evicted items drop → zeroize. Guarded so mount and unlock don't fire.

### App — panel bulk + Recent sections

`GeneratorPanel` gained two **collapsible** sections below the primary flow — **collapsed by default in
the Login-form popover** (`on_use.is_some()`) so it stays as compact as 3.4 left it, **open on the
standalone `/v/generator` page**:

- **Generate multiple** — a `NumberInput` count (1–50, default 10) + a "Generate" `Button` calling
  `generate_many` (pure/sync, no spinner). Results render in a scroll-capped list; each row is a shared
  `SecretRow` (masked + reveal + a compact process-entropy band + hardened `CopyButton` + a **Use/pick**
  action when a form is present). Picking fills the field; picking or copying a row pushes it to history.
- **Recent** — the history buffer as a scroll-capped `<For>` list (reveal/copy/Use), a **Clear** button,
  a "**History clears when the vault locks**" caption, and an `EmptyState` before anything is generated.

**History feeders** are exactly the spec's: each **Regenerate** (and mode-switch, which regenerates) and
each **bulk pick/copy**. The mount-seed secret and the 3.3 inline Login wand stay **out** (a form-fill, not
a review action). Copy everywhere still routes through the hardened 3.2 native `copy_text`. New en + vi keys.

## Decisions

- **`generate_many(&GenSpec, count)`**, not `&RandomConfig` — 3.4 (PR #33) merged before pickup, so bulk
  gets every mode for free.
- **History buffer is a reactive `RwSignal<Vec<HistoryItem>>` at app root** (the Recent list + wipe need
  reactivity), plus a monotonic `next_id` **never reset on clear** — so `<For>` keys never collide across
  lock/unlock cycles.
- **Bulk rows are rendered by a plain map, not `<For>`** — the batch is always replaced wholesale, and
  index keys would let a same-length new batch **reuse stale row DOM** (the non-reactive `secret` wouldn't
  update). History keeps `<For>` because its ids are globally unique.
- **Bulk + Recent live in both mounts but collapsed-by-default in the popover** — honors the spec's
  "available in both" while respecting the just-tightened popover (the spec's always-open "between Output
  and Entropy meter" placement predates the 3.4 mode picker).
- **Compact rows show a colored band word** (reusing the meter's `band_*` labels), not a raw bits number —
  glanceable and needs no new key.

## Security / memory hygiene

The session buffers hold `Zeroizing<String>`; the cap (20 history / 50 batch) bounds live copies;
eviction, Clear, batch-replace, and **wipe-on-lock** all drop → zeroize. `HistoryItem`/`BulkRow` are
non-`Serialize`/non-`Debug`, so history **cannot** reach `app.db`/the vault or a log. History is a
*deliberate* copy set (that's the feature) — the "secrets move, never clone" rule can't fully apply to a
review buffer, so it's **bounded** instead (cap + `Zeroizing` + wipe + non-serializable + Clear), per the
research note's honest-scoping clause. The plaintext a row paints to the DOM for display/copy is a bare
`String` — the same documented residual as the primary Output row; the buffers themselves stay `Zeroizing`.
No secret crosses IPC beyond the sanctioned hardened copy. No secret logging.

## Out of scope

Persisted history — **never** (the whole point is session-only). Zeroizing the 3.3 form password field —
a separate memory-hygiene follow-up. Mode-aware bulk beyond what `generate_many(&GenSpec)` already gives.
OS-screen-lock / idle wipe beyond the app's own lock (covered transitively — idle auto-lock funnels
through `active.path → None`). Pushing the primary Output copy into history (spec excludes it; only the
mount-seed secret is ever absent from Recent).
