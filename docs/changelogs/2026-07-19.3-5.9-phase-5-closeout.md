## ④ Carried bugs + the wasm-link CI gap (shipped first — independent, low-risk)

- **The wasm LINK is now gated in CI.** `mise run ci`'s wasm phase is only a `cargo check`
  (type-check); the frontend was never *linked* in CI, and a link-class `rust-lld` crash escaped
  that gap **twice** (4.6b, 4.9a). New `mise wasm-link` task (`trunk build`, debug — the crash was
  a debug-wasm failure) runs as its own PR step in `ci.yml`. Kept out of `mise ci` so local `mise ci`
  stays fast.
- **The audit-summary reversed range** (`"101–100 of 40"`). When retention prunes the log below a
  page the user had navigated to, the fetched page is empty (`count == 0`) while `total > 0`, so
  `start = offset+1` outran `end = offset+count`. Extracted the math into a pure, unit-tested
  `audit_summary_range` that returns `None` for an empty page and clamps `end` to `total`.
- **Re-key missing-blob error now names the entry.** `read_blob`'s bare `Storage(Io)` /
  `DecryptionFailed` didn't say which entry aborted a re-key; wrapped at the call site (cause preserved).
- **Completeness-guard honest-limit** (5.8 review): a doc amendment — the `..`-less `EntryPayload`
  match makes a partial re-key *impossible on the payload-variant axis* but only *detectable* on the
  surface/table axis, which the integration completeness test guards.
- **Stale `settings.rs` module doc** ("Security | Appearance" → the actual five tabs incl. Credentials).

## ③ The credential-age nudge (the bulk)

Phase 5 built change-password · rotate-SK · Recovery Key · re-key, but nothing told a user any of it
was due — and the audit log could not tell a password change from a Secret-Key rotation (both
funnelled through `change_password` → `PasswordChanged`).

- **Two new `vault_config` timestamps** — `last_password_change_at` + `last_secret_key_rotation_at`
  (migration `m20260719_100013`, additive nullable, **no `schema_version` bump**). 🔴 Stored in
  config, **NOT derived from the retention-pruned audit log**: a derived age would silently read
  "never" after 90 days — i.e. misfire hardest exactly when the credential is oldest (the inverted
  failure mode). A `NULL` resolves to `created_at`, never "never".
- **Persisted two ways, mirroring `recovery_slot`:** `change_password` writes them in the
  `rewrap_all_deks` transaction (both columns added to its `update_columns`); `rekey_vault` (which
  persists via `save_config`, that omits them) uses new targeted setters — and also nulls
  `last_snapshot_at`, since it retires the snapshot store (the 5.8 self-review bug).
- 🔴 **The rotation signal is an explicit `secret_key_rotated: bool`, NOT `new_secret_key.is_some()`.**
  `change_password_after_recovery` passes `Some(same_key)` (5.7 C4 re-stores the key on a fresh
  device), so `is_some()` would wrongly record a rotation. `rotate → true`, recovery-reset → `false`,
  plain change → `false`. A fail-first test (`credential_age.rs`) guards this exact edge.
- **A distinct `AuditAction::SecretKeyRotated`** (24 → 25 across the enum/`ALL`/`as_str`/`parse`, the
  IPC `ACTION_NAMES`, the tauri pin test, the app's `AUDIT_ACTIONS`/label/severity, en+vi locale).
  The 5.4 `Viewed`-conflation fix, applied to credentials.
- **The nudge** — a session-backed `credential_status` command (resolves `NULL → created_at`
  server-side; a `CredentialStatusDto` of two RFC-3339 strings, no secret) drives a quiet Warning
  `Badge` on the Change-Password (> 1 year) and Rotate-Secret-Key (> 2 years) rows. Conservative
  thresholds — a nagging password manager trains users to click through warnings. The SK nudge copy
  carries 5.6's keep-your-old-kit warning: a nudge toward a destructive act ships that act's warning.

## ① The kill-mid-restore smoke — a seam + an automated real-process-kill test

Open since **5.2b** (~14 slices). The journal's crash *state machine* is proven by the in-process
crash-matrix `Fixture`, but a real hard-kill on real hardware — the fresh-process fsync-durability
path — had never run, because the post-commit journal transitions are size-independent microsecond
metadata renames a `taskkill` can't land on by timing.

- **The seam:** `journal::persist` gains a `cfg(debug_assertions)`, env-gated pause
  (`VEDGE_RESTORE_PAUSE=Staged|HomeAside|Swapped|*`) that prints `PAUSED:<state>` and blocks, making
  every state deterministically killable. ~15 lines, compiled out of release (release-impossible,
  like the `VEDGE_E2E_*` / fast-KDF seams).
- **The automated smoke** (`tests/kill_mid_restore.rs`, `mise kill-smoke`): the "re-exec self"
  pattern — a runner spawns the test binary as a child that builds a vault + snapshot and reverts
  (blocking at the seam), hard-kills it (`TerminateProcess`) at each journal state, then re-opens the
  home in a **fresh** process and asserts recovery keeps the committed data. **All three states pass.**
  Reused the rekey test's lesson (drop the harness's own `vault.vdb` handles before the swap — Windows
  won't move a home with an open file), which the smoke caught when omitted.

## ② Legacy-tag retirement — audit, then CONFIRM-KEEP

Whether the legacy-tag read path (`decrypt_legacy_tag` + the at-unlock `migrate_legacy_tag`, the only
thing that can read a pre-5.6.0 KEK-sealed tag) can be retired — decidable only behind a prove-absence
audit (the 5.2.5 discipline: cannot-see ⇒ FAIL).

- New `scripts/tag_legacy_audit.ps1` + `mise tag-legacy-audit` counts `tags WHERE dek_wrapped IS NULL`
  across every reachable surface (live vaults, snapshots, scannable `.vbk`s — tar-extracted + queried,
  `dek_wrapped` being a plaintext column).
- 🔴 **Verdict on this machine: NOT clean → CONFIRM-KEEP.** The audit found real legacy tags in 4 dev
  vaults not opened since 5.6.0 (their migration never ran) + a `.vbk` it couldn't extract. Absence is
  not provable here without those vaults' passwords, so — per the spec's fallback (the
  `backfill_vault_uuid` precedent) — the legacy-tag path **stays**; no code deleted. The DO-NOT-TOUCH
  list (`format_version > CURRENT` = H1, `read_snapshot_tag_names`'s degrade, `backfill_vault_uuid`)
  is untouched.
