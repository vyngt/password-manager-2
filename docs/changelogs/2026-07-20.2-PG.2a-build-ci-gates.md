# Slice PG.2a — Build & CI Gates (2026-07-20)

The first of two PRs for **PG.2 (Attack Surface & Build Gates)**. PG.2b removes attack surface (curating
the Tauri capability set, setting a real CSP) — changes that break **silently**: a missing CSP directive is
a blank window, not a compile error. The two things that catch that class — **e2e's `assert_console_clean`**
and a **release-profile compile** — are exactly what CI lacked. So the net is built first: **2a ships the
gates, 2b's acceptance depends on them being green.** (5.8 already paid this bill — its Credentials-tab move
broke three e2e suites, invisibly, for a whole slice, because `e2e.yml` was dispatch-only.)

## `mise release-check` — the third "a build configuration nobody verifies" gate

`mise ci`'s wasm phase is a `cargo check` **debug**; 5.9's `wasm-link` is a `trunk build` **debug**; the
release bundle is only ever built locally by `mise build`. So a **release-only** code path was compiled by
**no** CI job. New `[tasks.release-check]` (`cargo check --workspace --exclude vedge-e2e --release` + the
frontend wasm under `--release`), wired as its own `ci.yml` step beside `wasm-link` — deliberately **not** a
`depends` of local `ci` (a release check is minutes; keep the local gate fast, 5.9's reasoning).

🔴 **It caught a real, pre-existing release-only break on its first run** — the strongest possible
justification for the gate:

- **`vedge-ui` `TIER3_TYPES` was dead in release.** The const's only reader, `assert_supported_type`, is
  `#[cfg(debug_assertions)]`; in a release build the function is compiled out, leaving the const unused →
  `-D dead-code` fails. **The real release bundle was broken on `develop` and no CI job compiled it.** Fixed
  by moving the const *inside* its only (debug-gated) consumer, so it can never go dead on its own.

## `/playground` gated out of release builds

The component gallery shipped in the release binary — dev surface in a password manager, reachable by URL,
unaudited, dead weight. Now `#[cfg(debug_assertions)]` (the codebase's dev-seam precedent — `app.rs`'s
`install_test_hooks`): `pages.rs` module, the `routes.rs` import, and the router mount. `mise ci` + `mise e2e`
build **debug** and keep it.

- 🔴 **A `#[cfg]` on a single `<Routes>` child breaks the router's child-tuple type inference** (rstml emits
  it in a way the `RouteChildren` tuple builder rejects). So `AppRoutes` is split into two whole cfg-gated
  functions — the release variant simply omits `<PlayGroundRoutes/>`. The top-level route list is tiny and
  stable (real routes live inside `<VRoutes/>`); a keep-in-sync note guards the duplication.
- 🔴 **The `playground` i18n namespace stays** (`build.rs`) — `features/vault/vault_search.rs` consumes
  `playground.clear`. The gate is on the module, not the locale keys.
- **A second dead-code fell out and was handled:** `api::settings::duplicate_theme` was called *only* from the
  playground theme gallery, so gating `/playground` orphaned it in release → gated the wrapper to
  `#[cfg(debug_assertions)]` too (the backend command stays registered). `release-check` surfaced it
  immediately — the gate paying for itself twice in one slice.

## e2e in the PR gate + a tighter console-clean net

- **`e2e.yml` now triggers on `pull_request: [develop, master]`** (plus a nightly `schedule` backstop), both
  on the **self-hosted** runner — GitHub-hosted runners can't reliably drive WebView2/WebDriver, and the
  self-hosted box (the dev machine, from 2.9.2) has WebView2 + msedgedriver at zero hosted minutes.
  `runs-on: ${{ inputs.runner || 'self-hosted' }}` resolves across all three triggers.
  🔴 **Honest caveat, recorded in the workflow:** this gate is only as live as the runner — offline, the PR
  check *queues* rather than fails, so it can't block a merge on its own; the nightly is the backstop so a
  regression can't hide longer than ~24h. (An honest "runs nightly" beats an aspirational "runs on PRs.")
- **`assert_console_clean` broadened** to also fail on `"Content Security Policy"` reports. A *throwing* CSP
  violation (dropping `'wasm-unsafe-eval'` → WASM won't instantiate) already surfaced as `uncaught:`, but a
  *non-throwing* one (an `img-src`/`connect-src` beacon block that only `console.error`s) slipped every match.
  With this, **every e2e scenario becomes a standing CSP regression test** — the net 2b's changes land into.

## `bundle.targets` narrowed to Windows

`"all"` (deb/appimage/dmg for a Windows-only v1.0) → `["nsis", "msi"]`. Only bites `cargo tauri build`;
`release-check`/`mise ci` unaffected.

## Gates

`mise ci` (fmt + clippy `-D warnings` + test + wasm) · **`mise release-check`** (new — green after the two
dead-code fixes) · `mise wasm-link` · `mise audit` (no dep changes) · `cargo check -p vedge-e2e` (the
broadened filter compiles). PG.1's `assert_vault_coherent` untouched — no vault-state changes in 2a.
