# Slice 2.1 — Multi-type Create & Edit

**Scope:** `vedge-core`, `vedge-tauri`, `vedge-app`. First slice of Phase 2 (Vault UX & Daily Use).

The entry UI stops being Login-only and gains **edit**. The create form gets a **type picker** and builds all eight editable `PayloadDto` variants (`Login, Card, SshKey, ApiKey, EnvVars, Note, Identity, Folder`); a new **`get_entry` reveal** command returns one entry's full *decrypted* payload so the edit form can prefill and preserve secrets — the first deliberate, user-initiated, audited relaxation of "no plaintext in WASM"; `VaultDetail` gains an **edit mode** that reuses the per-type forms and saves through the existing `update_entry`; and the detail read view renders per-type fields with type-appropriate copy buttons. `Document` is excluded from the picker (needs a blob sidecar) → sub-slice 2.1.1.

## Added / changed

### core (`vedge-core`)
- **`application/vault/use_cases/get_entry.rs`** (new) — `get_entry(session, GetEntryInput{ entry_id }) -> Result<EntryPayload, VaultError>`. Mirrors `move_entry`'s decrypt preamble; rejects `EntryPayload::Unknown` with `UnsupportedEntryType`; mirrors `copy_field`'s side-effects (touch `accessed_at` + append `AuditAction::Viewed` + in-memory index update). Read-only — no re-encrypt. Re-exported from `use_cases.rs` and the crate root.
- **`tests/get_entry.rs`** (new) — roundtrip per type (Login + Card/SshKey/ApiKey/EnvVars/Note/Identity/Folder), `Viewed` audit assertion (via `recent_audit`), unknown-type + wrong-id guards. New `Harness::seed_unknown` helper in `tests/common/mod.rs` (encrypts a row with an unrecognized `entry_type`, which the use-case API refuses to serialize).

### shell (`vedge-tauri`)
- **`commands/entry.rs`** — new `get_entry` command (`get_session` + lock, `entry_id_from_str`, then the **existing** `payload_to_dto`). Registered in `generate_handler!` (`lib.rs`).
- **`dto/entry.rs`** — extended the domain↔DTO round-trip tests to cover all nine variants (was Login + Document only). No new conversion function — `payload_to_dto` (the domain→DTO map the spec called `entry_payload_to_dto`) already existed.

### app (`vedge-app`)
- **`api/entry.rs`** — `get_entry(vault_path, entry_id) -> Result<PayloadDto, ApiError>` wrapper (uses `call`, returns the decrypted payload).
- **`features/vault/entry_form.rs`** (new) — pure, host-testable `EntryFormData` (a flat snapshot of every editable field + carry-through values: recovery codes, `tag_ids`/`folder_id`/favicon/favorite/notes, and Document blob metadata) with `to_payload()`/`from_payload()`, plus the `EntryForm` component that renders the active type's fields over a single `RwSignal<EntryFormData>`. The structural branch is driven by a `Memo` on `entry_type` so per-field typing never rebuilds the input tree (no focus loss). Includes `EnvVarsFields` (add/remove key-value rows) and `editable_types`/`type_to_key`/`type_from_key` helpers.
- **`features/vault/vault_create_form.rs`** — added the `<Select>` type picker; renders `<EntryForm>`; builds the payload via `EntryFormData::to_payload`. Removed `to_login_payload` (superseded); the hardcoded English save error is now i18n'd (`vault.err_save`).
- **`features/vault/vault_detail.rs`** — per-type read rendering + type-appropriate copy buttons (`FieldSelectorDto::{Username, Password, CardNumber, Cvv, ApiKey}`); an **Edit** button (hidden for Document/Unknown) reveals via `api::entry::get_entry` → `from_payload` → `EntryForm`, and **Save** persists via `api::entry::update_entry`. Reads `ActiveVault` for the path; new `on_saved` prop refreshes the parent.
- **`pages/v/manage/vault.rs`** — selection switched from an owned `IndexEntryDto` to an **id + derived entry** (`selected_entry` from the live `items`), so an edit auto-updates the open panel instead of showing stale metadata. Wires `on_saved`.
- **`locales/{en,vi}/vault.yaml`** — type-picker, per-type field labels, `edit`/`reveal`/`hide`, `err_save`/`err_reveal`/`err_update`/`err_invalid_expiry`, per-type copy labels; both locales; `src/i18n.rs` regenerated.

### docs
- **`CLAUDE.md`** — new Reactivity anti-pattern entry codifying the recurring i18n/`spawn_local` footgun (safe vs owner-less signal-read contexts).

## Deviations from the spec (see the 2.1 slice tracking note)

1. `entry_payload_to_dto` was **not** written — the existing `payload_to_dto` (`vedge-tauri/src/dto/entry.rs`) already maps every variant; "maps each variant" was delivered as extended round-trip tests.
2. The command builds the id with `entry_id_from_str` (`EntryId::parse` doesn't exist) and uses `get_session` + lock (not the indicative `state.session()` in the spec snippet).
3. `get_entry` mirrors `copy_field` **fully**, including the `accessed_at` touch (the spec's code snippet omitted it; its prose said "consistent with copy_field").
4. The form is a pure `EntryFormData` + one `RwSignal`, not "a union of field signals" — this is what makes the host tests possible without a reactive runtime.
5. Type picker offers **8** types; Document is read-only in detail with its Edit button hidden → **2.1.1**.
6. Selection is id-based/derived so the detail panel auto-refreshes after an edit.

## Fixed (post-review follow-up)

Caught via `cargo tauri dev` after the first push (the self-review these should have surfaced was skipped the first time — now done):

- **Reactive-context warning at `entry_view.rs:12` (via `vault_table.rs`)** — `VaultTableRow` read the i18n locale (`type_label_i18n`) eagerly in its owner-less body. Now `Signal::derive` (matches `vault_detail`); also relocalizes the Type column on language switch.
- **Create-form type picker** — was built once inside `untrack(...)` (froze the labels). Now built inside a reactive `{move || …}` wrapper around `<Select>`, so the picker labels relocalize and the locale read is tracked.
- **Reactive-context warning at `vedge-ui` `textarea.rs:42`** — `auto_resize` read its `NodeRef` with `.get()` (tracked) from inside a `request_animation_frame` callback (no reactive owner). Changed to `.get_untracked()` — it's imperative DOM work and shouldn't subscribe. (One-line vedge-ui fix; affects every `Textarea`, incl. the playground.)
- **Card expiry is now a single `MM/YY` field** (was two `expiry_month`/`expiry_year` inputs). `EntryFormData::card_expiry` parses `MM/YY` (or `MM/YYYY`; 2-digit year → `20YY`) into `(u8, u16)` and rejects a missing `/`, non-numeric parts, or month ∉ 1..=12; `from_payload` renders `MM/YY`. i18n `field_card_expiry` replaces the two prior keys (en+vi).
