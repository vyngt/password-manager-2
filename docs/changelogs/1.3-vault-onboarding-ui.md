# Slice 1.3 — Vault Onboarding UI (Full)

**Scope:** `vedge-app` (Leptos wizard + FFI), `vedge-tauri` (PDF-write command), `vedge-ipc` (error kind). Create flow only — import/recover UI is Phase 3.

A user can now create a vault entirely from the UI: pick a location via a native file dialog, set a master password (confirm + strength gate), create, save the Emergency Kit PDF, acknowledge, and land unlocked at `/v/vault`.

## Added

- **`vedge-app` onboarding wizard** (`features/vault/vault_setup.rs`) — 3-step flow (Location → Password → Emergency Kit) using `StepIndicator`, `Input`, `PasswordStrengthMeter`, `Checkbox`, `Button`. Reachable via a "Create a new vault" button on the unlock screen + a top-level `/onboarding` route.
- **`ActiveVault` context** (`features/vault/context.rs`) — `RwSignal<Option<String>>` provided at the app root, set on successful create; the shared active-vault handle entry screens (1.4/1.5) will read.
- **Native file dialog FFI** (`api/tauri.rs` binding `__TAURI__.dialog.save` + `api/dialog.rs` typed wrapper) — used to choose the `.vdb` location and the Emergency-Kit PDF destination.
- **`api::vault::create`** + **`api::emergency_kit::write_pdf`** wrappers.
- **`features/vault/secret_display.rs`** (mono Secret-Key block + `CopyButton`) and **`password_strength.rs`** (0–4 heuristic feeding the meter) — no `vedge-ui` equivalents existed.
- **`vedge-tauri` `write_emergency_kit_pdf(vault_path, dest_path)` command** — renders the kit and writes it with `std::fs` (registered in `generate_handler!`); `emergency_kit_pdf`'s render body extracted into a shared `render_kit_pdf` helper.
- **`AlreadyExists` made visible to the frontend** — `vedge_ipc::envelope::kind::ALREADY_EXISTS` + `ApiError::AlreadyExists` + `from_envelope` arm, so the wizard shows "a vault already exists here" instead of a generic transport error.

## Deviations from the spec (see slice tracking note)

1. PDF save uses a new backend command (`std::fs`), not the frontend `emergency_kit_pdf` bytes — the fs plugin is scope-gated; a backend write to an arbitrary dialog-picked path is the robust realization.
2. `SecretDisplay` + the wizard step-controller are built local to `vedge-app` (`features/vault/`), not as `vedge-ui` components.
3. `ActiveVault` provided at the app root (must sit above both `/onboarding` and `/v`).
4. Unlock-existing screen untouched; only `dialog.save` is bound (open deferred until the unlock/recents slice needs it).
5. Wizard copy is English literals; i18n wiring deferred (the app's other pages use `leptos_i18n`).
