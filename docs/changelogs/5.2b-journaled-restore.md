# Slice 5.2b — Journaled Restore + Crash Recovery

The second of Phase 5's three backup/restore PRs, and the hard one. Ships the
**journaled, crash-safe restore** half: a vault can now be replaced from a `.vbk`
archive **atomically** — the `.vdb` **and** its whole `.vedge_blobs/` sibling swap
together, a kill mid-restore leaves a consistent `(vault, blobs)` pair on the next
open, and a wrong/newer/unlocked target is refused before a single live byte is
touched. The rollback baseline + the clickable Backup tab follow in 5.2c.

Spec: `.../Phase 5 - Data Safety & Recovery/Specs/5.2 - Backup & Restore` (PR 5.2b).

## What shipped

1. **The intent-journal state machine (`infrastructure/backup/journal.rs`, new).**
   A **write-ahead** filesystem transaction: each `RestoreState`
   (`Staged → VaultAside → BlobsAside → Swapped`) is journaled **and fsync'd before**
   the op it authorizes. Recovery re-drives forward from the recorded state,
   **idempotently, probing the filesystem** (`move_if_needed`) rather than assuming
   an op did or didn't run. `VaultAside` is the commit point: recovery rolls **back**
   only from a bare `Staged`, **forward** from everything after. The original vault is
   preserved as `.old` / `.old-wal` and destroyed **last**, so a lossless rollback is
   available at every forward crash window. Corrupt staged snapshot → roll back from
   `.old`; neither a verified snapshot nor `.old` → `Err` (so `open` never fabricates
   an empty vault). Proven by a `#[cfg(test)]` matrix that crashes at **every** one of
   10 checkpoints and asserts a consistent, clean pair.

2. **`recover_if_pending` at the factory chokepoint.** Wired as the **first line** of
   `SqliteVaultRepositoryFactory::open`, before `VaultDbConnection::open` (whose
   `mode=rwc` would otherwise create a phantom empty vault at a mid-restore path).
   The one function every unlock / biometric / recovery / post-restore open passes
   through — impossible to bypass.

3. **`restore_vault` use case (core).** A **file** operation — no session, no KEK.
   Verifies the whole archive (`verify_archive`), **refuses** an unknown
   `format_version`, a `schema_version` above `CURRENT_SCHEMA_VERSION` (the first read
   of that field since Phase 1), and a `vault_uuid` that disagrees with the target's —
   **all before any live file is touched**. Then extracts + fsyncs the staged tree,
   runs the write-ahead swap, re-opens the restored vault and writes exactly one
   `BackupRestored` audit row (non-fatal — the swap has already committed).

4. **`inspect_backup` use case (core).** Read-only, no session, safe on a corrupt or
   missing target. Reads the archive manifest + the **target's plaintext** identity
   and computes the hard-stops (`uuid_mismatch` / `unknown_format` / `unknown_schema`
   / `target_unreadable`) so 5.2c's dialog can render a *blocked* state. The
   commit-counter / `rollback_delta` fields are carried but `None` until 5.2c.

5. **Read-only target-identity reader (`infrastructure/backup/target.rs`, new).**
   Opens a target `.vdb` `mode=ro` and `SELECT`s `vault_uuid` / `schema_version` /
   `last_unlocked_at` / a live entry count — no KEK, no migration, no write to the
   file it may replace — then **closes the connection** so the subsequent rename
   succeeds on Windows.

6. **WAL correctness.** The swap **preserves** the original `-wal` as `.old-wal`
   (never deletes it — it may hold committed-but-uncheckpointed transactions needed on
   rollback) and deletes only the rebuildable `-shm`. After a forward swap no stale
   `-wal` sits beside the new vault.

7. **`restore_vault` + `inspect_backup` commands (tauri) + DTOs (ipc).**
   `restore_vault` refuses an **unlocked** target (`is_unlocked` → `Invalid`);
   `confirm_rollback` is accepted-but-inert (its gate arrives with the rollback delta
   in 5.2c); `inspect_backup` takes no session. `BackupPreviewDto` / `RestoreReportDto`
   are derivatives only. `BackupRestored` now maps to a **Warning**-class audit badge.

## Decisions honored / drifts from the spec

- **Write-ahead, not op-first (a design fix).** An architect pass found the terser
  "do the op, then advance the journal" design is a data-loss bug: a crash between a
  rename and its journal write leaves the journal one state behind reality, and
  recovery would keep a half-dismantled live vault → an empty vault on next open. The
  shipped design journals **before** the op and recovers by probing the filesystem.
- **Cross-volume is prevented, not refused.** Staging is always
  `<target_parent>/.<stem>.restore-staging`, so the staged→live rename is intra-volume
  by construction — there is no cross-volume case to refuse. (The spec listed a
  cross-volume *refusal*; prevention is strictly stronger. The archive may live on any
  volume; only the target-side rename must be intra-volume, and it always is.)
- **The crash matrix is a `journal.rs` unit test**, not a use-case `FailPoint`. It
  drives the state machine directly at 10 fine-grained checkpoints — more precise than
  a use-case fault point could be.
- **The journal is stem-keyed** (`<stem>.restore.intent`), not a fixed
  `restore.intent`, so several vaults sharing a directory can't collide.
- **`inspect_backup` takes no `state` arg** (the spec showed one; it's a pure
  read-only file op with nothing to read from the session registry).
- **`BackupPreview` flattens the manifest fields** rather than embedding the infra
  `BackupManifest` type in an application-layer return.
- The **unlocked-target refusal** is enforced in the command + will be e2e-tested in
  5.2c; there is no core-level concept to unit-test (restore is a file op).

## Adversarial-review hardening (before merge)

A dedicated review pass on the recovery path found five real defects at boundaries the
crash matrix didn't cover — all fixed + regression-tested:

- **Cross-restore wedge:** a second restore (or a restore after an un-recovered crash)
  collided with the prior journal + `.old` and locked the vault out of *every* open.
  `restore_vault` now runs `recover_if_pending` first.
- **Path-identity skip → empty vault:** a byte-compare of the journaled vs. opened path
  could falsely skip recovery on Windows (casing / short names) and let `mode=rwc`
  fabricate an empty vault. Removed — the stem+parent-keyed journal already scopes it.
- **Intact-original lockout:** a crash at `VaultAside` *before* the first move plus an
  unverifiable staged snapshot refused to open a vault whose original was sitting
  untouched. Recovery now keeps it.
- **Stranded new blobs:** rolling back over a target that had no blob dir left the NEW
  blobs beside the OLD vault. Rollback now drops them.
- **Path traversal:** blob member names are validated (`is_safe_blob_name`) so a crafted
  archive can't escape the staging dir (the `tar` crate already refuses `..`; this is
  defense-in-depth).

One lower-severity item is **deferred with a note**: recovery re-verifies the vault
snapshot but not staged blobs — a torn blob reads as `DecryptionFailed` for that one
document (AEAD-sealed, never silent), so per-blob journal digests are a follow-up.

## Tests

`crates/vedge-core/src/infrastructure/backup/journal.rs` (unit): full commit → new +
clean; **crash at every checkpoint** → consistent pair (old for `Staged`, new after);
orphan-staging reap; corrupt-snapshot rollback from `.old`; unrecoverable → `Err` with
no phantom vault; zero-blobs install.

`crates/vedge-core/tests/backup_restore.rs` (+7): the **round-trip proof** (3 logins +
a document → backup → install-from-backup → unlock → decrypt the document); **restore
over an existing vault** (exercises `.old` cleanup + the Windows close-before-rename
path); refusals for tamper / uuid-mismatch / newer-schema / unknown-format (each leaves
the target untouched); an `inspect_backup` preview.

## Hard gate — handed off

The kill-mid-restore smoke (Standards §6): host tests prove the *state machine*; only a
real `taskkill /f` proves *fsync discipline* against a real FS. Each `persist` logs its
journal transition (`tracing::warn`). For each of the 4 states: start a restore of a
large-ish vault → `taskkill /f /im vedge.exe` at that transition → relaunch → open →
assert it opens and `(vault, blobs)` are a consistent pair.
