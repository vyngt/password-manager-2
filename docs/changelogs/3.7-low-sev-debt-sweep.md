## What shipped

### #1 — Palette rows memoized (`command_palette.rs`)
`build_rows` was a plain `Copy` closure that cloned the loaded index and rebuilt a `tag_map: HashMap` on
**every** call — and the view alone reads it ~3× per render (`aria-expanded`, `aria-activedescendant`,
results), plus once per arrow key. Now:
- `PaletteRow` derives `PartialEq` (its fields — `ActionId`, `String`, `EntryTypeDto` — already are).
- A `tag_map` `Memo` rebuilds the id→name map only when the loaded `tags` change.
- The rows are a `Memo<Vec<PaletteRow>>`, recomputing only when an input (query / entries / selection /
  tags / locale) actually changes — not per read. `Copy`, so the view and the keydown handler both read it
  (`rows.get()` / `rows.with(Vec::len)`). Row content is byte-identical — a pure perf refactor. Side benefit:
  the `t_string!` reads now live in the memo, so rows relocalize on a language switch.

### #2 — Palette **Edit** works from any route (`command_palette.rs`)
`ActionId::Edit` only bumped `ui.edit_request`, a pulse observed by `VaultDetail`'s `Effect` — which is
mounted **only on the vault route** and whose `prev`-guard **skips its first run**. Fired from
`/v/generator` etc., the pulse landed before the (re)mounted Effect captured its baseline and was swallowed
(a silent no-op). Fix: navigate to `/v/vault`, then **defer the bump one macrotask** via `set_timeout(0)` so
it fires *after* the microtask flush that mounts the route (same ordering the file already uses for
focus-after-mount). Same-page Edit is unaffected (navigate-to-current is a no-op; the deferred bump is still
caught one tick later).

### #3 — Cached-key name sort (`vault_filters.rs`)
`NameAsc` used `sort_by_key(|e| e.name.to_lowercase())`, re-allocating a lowercased `String` on every
comparison; `Manual`'s tie-break did the same. Both now use `sort_by_cached_key` (the pattern 3.0 set for the
recency arms) — `NameAsc` caches the lowercase once per element, `Manual` uses a `(sort_order, name_lower)`
tuple key (`Ord`, cached once). Stable, same order as before — fewer allocations. Sort fixtures unchanged.

### #6 — Typed document-too-large error kind (core → tauri → app)
The 50 MiB cap was surfaced app-side by `contains("too large")` string-matching. Now a dedicated **unit
variant** `DocumentTooLarge` flows end-to-end:
- new `envelope::kind::DOCUMENT_TOO_LARGE` wire constant (`vedge-ipc`);
- `CommandError::DocumentTooLarge` (`vedge-tauri/error.rs`) — the `From<VaultError>` maps
  `VaultError::DocumentTooLarge { .. }` to it instead of flattening into `Invalid`;
- the path-import short-circuit (`commands/document.rs`) returns the typed variant (drops the `format!`);
- `ApiError::DocumentTooLarge` + its `from_envelope` arm (`vedge-app/api/error.rs`);
- `document_attach.rs` matches `Err(ApiError::DocumentTooLarge)` and shows the localized message.

A **unit** variant (not `{size, limit}`): a struct content would serialize `message` as an object and break
the app's `ErrorEnvelope { message: Option<String> }` decode — and the app owns the localized copy, so it
needs only the *kind*, not the byte counts.
