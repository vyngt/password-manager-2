# Slice 2.2 — Search & Filters (client-side)

**Scope:** `vedge-app` only. **No `vedge-core` / `vedge-ipc` / `vedge-tauri` change** — all query APIs already existed.

Upgrades `VaultPage` from a name+url text filter to a full **client-side** search/filter/sort over the already-decrypted index metadata (`Vec<IndexEntryDto>`) the frontend already holds — no encryption barrier, no per-keystroke IPC. A person can now find entries by name / url / **tag name**, narrow by **type / tag / favorites**, **sort** by name / recently-updated / recently-used, and **view Trash** (read-only), with distinct empty states.

## Added / changed

### app (`vedge-app`)

- **`features/vault/vault_filters.rs`** (new) — the slice's core, split into a pure function + a control component (mirrors 2.1's host-testable `EntryFormData` design):
  - `filter_and_sort(items, &Filters, &tag_names, SortKey) -> Vec<IndexEntryDto>` — **pure, host-tested**. Query is a case-insensitive substring over `name`, `url`, **and each `tag_id`'s resolved name** (`tag_names: HashMap<String,String>` from `list_tags`); the `entry_type` / `tag_id` / `favorites_only` facets AND together. Sort: `NameAsc` (case-insensitive), `RecentlyUpdated` (`updated_at` desc), `RecentlyUsed` (`accessed_at` desc, `None` last). Timestamps are fixed-width RFC-3339 millis-`Z` strings, so a lexical compare is chronological — no date parsing.
  - `Filters` (`query`, `entry_type`, `tag_id`, `favorites_only`) + `SortKey` enum.
  - `VaultFilters` component — the toolbar: `VaultSearch` + type / tag / view(active·trash) / sort `Select`s + a favorites `Toggle`. Each control binds a page-owned `RwSignal`; option lists + labels read locale strings inside reactive closures / `Signal::derive` (owner rule).
- **`pages/v/manage/vault.rs`** — new facet signals (`entry_type`, `tag_id`, `favorites_only`, `sort`, `trashed_view`, `tags`); `refresh` now picks `list_trashed` vs `list_entries` by `trashed_view` and best-effort loads `list_tags`; the mount `Effect` also tracks `trashed_view` so toggling re-fetches. The table is fed by a derived `filter_and_sort` over a **memoized** `tag_id→name` map. A reactive `empty_label` distinguishes *no entries yet* / *no matches* / *empty trash*. The old `matches()` fn + its tests were removed (migrated into `vault_filters.rs`).
- **`features/vault/vault_table.rs`** — two new props: `empty_label: Signal<String>` (replaces the hardcoded `no_items` fallback so the page owns the empty-state wording) and `hide_delete: Signal<bool>` (gates the per-row Delete `IconButton` — the trashed view is read-only in this slice).
- **`locales/{en,vi}/vault.yaml`** — `filter_type`, `filter_tag`, `filter_favorites`, `filter_all_types`, `filter_all_tags`, `view_active`, `view_trash`, `sort_label`, `sort_name`, `sort_updated`, `sort_used`, `empty_none`, `empty_no_matches`, `empty_trash` (both locales, key-aligned); `src/i18n.rs` regenerated.

## Deviations from the spec (see the 2.2 slice tracking note)

1. **Type facet uses a local `filterable_types()` list (9 known variants incl. `Document`)** — the spec suggested `all_types()`, but only `editable_types()` (8, excludes Document) exists in `entry_form.rs`; a Document-inclusive facet needs the full set, so a small local array was added rather than repurposing the editable list.
2. **Active/Trash is a two-option `Select`** (`view_active` / `view_trash`), not a bare `Toggle` — it renders both spec i18n labels cleanly and composes with the other facet dropdowns.
3. **`VaultTable` empty-state is threaded as an `empty_label` prop**, and the *no entries / no matches / empty trash* choice is computed in the page (the component only knows the filtered list is empty, not *why*).
