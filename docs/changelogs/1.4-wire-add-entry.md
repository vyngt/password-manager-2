# Slice 1.4 — Wire Add-Entry to Backend

**Scope:** `vedge-app` only. Closes the `TODO(UI adaptation)` in `vault_create_form.rs`.

The "new item" form now **persists a real, encrypted Login entry** through the backend instead of producing a throwaway local `VaultItem`. On submit it reads the active vault path from the `ActiveVault` context (1.3), builds a `PayloadDto::Login`, and calls the already-wired `api::entry::create_entry`. Success closes the form and pings the parent to refresh; errors show inline without losing the typed input.

> The added entry does **not** appear in the on-screen list yet — the list is still the empty legacy stub until slice 1.5. Verify persistence via `list_entries` in devtools / the `entries` table.

## Changed

- **`features/vault/vault_create_form.rs`** — submit rewired:
  - Builds `PayloadDto::Login(LoginPayloadDto { meta: CommonMetaDto { name, entry_type: Login, url, .. }, username, password, .. })` from the form fields (empty URL → `None`) and calls `api::entry::create_entry(&vault_path, &payload).await` inside `spawn_local`.
  - Reads the active vault via `expect_context::<ActiveVault>()`.
  - `on_created` signature changed from `Callback<VaultItem>` → **`Callback<()>`** (a "list changed" ping; the parent re-fetches).
  - Added an inline error line (`--color-danger-text`) and reactive gating of the Save button on `submitting || empty title` to prevent double/empty submits. Password signal is cleared on close (existing `reset_form`).
  - Dropped the local `VaultItem` / `uuid` machinery.
  - Extracted a pure `to_login_payload(...)` helper with host unit tests (field mapping + empty-URL → `None`).
- **`pages/v/manage/vault.rs`** — parent `on_created` is now `Callback<()>` that calls the `load_items` stub as a refresh ping (becomes the real `api::vault::list_entries` fetch in slice 1.5).

## Deviations from the spec (see slice tracking note)

1. Errors surface via an **inline error line**, not a toast — matches the 1.3 pattern; no app-level `ToastProvider` is wired into the running app (Toast lives only in the playground).
2. Payload construction is a pure `to_login_payload` helper (host-tested) rather than inline — thinner component, cheap unit coverage. Behaviour identical.
3. Error copy is an English literal; i18n wiring deferred (consistent with 1.3).
4. The parent's refresh ping calls the existing `load_items` stub; the real list re-fetch lands with slice 1.5 (the spec assigns re-fetch to the parent/1.5).

Error path: with no active vault, Save shows an inline "Could not save…" and keeps the input.
