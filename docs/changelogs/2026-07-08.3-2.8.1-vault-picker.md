# Slice 2.8.1 — Vault Picker at Scale

Redesign the returning-user launch screen into a **two-pane vault picker** — a searchable,
recency-sorted, keyboard-navigable list of the user's vaults on the left, and a focused unlock
panel (master password + 2.8 biometric) on the right — so 10+ vaults stay scannable. Folds in a
small `rename_recent_vault` backend vertical (core → ipc → tauri → app) and fixes two recents
defects surfaced in review. Spec: `.../Specs/2.8.1 - Vault Picker at Scale`. Mockup:
`2.8.1 - Vault Picker`.

## The two recents fixes

- **A freshly created vault now lands at the top.** `add_recent_vault` stored `last_opened: None`,
  so a new vault sank to the bottom. It now stamps `last_opened = now()` (server-side) — adding a
  vault means it was just created or just opened.
- **Recency sort actually works now.** The premise in the spec (that `list()` ordered
  `sort_order ASC, last_opened DESC`) was inaccurate: **the SQLite `list()` query had no `ORDER BY`
  at all**, while `touch_on_unlock` maintained a `sort_order` renumber dance that `list()` then
  ignored — two mechanisms, neither wired to display. Fixed to a **single recency key**: `list()`
  orders by `last_opened DESC` (RFC3339-UTC text → lexical DESC == chronological; SQLite sorts NULL
  last under DESC, so never-opened rows sink), and `touch_on_unlock` is simplified to a plain
  timestamp bump. The `sort_order` column stays (reserved for a future manual-pin) but no longer
  drives ordering.

## What shipped

### Core — `vedge-core`

- **`rename_recent_vault(repo, id, display_name)`** (`recent_vault_ops.rs`) — trims and rejects an
  empty name (`InvalidSettingValue`), then `get` → set → `upsert`. No new repo method (the port
  already has `get` + `upsert`). Re-exported from `use_cases.rs` and the crate root.
- **`add_recent_vault`** now stamps `last_opened = Some(now())` (fix #1).
- **`touch_on_unlock`** simplified to `repo.touch_last_opened(id, now())` — recency is the sole
  ordering key (fix #2, part).
- **`SqliteRecentVaultRepository::list()`** now `order_by_desc(Column::LastOpened)` (fix #2, part).

### Boundary — `vedge-tauri` / `vedge-app`

- `rename_recent_vault(id, display_name)` command (`commands/recent.rs`, registered in
  `generate_handler!`) + `api::recent::rename_recent_vault` wrapper (`call_void`). No new IPC DTO —
  the args are primitives. `RecentVaultStatusDto` keeps its `#[serde(flatten)]` (the wasm guard test
  passes and the live screen already decodes it — the 1.6 carry-over is cleared by verification).

### App — `vedge-app`

- **Pure `filter_sort_recents(items, query)`** (`recents_filter.rs`, host-tested) — case-insensitive
  name/path substring filter (empty ⇒ all), then sort **existing-first → `last_opened` desc (None
  last) → name A→Z**. Mirrors 2.2's `filter_and_sort` shape.
- **Two-pane picker** (retires the `VaultCard` stack):
  - `vault_launch.rs` — the `VaultLaunch` orchestrator: owns the recents state + all signals /
    closures, derives the visible list, renders a centered empty state (no vaults) or a `Spinner`
    (loading), and threads callbacks to the two panes. Errors surface as **`Danger` toasts**.
  - `vault_list.rs` — `VaultList` (left): "Your vaults" header, search box, keyboard nav
    (↑/↓/Enter over the filtered list, mirroring the 2.3 palette), inline **rename** (hover pencil →
    editable field, Enter/blur commits, Escape cancels), and dimmed **missing** rows with
    Remove/Locate.
  - `vault_unlock_panel.rs` — `VaultUnlockPanel` (right): name/path header, master-password field
    (with reveal/hide — fixes the old dev-assertion), Unlock, and the 2.8 biometric button when the
    vault is enrolled.
- **Rename** wires the new command; **Locate** re-points a moved vault (pick the file → re-add
  preserving the display name → drop the stale row; a non-vault pick errors and keeps the row).
- i18n: `your_vaults`, `search_vaults`, `no_match`, `vault_missing`, `vault_remove`, `vault_locate`,
  `vault_rename`, `vault_rename_placeholder`, `open_file`, `new_vault`, `no_vaults_title`,
  `no_vaults_body`, `err_rename`, `dismiss` — identical keysets in `en` + `vi`. Labels say
  "Your vaults", never "recent".

## Deviations (recorded in the tracking note)

1. **Spec-vs-reality correction** — the spec's premise that `list()` sorted
   `sort_order ASC, last_opened DESC` was inaccurate (no `ORDER BY` existed). The fix adopts a single
   recency key (`last_opened DESC`) and retires the `sort_order` renumber dance rather than running
   two ordering mechanisms.
2. **Errors are `Danger` toasts** (via the already-mounted `use_toast`), not an inline error signal —
   per the spec's acceptance criterion. Adds a `dismiss` i18n key.
3. **"Locate" = re-point** (add-new + remove-stale, preserving the display name) — reuses existing
   verticals; no path-update command was added.
4. **`RecentVaultStatusDto` keeps `#[serde(flatten)]`** — kept by verification (the wasm guard test
   passes; the live screen already decodes it), with de-flatten as the documented fallback if
   `cargo tauri dev` shows flakiness.
5. **Rows render via `enumerate().map().collect_view()`** (the proven 2.3 palette pattern for
   index-based keyboard highlight), not a keyed `<For>`; the list rebuilds on filter change only.
6. **One extra i18n key beyond the spec's list** (`no_match`) for the "no search results" state.

## Deferred

switching inside `/v`; relative-time recency labels ("2m ago" — the row shows the `YYYY-MM-DD` date).
