# 5.3.1b — The Table Migration (2026-07-16)

The second of slice 5.3.1's four PRs (a: `DataTable` hardened · **b: the migration** · c: selection + action bar
· d: filters, relocation & export scope). The hand-rolled entries `<table>` — the **primary table in the
product**, with no `role="grid"`, no `aria-sort`, no keyboard navigation — now renders through the design-system
`DataTable`, clearing the **Gate 1.0 a11y blocker** that sat unclaimed for two phases.

**Behaviorally a no-op.** Every feature survives — row-click→detail, favourite toggle, move / delete / restore /
delete-permanently, **drag-reorder** (`SortKey::Manual`), and tag chips. The migration *adds* the a11y machinery
(`role="grid"`, roving `tabindex`, `aria-selected`, full keyboard nav) that was the whole point, but changes no
user capability. It ships **alone**, so if drag-reorder had broken, nothing else in the diff could hide it.

## The `Send + Sync` cell constraint → a view-model

A `DataTable` cell closure is `Arc<dyn Fn(&T) -> CellValue + Send + Sync>`, so it **cannot call `t_string!`**
(that captures the non-`Send` `I18nContext`) nor read app signals — the pattern `health_table`/`audit_table`
already established. So each entry is pre-resolved into a **`VaultRow`** view-model (final localized/formatted
strings + resolved tag chips + the five aria labels) inside a reactive `Signal::derive` that reads
`items` + `tags` + `hide_delete` + i18n. It **re-derives on any of them** — which is exactly what preserves
today's optimistic in-place `items` mutations (favourite/tag/move flips) repainting, the tag chips reacting to a
tag rename, and relocalization on a language switch.

Neither `health` nor `audit` has **per-row interactive controls** — the entries table has five. Rendering them as
`CellValue::View` requires the cell to capture the page's `Callback`s; that is sound because Leptos `Callback` is
`Send + Sync` (as `health_table`'s own `on_row_click` already proves). Favourite + the action cluster keep their
`ev.stop_propagation()` so a control click never opens the detail drawer.

## Preserved: `vault.rs` and the e2e action hooks

`VaultTable`'s **public props are unchanged**, so the `vault.rs` call site is untouched — the swap is entirely
internal. The action-button testids (`row-favorite`, `row-move`, `row-delete`, `row-restore`,
`row-delete-permanent`) live inside cells and are carried verbatim. `on_reorder` maps 1:1 to `DataTable`'s new
`on_row_reorder` hook (from PR a); `reorder_enabled = sort==Manual` passes straight through.

## Drifts & decisions

1. **Two e2e row locators re-pointed** (`entry_row_count`, `open_entry`): the migrated rows carry `data-testid`
   (the entry id, via `DataTable`'s `row_testid`) instead of the bespoke `data-entry-row` / `data-entry-id`.
   `tr[data-testid]` selects exactly the body rows (the header row has none). **Locator updates, not behaviour
   changes** — the scenarios are byte-identical. A consumer-named `row_attr` was rejected: it would need a
   runtime attribute *name*, which Leptos `view!` can't render without unproven `custom_attribute` machinery.
2. **Empty state**: `DataTable`'s built-in empty state (generic icon + `empty_message`) replaces the
   `EmptyState` + `FaInboxSolid`. Same message; asserted nowhere.
3. **Action-cell padding no longer opens the row** (`ColumnType::Action` stop-propagates the whole cell); before,
   only the buttons did. Negligible, untested, arguably better.

## Tests

- 🔴 **Host suite green, UNMODIFIED** — no host test touches `VaultTable` (it's a component); `filter_and_sort` /
  `smart_folders` are pure and untouched by a rendering swap. Host total **unchanged vs 5.3.1a (783)**.
- **e2e**: the row-hook scenarios (`trash` → restore / delete-permanent, `daily_loop` → favourite + row-click)
  stay green with the two re-pointed locators. *(Runs on manual dispatch; verified locally.)*
- 🔴 **Manual smoke — the migration's real net (no drag-reorder e2e exists):** a folder in Custom/Manual order,
  drag a row onto another → order persists + survives refresh; every per-row action still fires; console clean.
