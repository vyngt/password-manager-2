# Slice PG.5a — In-App Help & Onboarding (2026-07-20)

The **engineering half** of the split PG.5 (PG.5b = the written external guide, which screenshots the UI this
slice produces). All native Leptos + the existing i18n — 🔴 **no markdown renderer, no `inner_html`** (the exact
injection path PG.2b closed). One PR, green-per-commit; acceptance for the help/onboarding visuals + the `?`
popover behaviour is a **human visual pass** (the user's).

🟢 **What it could not break — a test proves it:** PG.3's `attack_surface.rs` pins the 8 capability grants + the
exact CSP. Help adds **no `invoke` beyond `about::app_version()`** (already used pre-unlock by `window_panel`,
Rust-side, offline, no capability) and **no network / `fetch`** → both pin tests stay green. PG.1's
`assert_vault_coherent` is untouched — no vault state.

## HelpPopover + the four contextual `?` popovers (C1)

New `features/help_popover.rs` — a `?` `IconButton` that opens a short help sentence in the design-system
`Popover`. A thin composition of two existing primitives (owner-safe: `body`/`label` are `Signal<String>` read in
reactive closures), so it lives in **vedge-app, not vedge-ui** — no new visual primitive/token/CSS, so the DS
playground ceremony (`vedge-ui/CLAUDE.md` step 6) would be out of proportion; promote it later if a second
consumer appears. `Shape::Pill` (there is no `Circle`) makes the small square button round.

Wired at the four genuinely-confusing decision points — each **reuses** an existing framing where a string
already states the fact, and adds one concise **new** key only for the two contrasts no single row draws:

| Point | `?` body |
|---|---|
| Change-password **vs** Re-key (both headings) | **NEW** `settings.help_password_vs_rekey` — *password leaked → change password; file copied → re-key* |
| Recovery Key | reuse `settings.recovery_key_keep_separate` (5.7 keep-separate) |
| Emergency Kit | reuse `unlock.help_ek_a` (the canonical "what is an EK") |
| Secret Key (rotate) | reuse `settings.rotate_keep_old_kit` |
| Snapshot vs backup vs export (snapshots page title) | **NEW** `snapshots.help_three_way` (TIME / SPACE / ROWS — Decision ⑦) |

🔴 The `?` body always **adds** the when-to-use / binding fact that the row's *visible* subtitle doesn't already
show — restating a visible line would be the drift the two-artifact split forbids.

## The pre-unlock launch Help surface + version footer (C2)

The launch screen (`vault_launch.rs`) is app-level and **pre-unlock** — exactly where a locked-out user needs
help. Its root was restructured into a **column**: a `flex-1 min-h-0` centered main area (so the populated
two-pane still fills height — `min-h-0` is load-bearing) above a `shrink-0` footer carrying:

- **`launch-version`** — the app version, from the offline `app_version` command (no capability, no network), the
  same source the titlebar About uses. This is the **launch-screen version deferred from PG.3/PG.4**.
- **`launch-help`** — a Help door opening a `Dialog` (**not a Popover** — immune to the inner-scroll detach below,
  and titled/focus-trapped for multi-sentence answers). A small `HelpTopic` sub-component renders the four
  recovery questions: what is an Emergency Kit, what is a Recovery Kit + why keep it separate (reuses
  `recovery_key_keep_separate`), I forgot my password, I moved my vault file — plus the MIT line and version.

## First-run onboarding welcome (C3) — closes Gate 1.0 §E

The "no vaults yet" empty state became a genuine welcome — **one screen, non-blocking** (Create is right there):
a `welcome_title` + `welcome_tagline` (what VEdge is: local-first, no cloud) and a callout stating the **ONE
unrecoverable-by-design fact** (the Secret Key + Emergency Kit are the only way back in) — set at creation, not
after a lockout, reinforcing the create wizard's step 3 without duplicating its mechanics. The Primary CTA is
relabelled to `unlock.create_first`; **every testid preserved** (`launch-new-vault` → `/onboarding`, `open-backup`
→ the backup dialog) so the new-machine flow keeps its door and the existing onboarding e2e still passes. The
now-orphaned `unlock.no_vaults_title`/`no_vaults_body` were removed (en+vi); `unlock.new_vault` stays (still the
populated picker's "New" label).

## 🔴 Known limitation — the `?` Popover scroll detach (tracked follow-up)

`Popover` binds its reposition/close `scroll` listener to `window` in the bubble phase, so a `?` opened inside a
**Pattern-B inner-scroll Settings panel** (the Credentials tab, `tabs--fill`) neither repositions nor closes on
that panel's scroll — it floats until the next click (which closes it). Mitigated here by keeping every `?` body
one-glance short (`BottomStart`, click-away closes); the launch Help **Dialog is immune** (no inner-scroll
anchor). The robust fix — a capture-phase scroll listener or a `scroll_root` prop on `Popover` — touches a shared
component used by four other menus (date-picker, filters, dropdown, context-menu), so it is deferred to its own
DS follow-up rather than risking those menus in a help/onboarding slice.
