# 5.3b — Import & the Preview (2026-07-16)

The second of slice 5.3's three PRs (5.3a export+format · **5.3b import+preview** · 5.3c tweezers+benchmark),
and the return leg of 5.3a's one-way door: **data can now come back in.** This is the novel security surface
of the slice — real plaintext secrets held in RAM during preview, the **first `ZeroizeOnDrop` in the repo**,
and a WASM boundary that *leads* the egress rule (derivatives only) rather than copying `get_entry`'s
plain-`String` 5.4 debt.

## 🔴 Decision ① — the reverse mapping is hand-written, NOT DRY'd

`domain/export/mapping.rs` gains `export_to_payload` + `common_meta_from_export` + `export_entry_type`, the
mechanical twins of 5.3a's `payload_to_export`, kept in the **same file** so a reviewer reads the two
directions side by side. **The duplication IS the decoupling** — welding the two together would freeze the
at-rest JSON→binary decision by a *file format*. `tests/payload_wire_format.rs` stays green and untouched.

The reverse returns an `ImportedEntry` enum with **three arms**, because `create_entry` is not universal:
`Standard(EntryPayload)` → `create_entry`; `Document` → `import_document` (a blob must be written first under
a fresh DEK); `Unknown(raw)` → a low-level write, because `create_entry`, `EntryPayload::Serialize`, and
`to_encryptable_json` all *refuse* `Unknown` (`entry_payload.rs`).

## 🔴 Decision ③ — `Unknown` round-trips byte-faithfully

An `Unknown` is written back by encrypting its `raw` JSON verbatim (fresh ULID + DEK + nonce, one `Created`
audit — mirroring `create_entry`'s crypto discipline). The one thing touched is `folder_id`: a `CommonMeta`
cross-reference we own and the one that would *orphan* the entry in the index's folder map, so it is remapped
through the batch (or stripped → flat) — the unknown *schema* fields stay byte-for-byte. The round-trip test
uses an `Unknown` with no cross-references, so it is byte-identical end to end.

## 🔴 Decision ⑦ — the preview crosses derivatives only

`vedge-ipc/src/import.rs` defines `ImportPreviewRow` with `has_password: bool` (the 4.2 `has_totp` shape) —
the password renders `•••` and the value **never crosses**. Proven two ways: a host serde test
(`preview_row_carries_no_secret` — no `password`/`totp_secret`/`secret` key in the JSON) and a real
`serde_wasm_bindgen` decode test (`import_preview_row_decodes` in `tests/wire_wasm.rs`). The commit happens
entirely in Rust; the frontend only returns `[{row_id, import: bool}]`.

## 🟢 Decision ④ — folders remap within the batch; tags match-or-create; never a merge

`commit_import` creates picked **folders first**, in dependency order (a small Kahn-style pass so a nested
parent lands before its child; a no-progress pass forces the remainder flat), building a
`HashMap<source_ulid, fresh_EntryId>`; every other entry remaps its `folder_id` through that map. A folder
absent from the picks imports **flat**, and the preview says so (a `Warning` badge). Tags are matched-or-
created by name via the idempotent `create_tag`. **No merge**: importing a "Work" folder into a vault that
already has one makes a **second** one — the rule doing its job, pinned by `import_makes_a_sibling_folder_never_merges`.

## 🔴 The staging session — the first `ZeroizeOnDrop` in the repo

`ImportSession` (`application/vault/use_cases/import_entries.rs`) is `#[derive(Zeroize, ZeroizeOnDrop)]`, held
as a `pub(crate)` field on `VaultSession`. Living on the session means it **inherits all five lock-teardown
paths** (TTL reap, screen-lock, `lock_vault`, `remove_session`, session-replacement) and zeroizes as part of
the existing `VaultSession::Drop` cascade — the spec's "dies with the lock" satisfied structurally, not by a
new hook. The staged secrets are one `Zeroizing<Vec<u8>>` (the serialized bundle) + per-document
`Zeroizing<Vec<u8>>` blobs, capacity-bounded; the derivatives-only preview is `#[zeroize(skip)]`. Structured
secrets are materialized only transiently — at `begin` (to derive the preview) and at `commit` (to write) —
so plaintext structs never outlive a call. `cancel_import` drops the field immediately.

## 🔴 Decision ⑧ — never fake a shred; paste-into-VEdge is the real fix

The import panel offers a **paste-CSV textarea** (RAM only — the bytes never touch the filesystem or the OS
clipboard round-trip), alongside a file picker. This is the honest no-disk path; VEdge never claims a
plaintext file can be securely wiped.

## Decision ② — duplicate detection (advisory, never a merge)

New deps `url` (WHATWG host normalization — drops default ports, keeps subdomain) + `psl` (compile-time
Public Suffix List, IDN/punycode) drive `duplicate_of`: a row sharing an earlier row's normalized host is
flagged, and a base-domain sibling gets a soft "shares the domain X" hint. **The import never auto-merges** —
the user decides. `cargo-deny` accepts both (MIT/Apache-2.0).

## The UI

Settings ▸ **Import** (`features/settings/import_panel.rs`, `api/import.rs`, commands
`begin_import`/`commit_import`/`cancel_import`): choose the source (encrypted `.vedgex` + passphrase, or a
CSV file / pasted text), **Preview**, review the per-row badges (type · name · `•••` · status · duplicate
hint), toggle Import/Skip per row, then **Import selected**. A best-effort report shows imported / skipped /
failed counts.

## Drifts & decisions (from the as-planned spec)

1. **Commit is best-effort per row** (the approved Decision A): a row that fails to write is reported in
   `ImportReport.failed` and skipped, not fatal — consistent with the CSV row-badge model. Folders are
   created first; a child whose folder failed imports flat.
2. **e2e is deferred with a documented note.** No existing e2e navigates the Settings-tab UI (the 5.3a export
   panel has none either), and the file/encrypted round-trip needs native dialogs that WebDriver cannot
   drive. The **paste-CSV preview/skip** flow *is* automatable and is the recommended fast-follow; the slice's
   correctness is proven at the **integration level** (`tests/import_entries.rs` — a full vault round-trip,
   stronger than an invoke-driven e2e). This matches 5.3a's deferral rationale.
3. **The `Unknown` import remaps only `folder_id`** (the orphaning reference); other cross-references in the
   `raw` are preserved byte-faithfully. A dangling source tag id is harmless (it simply does not resolve).
4. **New `VaultError::ImportNotStarted`** — a state guard for `commit`/`cancel` with no `begin` (maps to
   `CommandError::Invalid`; the GUI always begins before committing).
5. **`begin_import` owns the session-field lifecycle** (stash → return preview; `commit` takes it back;
   `cancel` drops it), because `VaultSession.import` is `pub(crate)` and the shell cannot touch it directly.
6. **`ImportSession` derives `ZeroizeOnDrop` genuinely** by staging the bundle as serialized bytes rather than
   structured `ExportEntry`s (which hold `secrecy::SecretString`, itself not `Zeroize`). The blob tuples are
   `#[zeroize(skip)]` and self-zeroize via their inner `Zeroizing`.
