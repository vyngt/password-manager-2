# Slice PG.2b — Attack-Surface Reduction (2026-07-20)

The second of two PRs for **PG.2**. 5.4 + 5.4.1 spent two slices sealing the *front* door — no decrypted
secret crosses into WASM — while the *side* door stood open: the renderer held `shell:allow-execute`, the whole
`fs:*` family and `http:default`, with `"csp": null` and `"withGlobalTauri": true` removing any containment,
from an uncurated `tauri migrate` capability set (`migrated.json` — *"permissions that were migrated from v1"*,
with duplicate entries). Latent, not a live exploit (Leptos escapes by default, only local assets load, no user
data is rendered as HTML) — but zero defence-in-depth, and Phase 7's markdown editor would introduce exactly
that vector. Lands on 2a's gates (release-check + e2e-in-PR + the CSP-aware `assert_console_clean`).

## Dependencies — updated within requirements, then pruned, then frozen

Two independent shrinks, both leaving `cargo deny` clean:

- **`cargo update`** (within existing requirements — no `"2"`→`"3"` edits): 207 packages to latest
  semver-compatible versions, graph **973 → 923** (newer transitive deps dropped stale duplicates). Done
  *first*, because Tauri minor bumps can change permission behaviour and this slice IS the capability audit.
- **Plugin prune** (below): **923 → 878**. Net for the slice: **973 → 878 packages** — the frozen set for
  Gate 1.0 §B.

## Capabilities — two uncurated files → one curated set

`capabilities/migrated.json` (≈80 grants) + `capabilities/desktop.json` (a second, overlapping file — both
auto-loaded) collapse into one `capabilities/default.json`. The renderer now holds **8** grants, each proven
used by a frontend grep:

```
core:default
core:window:allow-{minimize, maximize, unmaximize, close, start-dragging}   # the custom titlebar
dialog:allow-{open, save}                                                    # the one frontend plugin
```

🔴 **Everything else dropped** — proven unused by the frontend (the "prove absence" discipline applied to
permissions): the whole `fs:*` family, `http:default`, `shell:allow-execute`/`allow-open`, `clipboard-manager:*`,
`os:*`, `global-shortcut:*`, `notification:default`, `process:*`, `core:webview:allow-print`,
`core:app:allow-app-{show,hide}`, ~35 unused `core:window:*`, and the duplicate entries. VEdge's thick-core
architecture does all of this Rust-side, which needs no frontend capability: file I/O in the core, HIBP via
`reqwest`, secret copy via a `copy_text` command (`arboard`), the palette a DOM keydown, an entry URL a plain
`<a target=_blank>`. **`allow-start-dragging` kept** — the titlebar drags via `data-tauri-drag-region`, which
Tauri intercepts natively under that permission.

🟢 `core:window:allow-set-content-protected` was dropped (unused). Screen-capture blocking is a real feature
but a Rust-side behaviour change that conflicts with PG.5's screenshots — deferred, not bolted on here.

## Plugins — drop the dead deps + registrations

Seven plugins were registered but used by neither the frontend nor Rust: **shell, notification, process, fs,
clipboard-manager, os, global-shortcut** (the last registered with zero shortcuts). Their `Cargo.toml` deps and
`lib.rs` `.plugin()` registrations are removed (−45 packages).

- **`http` — dep kept, registration removed.** `tauri-plugin-http` re-exports the `reqwest` HIBP uses
  (`breach/hibp.rs`), so the dependency stays; but `.plugin(tauri_plugin_http::init())` is gone, closing the
  frontend's arbitrary-HTTP IPC primitive while HIBP keeps compiling (a library re-export needs no plugin
  registration).
- **Kept:** `dialog` (the one frontend plugin), `single-instance` (its registration *is* the single-instance
  guard). `tauri-build`'s capability validation confirms `default.json` references only registered plugins.

## CSP — a real policy, and the inline-script blocker resolved

`app.security.csp` was `null` (disabled). Now the code-tailored policy:

```
default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline';
img-src 'self'; font-src 'self'; connect-src 'self' ipc: http://ipc.localhost;
object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'none'
```

- `'wasm-unsafe-eval'` — Leptos/WASM will not boot without it (never paired with `unsafe-eval`, which overrides
  it). `style-src 'unsafe-inline'` — Leptos `style:` bindings compile to inline style *attributes*. `img-src
  'self'` — QR is inline `<svg>`, not `data:`; and 🟢 it **blocks the remote-image beacon** an `Avatar` `src`
  could carry (a tracking vector in a local-first manager — safe, remote avatar src is playground-only).
  `connect-src … ipc:` covers Tauri v2 IPC (incl. 5.8's re-key `Channel`); HIBP is Rust-side.
- 🔴 **The one blocker — the inline `<script>` in `index.html` (the e2e console-clean seam) — moved to an
  external `console-guard.js`** (Trunk `copy-file` + a classic `<script src>` before the deferred wasm module),
  so `script-src 'self'` covers it without an `'unsafe-inline'` concession. The seam ships (documented inert,
  captures boot faults) — the same "keep the dev seam" call as `/playground`, decided deliberately.
- Dev is unaffected: `cargo tauri dev` loads the external `devUrl` (Trunk server), so the production CSP does
  not bite live-reload. The authoritative test is `mise e2e` (built with `custom-protocol` → the production
  `tauri://` CSP path).

## `withGlobalTauri` — decided: kept `true`

🔴 The evidence made this a keep, not a flip: **100% of the frontend's Tauri IPC flows through
`window.__TAURI__.*`** (`core.invoke`, `core.Channel`, `window.*`, `dialog.*`) — there are zero `@tauri-apps/*`
JS imports and zero `invoke("plugin:…")` strings. Turning it off breaks the entire frontend, not just 5.8's
`Channel`. **The real containment is the curated capability set + the CSP** — which bound what the exposed API
can actually *do* — not this flag.

## 🔴 The 2a e2e gate earned its keep — it caught a real CSP interaction

The full e2e run (all 34 scenarios boot + operate cleanly under the CSP) flagged exactly one failure:
`snapshots::revert_corrupt_vault_from_picker`. Bisected to the CSP (it passed with `csp: null`, failed with
the policy). Root cause: that scenario is the **only** one that used `driver().refresh()` — a raw webview
reload — to force the picker to re-probe a corrupted vault, and a webview reload does not survive the
production CSP.

🟢 **The CSP is correct; the test was exercising a non-real path.** The frontend never reloads its own webview
(`refresh_registry` re-probes on *mount*, i.e. on app launch), and a release build disables F5 — so a corrupt
vault is detected on the **next app launch**, never via an in-place reload. The fix mirrors reality: the test
now **relaunches** the app (`session.close()` → `Session::launch`, exactly `daily_loop`'s restart idiom)
instead of reloading the webview. The H0 DoD (a corrupted `.vdb` is survivable via Restore-from-picker) is
unchanged and still fully asserted — only the re-probe *trigger* moved from a synthetic reload to a faithful
restart. *(This is the 2a e2e gate working as designed: a change that breaks silently, surfaced by a test.)*
The Restore-action wait was also widened 25 s → 60 s: a relaunch is a full cold app boot + a fresh registry
re-probe (opening every vault to check status), far heavier than the old lightweight reload, and under
full-suite load that cold path can exceed the reload-era 25 s.

## Verification

`mise ci` · `mise release-check` · `mise wasm-link` (builds the new `index.html` + `console-guard.js`) ·
`mise audit` (clean on the 878-package set) · **`mise e2e`** — the production-CSP proof: the app boots under
the CSP, the external console guard loads, dialogs open, window controls + titlebar drag work, and the
CSP-aware `assert_console_clean` (2a) reports no violations across all scenarios. PG.1's
`assert_vault_coherent` untouched — no vault-state changes.
