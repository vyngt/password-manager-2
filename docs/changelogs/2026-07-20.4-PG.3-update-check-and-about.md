# Slice PG.3 — Update Check & About (2026-07-20)

The third **Pre-Gate Hardening** slice. One new surface — **Settings ▸ About** — carrying four things in a
single visit: the app **version** (`1.0.0`), a **manual update check** (opt-in auto, never auto-install),
VEdge's **MIT** licence, and the **third-party attribution** MIT/Apache-2.0 require when distributing. Discharges
Gate 1.0 §D's licence + attribution + manual-update items. One PR, five green-per-commit commits.

## 🔴 The load-bearing constraint — the first test of whether PG.2b held

PG.2b removed the frontend's `http:default` capability *and* the `tauri_plugin_http` registration, and set a
CSP whose `connect-src` is `'self' ipc: http://ipc.localhost` (no remote origins). The obvious implementation —
`fetch()` from the frontend — would force re-adding the HTTP capability **and** loosening `connect-src` to reach
GitHub, undoing PG.2b in the very next slice.

**→ The update check is a Rust command using `tauri_plugin_http::reqwest`, exactly as `breach/hibp.rs` already
does** — a library re-export needs no plugin registration. So the frontend makes no network request at all.

🟢 **This gives a mechanically checkable acceptance criterion, not a principle:**

> `capabilities/default.json` and `app.security.csp` are **byte-identical** before and after this slice.

**Made mechanical, not reviewed** — `crates/vedge-tauri/src/attack_surface.rs` pins the exact 8 capability
grants and the exact CSP string (read from the two files); if a future slice moves either, the test fails loudly
and the pin has to be updated *out loud* (the "remove the possibility" discipline of 5.4.1's guard, 5.8's
no-`..` match). Both pins pass — neither moved.

## MIT licence (C1)

Gate 1.0 §D's decision (MIT alone — the `MIT OR Apache-2.0` dual convention serves libraries; VEdge is an app),
applied by the same workspace-inherit mechanism the `1.0.0` version pin uses: root `LICENSE` (`Copyright (c) 2026
VyNT`), `[workspace.package] license = "MIT"` + `license.workspace = true` in **all eight** crates (`cargo
metadata` confirms all report MIT). `deny.toml`'s stale "own crates set no license field" note corrected;
`cargo deny check licenses` stays clean.

## Third-party attribution (C2)

🔴 `cargo deny check licenses` answers *"are these licences acceptable?"*; this answers the **distribution
obligation** it does not — *"have we reproduced the notices those licences require?"* (MIT: the copyright notice
in all copies; Apache-2.0 §4: the licence + NOTICE).

- **`cargo-about`** (same authors as cargo-deny, build-graph aware). `about.toml`'s `accepted` mirrors deny.toml's
  14-SPDX allowlist; `targets` = `x86_64-pc-windows-msvc` + `wasm32-unknown-unknown` so the graph covers **both**
  the native shell and the WASM frontend (the shipped set); build- and dev-deps ignored.
- Two Handlebars templates: a **structured JSON** (SPDX id + crate name/version — *no* licence text, so the
  fields are escape-safe under cargo-about's HTML-escaping) that the About tab renders natively, and a
  full-text `THIRD-PARTY-NOTICES.txt` (triple-brace, unescaped).
  🔴 The text template needed `{{{ }}}` — cargo-about HTML-escapes `{{ }}`, which turned `"` into `&quot;` in the
  licence bodies.
- **`mise about`** regenerates both committed artifacts; **`mise setup`** installs `cargo-about --features cli`
  (the CLI needs the `cli` feature — a plain `cargo install cargo-about` builds a library-only binary). Committed
  (not build-time) so they are reviewable in a diff and reproducible without the tool. 227 licence groups / 543
  crate refs; the About tab merges them by SPDX id.
- `bundle.resources` ships `THIRD-PARTY-NOTICES.txt` with the installed app. (bundle.resources is neither
  `capabilities/default.json` nor the CSP → ① holds.)

## Version + update-check commands (C3)

- `semver = "1"` on `vedge-tauri` — already in the lock (transitive), so it adds **zero** packages; the frozen
  878 set is unchanged (Cargo.lock gains only the dependency edge).
- `vedge-ipc`: `UpdateCheckDto` + `UpdateStatus { UpToDate, UpdateAvailable, Unknown }`. **Failure is a status,
  not an `Err`** — so the manual caller shows an inline message and the auto caller stays silent without either
  branching on a result.
- `commands/update.rs`:
  - `app_version(AppHandle)` → `app.package_info().version` (the value the *installer* carries, not `env!`).
  - `check_for_update(AppHandle)` → `GET https://api.github.com/repos/vyngt/vedge/releases/latest` (the slug
    behind a single `const GITHUB_RELEASES_REPO`; `/releases/latest` excludes pre-releases), UA `VEdge/{ver}`,
    10 s timeout. A **404** (no release published yet) reads as up-to-date, not a failure.
  - A pure `compare()` — strip a leading `v`, **semver** compare (`1.10.0 > 1.9.0`, false lexicographically), and
    🔴 a build **ahead** of the newest tag (a dev build off `develop`) reads UpToDate — **never a downgrade**. 6
    unit tests: equal / newer / ahead / v-prefix / semver-ordering / malformed.

## The About tab (C4)

The sixth Settings tab (`Security · Credentials · Appearance · Maintenance · Backup · About`):

- **Version** — `api::about::app_version()` on mount (offline, no network).
- **Manual "Check for updates"** — always available (opt-in governs only the *background* check); an **inline,
  dismissible** result (up-to-date / available + a Download link / "couldn't check") — never a modal (④). The
  Download link is the same `<a target="_blank" rel="noreferrer">` primitive the entry URL uses, so it needs no
  shell capability.
- **Auto-check toggle** — `SecurityPrefs.update_check_enabled`, `#[serde(default)]` → default **OFF** (mirrors
  `breach_check_enabled`); gated behind `SecurityPrefsLoaded` so a pre-load toggle can't save over the persisted
  prefs.
- **Licence** — MIT + copyright, native.
- **Third-party notices** — `include_str!` the committed JSON, merge by SPDX id (`BTreeMap`/`BTreeSet` → sorted,
  deduped), render **natively** via `<details>` (no `inner_html` → no CSP change).

**Quiet launch auto-check** (`app.rs`): when opted in, runs **once per launch** and is **silent on failure** — a
shared `UpdateStatusCtx` is written only for a definitive result, so the About tab reflects it with no toast or
badge. `settings.about_*` keys added to en + vi; `i18n.rs` regenerated.

⚠️ About makes **six** Settings tabs — flagged for **PG.4**'s UX sweep, not pre-optimised here.

## The guard + e2e (C5)

- `attack_surface.rs` — the ① pins (above).
- `tests/about.rs` (e2e): opens Settings ▸ About, asserts the version renders as `1.0.0` (the `app_version`
  command end-to-end), the MIT licence shows, and the notices list renders (the committed JSON parses + renders
  natively); then `assert_console_clean` reports **no CSP violation** — the standing proof ① held, since a
  frontend fetch to GitHub would trip `connect-src 'self'` on exactly this surface. The manual button is not
  clicked (no network); the auto-check is off by default.
