# Slice 2.3 — Command Palette & Shortcuts

**Scope:** `vedge-app` + a one-line shared `vedge-ui` `Dialog` CSS tweak (see UX polish). **No `vedge-core` / `vedge-ipc` / `vedge-tauri` change.**

Adds the vault's first **app-wide keyboard layer**: a `Ctrl/⌘-K` command palette that quick-opens entries and runs New / Lock / Edit / Copy, built on a new shared `VaultUiState` context (selection + create-toggle + an edit-request trigger lifted out of `VaultPage`). `VaultUiState` is the reusable surface later slices (2.4 favorites, 2.5 folders) hang commands on.

## Added / changed

### app (`vedge-app`)

- **`features/vault/ui_state.rs`** (new) — `VaultUiState`, a `Copy` struct of `RwSignal`s (`selected_id`, `show_create`, `palette_open`, `edit_request`) mirroring `ActiveVault`. Provided at the `/v` layout, read via `expect_context`.
- **`features/vault/command_palette.rs`** (new) — the `CommandPalette` component on `vedge_ui`'s `Dialog` (Escape + focus-trap + overlay + focus-restore come for free; the search `<input>` is the first focusable, so the Dialog autofocuses it). A flat `PaletteRow` list (`Action { id, label }` | `Entry { id, name }`) is rebuilt reactively from the query, the loaded entry index, and the selection; **actions** are New / Lock plus (with a selection) Edit / Copy-password / Copy-username, filtered by `matches_command`; **entries** are quick-open, filtered by 2.2's `query_matches` (now `pub`) and capped at 50. `↑/↓` navigate (wrapping, with scroll-into-view), `Enter` runs, `Esc` closes; rows are non-focusable `role="option"` so focus stays in the input. A single `Copy` `run_row` dispatcher drives `VaultUiState`/`ActiveVault` (New → create form, Lock → `api::vault::lock` + navigate `/`, Edit → bump `edit_request`, Copy → `api::entry::copy_field`, Entry → select + navigate `/v/vault`). Pure host-tested helpers: `matches_command`, `selection_actions_enabled`, `is_text_entry` (+ the DOM `typing_in_field`).
- **`pages/v/layout.rs`** — `provide_context(VaultUiState::new())` and a `window_event_listener(keydown, …)` for `Ctrl/⌘-K` (accepts `ctrlKey || metaKey`; suppressed while typing in a field via `typing_in_field`, except when the palette is already open — then it closes), removed on unmount via `on_cleanup`. Mounts `<CommandPalette/>`.
- **`pages/v/manage/vault.rs`** — consumes `VaultUiState`: `selected_id` and the create-toggle now come from the context (`ui.selected_id`, `ui.show_create`) instead of local signals; `selected_entry`, `items`, `show_attach`, and the filter signals stay local. Mouse behavior unchanged.
- **`features/vault/vault_detail.rs`** — factors `start_edit`'s reveal-then-seed flow into a `Copy` `reveal_and_edit` (reads `untrack`ed so the observing effect doesn't re-subscribe to `active.path`), and adds an `Effect` on `ui.edit_request` (prev-value guard skips the initial mount / stale bumps; gated by the existing `is_editable`) so the palette's Edit enters edit mode.
- **`features/vault/vault_filters.rs`** — `query_matches` is now `pub` (reused by the palette).
- **`locales/{en,vi}/vault.yaml`** — `palette_placeholder`, `palette_actions`, `palette_entries`, `palette_empty`, `cmd_new_entry`, `cmd_lock`, `cmd_edit`, `cmd_copy_password`, `cmd_copy_username` (both locales, key-aligned); `src/i18n.rs` regenerated.

## Deviations from the spec (see the 2.3 slice tracking note)

1. **Enum-dispatch instead of the spec's literal `Command { run: Callback<()> }`** — rows are an `ActionId`/`Entry` enum dispatched by one `Copy` `run_row`; avoids per-render `Callback` allocation and owner pitfalls while meeting every acceptance criterion. `Entry` carries only `{ id, name }` (not the full `IndexEntryDto`) to keep the enum small.
2. **Selection-dependent actions (Edit/Copy) are hidden, not greyed, when no selection** — standard palette UX (you can't navigate to a disabled row); the pure `selection_actions_enabled` predicate still gates them.
3. **Palette copy has no in-page toast** (`status_msg` is `VaultPage`-local) — the clipboard is still populated (30 s auto-clear); feedback parity comes with 2.9's app-wide toasts.
4. **Edit is bump-only (no navigate)** — it assumes the vault detail is mounted (i.e. you're on `/v/vault` with a selection, the normal flow). A stale bump can't auto-edit a freshly mounted detail (the prev-value guard is intentional).

## Manual smoke (human — `cargo tauri dev`; not runnable headless here)

`Ctrl/⌘-K` opens from any `/v` screen and is suppressed while typing in a field; typing filters actions + entries; `↑/↓`+`Enter` run; `Esc` closes and restores focus; New opens the create form; Lock → launch screen; quick-open opens an entry's detail; with a row selected, Edit enters edit mode and Copy password/username hit the clipboard. Console stays warning-free.

## UX polish (mockup pass — `2.3 - Command Palette.html`)

A follow-up visual pass aligning the palette + shell with the design mockup:

- **Sidebar (`pages/v/layout.rs`)** — now **collapsible**: collapsed = icon rail with hover tooltips (default), expanded = icon + text label (`w-[60px]` ↔ `w-44`, animated), plus a brand header (`Pm` mark + "VEdge"), distinct nav icons (key / gear / lock — Vault & Settings were both a placeholder mark), a teal-tint **active pill** (`bg-primary-muted`/`text-primary`), Lock pinned at the bottom with a separator, and a collapse/expand toggle. New `nav.toggle_sidebar` key (en/vi). Collapsed icon buttons are fixed squares centered via a `flex justify-center` wrapper (the `Tooltip` trigger is a content-width `inline-flex` span, so `w-full` alone couldn't center them).
- **Command palette (`command_palette.rs`)** — added a **search header** (magnifier + `esc` badge), a **hint footer** (`↑↓ / ⏎ / esc / ⌘K`), per-row **type icons** (new shared `entry_view::type_icon`) + action icons, right-aligned **entry type labels**, and a richer **highlight** (accent bar + `⏎`). New `palette_hint_*` keys (en/vi).
- **Dialog background (`vedge-ui/src/styles/dialog.css`)** — `--color-surface-4` → `--color-background` so every dialog reads as the cleanest surface on the scrim (shared, theme-driven).
