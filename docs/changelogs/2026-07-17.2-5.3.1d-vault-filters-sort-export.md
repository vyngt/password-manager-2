# Slice 5.3.1d — Vault filters, header sort, relocation & three-scope export

The **final** PR of slice 5.3.1 (Vault Page & Entry Selection) — this completes the slice. It bundles nine
spec decisions (① ② ③ ⑦ ⑧ ⑨ ⑩ ⑪ ⑫) and was worked as **one PR in three internal commit-loops**
(d1 → d2 → d3), each a full implement → test → self-review → commit cycle on a green checkpoint. Spec:
`.../Phase 5 - Data Safety & Recovery/Specs/5.3.1 - Vault Page & Entry Selection`.

## d1 — the filter/sort model + the persisted `SmartFolder` migration (⑦ ⑧ ⑩ ⑪-logic)

Refactored the model **first**, host-tested, behaviorally a no-op (the old Selects kept working) — so the UI
in d2/d3 built on a locked, proven core.

- **Tags → multi (⑦):** `Filters.tag_id: Option<String>` → `tag_ids: Vec<String>` + `tag_match: TagMatch
  { #[default] Any, All }`. `filter_and_sort`: empty `tag_ids` passes; `Any` = `tag_ids.iter().any(...)`,
  `All` = `.all(...)`; AND-ed with the other facets, unchanged.
- **Directional sort (⑩):** `SortDir { Asc, Desc }`; `SortKey { Name(SortDir), Url(SortDir), Updated(SortDir),
  RecentlyUsed, Custom }` (Custom = the old Manual) with a manual `Default = Name(Asc)`. A new **`Url` sort**
  arm (None sorts as `""`, last on Asc). `SortKey` **drops `Serialize/Deserialize`** — it's transient view
  state now.
- 🔴 **The persisted-format migration (⑧):** a smart folder can't be Custom (⑪), so persistence uses a
  narrower `SavedSort { Name/Url/Updated(SortDir), RecentlyUsed }` (**no `Custom`** — a compile-time
  guarantee). `SavedSort` carries `#[serde(from = "String", into = "String")]` with a **token map** that
  writes `name_asc|…|recently_used` and reads those **plus the legacy tokens** (`"NameAsc"→Name(Asc)`,
  `"RecentlyUpdated"→Updated(Desc)`, `"Manual"→Name(Asc)`, unknown → `Name(Asc)`) — so it **never fails to
  deserialize**, where a bare-`#[serde(default)]` would have errored on the present-but-unparseable
  `"Manual"`. `SmartFolder` keeps the legacy `tag_id` as a read-only `skip_serializing_if` field alongside
  new `tag_ids`/`tag_match`/`sort: SavedSort`; `apply_preset` merges `tag_ids` **or** `[tag_id]` and widens
  `SavedSort → SortKey`.
- **⑪ (logic):** Custom order is a property of a *folder*, so `reorder_enabled = Custom && scope.is_folder()`,
  and a page `Effect` coerces `Custom → Name(Asc)` whenever the scope isn't a folder (self-correcting).

## d2 — the filter popover + header sort UI (② ⑦-UI ⑨ ⑪-UI)

- **Filter popover (②):** a `Filter` button + count `Badge` opens a `Popover` with the facet panel — type
  `Select`, multi-select **tag pills**, an **any/all `SegmentedControl`** on the Tags group, and a favorites
  toggle. A **chips row** (`FilterChips`) renders one removable chip per active facet + **Clear all** (resets
  facets, **not** search) + a `12 of 247 entries` count; the Tags chip states its semantics
  (`Tags: work or personal`, never `Tags: 2`).
- **Sort into headers (⑨):** the sort `Select` is **gone**; `Name` / `Url` / `Updated` column headers are now
  `sortable` and drive `SortKey` (2-state Asc↔Desc cycle, `aria-sort` reflected). `Type` became an **icon in
  the Name cell**; the freed column is a new **`Tags`** column (chips, **not** sortable — cross-tag ordering
  is meaningless). RecentlyUsed / Custom carry no header state — they show a removable **sort-mode chip**, and
  live in the `⋯` menu.
- **⑪ (UI):** the drag handle renders only in Custom+folder; the `⋯` "Custom order" mode is offered only in a
  folder scope.

## d3 — relocation, the New-entry dialog & the three-scope export (① ③ ⑫)

- **Export-scope plumbing (③, d3a):** `ExportEntriesInput` gained `ids: Option<Vec<EntryId>>`; a subset is
  **intersected with the active set** (a stale/absent id is dropped, never exported) via the frozen 5.3
  adapter. Plumbed core → tauri (`entry_ids: Option<Vec<String>>`) → api (`entry_ids: Option<&[String]>`).
- **The three-scope export dialog (③, d3b):** one `ExportDialog` — export the **N selected** / the **N
  matching the filter** / **all N**, each with its live count — resolving the chosen scope to that
  `Option<Vec<EntryId>>`. The format card reuses the Settings copy and states CSV's "logins only, plain text"
  constraint at the moment of choice (⑧). Opened from the selection bar's **Export…** (default Selection) and
  the `⋯` **Export all…** (default All).
- **Import/Export relocation (①, d3c):** **Import…** and **Export all…** now live in the vault `⋯` menu —
  import lives where the entries do. `ImportDialog` is a thin `Dialog` shell around the **shared**
  `ImportPanel` (Settings ▸ Backup keeps its own copy); the panel gained an optional `on_imported` callback so
  the vault list refreshes behind the still-open report on a successful commit.
- **New entry → the edit Dialog (⑫, d3d):** `VaultCreateForm` now hosts `EntryFormBody` in the **same roomy
  `Dialog size=Lg`** shell as edit — multi-field types (Identity/SSH/Card) get the full-width surface instead
  of the squeezed inline panel. The Dialog owns its visibility (`open=show`), so it mounts unconditionally;
  every close path (Cancel / scrim / Escape / save-success) routes through `do_cancel`, which resets the form,
  so it's fresh on each open.

## Decisions / deviations

- **One PR, three commit-loops** (not three PRs) — the incremental safety of separate checkpoints without the
  review overhead of separate PRs.
- **`SavedSort` is a serde token map, not a `#[serde(rename)]` enum** — only a `from`/`into` String round-trip
  can absorb the *legacy* unit-variant tokens (esp. the now-illegal `"Manual"`) without a deserialize error.
- **The old `VaultFilters` Selects were transitional, then replaced** — d1 minimally adapted them so the app
  never broke between loops; d2 removed them wholesale (the Filter popover + header sort).
- **`ImportPanel` is reused, not forked** — the vault Import… dialog and Settings ▸ Backup render the same
  component; only the new optional `on_imported` callback differs.
- **`export_selected` stays integration-level** — the native save dialog isn't WebDriver-automatable (the
  5.3a/b precedent); the id-subset intersection is proven by a core integration test instead.
