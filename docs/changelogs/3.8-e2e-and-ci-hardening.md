# Slice 3.8 — e2e + CI Hardening

Turns the 2.9.2 daily-loop from a single locale-coupled, Argon2-dominated local `#[ignore]` test into a
**locale-independent, fast, CI-enforceable** suite extended over the Phase-3 features, and stands up the
project's **first CI** (GitHub Actions **and** a local Dockerised Jenkins). Spec:
`.../Phase 3 - Password Generator/Specs/3.8 - e2e and CI Hardening`.

## What shipped

### 1. `data-testid` sweep — the suite is now locale-independent
- ~32 semantic `data-testid` attributes across the daily-loop touch points. The enabling technique:
  Leptos 0.8 spreads `attr:data-testid="…"` from a call site onto a single-root `vedge-ui` component
  (`Button`/`IconButton`/`SidebarItem`) — **no component changes, no wrappers**. Raw `<button>`/`<div>` sites
  get a plain `data-testid`; the ack checkbox's wrapper is tagged (js-click resolves the inner input). The
  `vedge-ui` `Select` gained a `data-value` on each option (mirrors `SegmentedControl`) so the type picker's
  "Note" option is selectable by value, not label.
- Harness migrated to a `by_testid` / `click_testid` / `js_click_testid` family; the English `mod ui` block
  is **retired**. Inputs keep their DOM `id`s (`ef-*`, `vault-search`, …) used via `fill_id`; structural
  hooks (`tr[data-entry-*]`, `[role='option']`+`[data-value]`, `[role='combobox']`, `div[role='dialog']`) are
  reused. Convention documented in the e2e README.

### 2/3/4. Test-only, release-impossible seams
Each gated on **both** `cfg(debug_assertions)` **and** an env var — two-factor, so it cannot exist in a
release bundle (verified: all five seam items are `#[cfg(debug_assertions)]`-gated; the `not(debug_assertions)`
twins reference nothing debug-only). The harness sets the env in `Session::launch`.
- **Fast-KDF** (`VEDGE_E2E_FAST_KDF`) — new `KdfParams::fast()` (m8/t1/p1, debug-only) + `resolve_kdf_seam` at
  the `create_vault` command. Prod default (`None → argon2id_default`, 256 MiB/t3/p4) untouched. Cuts the
  run's dominant cost.
- **In-memory biometric** (`VEDGE_E2E_BIOMETRIC_MEMORY`) — `resolve_biometric` at the compose site swaps the
  platform authenticator for `MemoryBiometricAuthenticator` (reports available, never prompts).
- **Lock-on-blur hook** — debug-only `test_set_dialog_in_progress` (`api/dialog.rs`, since `DialogGuard` is
  private RAII) exposed to JS as `window.__vedge_test_dialog(on)` (installed by `app.rs`), so the negative
  assertion can fake an open native dialog. (Added `js-sys` as a direct dep — already transitive, no new
  lockfile crate.)

### 5. New scenarios (separate `#[ignore]` tests, so a failure names the feature)
- **generate-into-form (3.3):** Login form → wand → assert `ef-password` populated.
- **generator-history-wipes-on-lock (3.5):** generate → Recent populates → lock → unlock → Recent empty (the
  session-secret security contract, e2e-observable).
- **trash restore/delete/empty (3.6):** trash three → Trash folder → Restore / Delete-permanently (confirm) /
  Empty (confirm) → assert counts.
- **lock-on-blur (2.6/3.8):** persist `lock_on_blur=true` + restart; negative (dialog-in-progress → blur → no
  lock) then positive (blur → locks), via the debug hook.

### 6. First CI (both substrates — user-directed)
- **GitHub Actions = authoritative PR gate.** `ci.yml` runs `mise ci` + `mise audit` on **`pull_request` to
  develop/master + manual dispatch only — no `push`** (fast feature commits burn nothing). `e2e.yml` runs
  `mise e2e` on **dispatch only** with a `runner` input (default `windows-latest`, `self-hosted` option = zero
  GitHub minutes; nightly `schedule` left commented-out). Linux core gate installs the WebKitGTK deps
  (Tauri).
- **Local Jenkins in Docker = off GitHub.** `Jenkinsfile` (one stage per gate step) + `ci/jenkins/` (a
  toolchain-baked controller image + compose + README). Core gate only; e2e-in-Jenkins left as documented
  experimental (needs a Linux app build + WebKitWebDriver + xvfb). Flipped the "e2e in CI not enabled" notes
  in `docs/testing.md` + the e2e README.

## Decisions & deviations

- **Seam gating via env + `cfg(debug_assertions)`** (mirrors the shipped `VEDGE_DATA_DIR` seam), **not** a new
  `test-seams` cargo feature — reuses a reviewed precedent, keeps the `mise e2e` build command unchanged, and
  core has no `[features]` block to extend. `[DRIFT]` vs the spec offering either.
- **CI shipped as both GitHub Actions *and* Jenkins-in-Docker** — an extension of the spec's single "GitHub
  Actions assumed", per the user's request to experience Jenkins while keeping GitHub minutes low. `[DRIFT]`.
- **Biometric e2e *scenario* deferred** (the *seam* is shipped + gated). The enroll flow needs
  Settings-UI testids not in this sweep and a human authoring pass against a live app. `[DRIFT]` — one
  acceptance criterion carried forward.
- **`data-testid` at call sites, not vedge-ui prop changes** — the spread technique means the design-system
  components are untouched.

## Security
The three seams are release-impossible (two-factor gating). Fast-KDF carries *less* over the wire than before
(it only changes the create profile in a debug+env build). No plaintext handling changes.

## Tests (+0 host)
`mise run ci` green — **521 tests** (unchanged; the seams are env-gated wiring, and the e2e crate is
`--exclude`d from `mise test`). The e2e crate compiles (`cargo test -p vedge-e2e --no-run`). No pure helper
warranted a host test.

## Verification
- `mise run ci` (native, Windows/1.96) — fmt-check + clippy `-D warnings` + test + wasm32 — **green, exit 0**.
  Release-impossibility verified by the `#[cfg(debug_assertions)]` gates.

### Actually run (post-ship) — and it earned its keep
Both the e2e and the Jenkins gate were run for real; the exercise found four latent issues (all fixed here):
- **`mise e2e` on Windows: 5/5 green.** `daily_loop` (88 s vs the pre-fast-KDF ~129 s → the seam works) +
  `generate_into_login_form` + `generator_history_wipes_on_lock` + `trash_restore_delete_empty` +
  `lock_on_blur_respects_dialog_guard`. **Bug #1 (found + fixed):** `add_note` opened the first
  `[role=combobox]` — a vault-*toolbar filter* Select — not the create-form type picker (which flipped the
  filter, not the entry type). Fixed by scoping the picker with `data-testid="entry-type-select"`.
- **Jenkins-in-Docker core gate: green.** The image builds, the baked toolchain runs, and a full `mise ci`
  inside the container is green (Linux, pinned rust 1.96). Standing up the **first Linux CI** surfaced three
  more issues the Windows-only local gate never compiled/ran: **Bug #2** a cross-platform test
  (`filename_from_path` hardcoded a `C:\…` path that only backslash-splits on Windows) → `#[cfg(windows)]`;
  **Bug #3** clippy findings in `cfg(not(windows))` biometric/keychain code (`platform_authenticator`
  by-value → cfg-scoped allow; `StubBiometricAuthenticator` doc paragraph) never linted before; **Bug #4**
  clippy version drift (container 1.97 > local 1.96 flagged `iter_mut`→`values_mut`). Fixed the code (clean
  on both 1.96 and 1.97) and **pinned the CI toolchain to 1.96** (Jenkins Dockerfile + GitHub Actions) so CI
  clippy == local clippy.
- **Still a human step:** the Jenkins **web-UI job orchestration** (unlock at `:8080` → create the Pipeline
  job) — a few clicks per `ci/jenkins/README.md`. The GitHub Actions run is unverified until pushed/dispatched
  (config is standard).

## Out of scope
Real biometric / native-dialog automation (manual); making e2e a blocking PR gate; keychain bypass;
e2e-in-Jenkins (Linux app build + WebKitWebDriver); the biometric e2e scenario (deferred, above).
