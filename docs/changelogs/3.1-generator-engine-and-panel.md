# Slice 3.1 — Generator Engine & Panel

The first Phase-3 feature slice: a random-password **generation engine** with *honest* entropy and a
standalone **generator panel** to exercise it. Every later generator slice (3.3 into-form, 3.4 modes,
3.5 bulk/history) builds on the `(secret, entropy_bits)` shape this lands. Spec:
`.../Phase 3 - Password Generator/Specs/3.1 - Generator Engine and Panel`.

## Architecture decision — a shared `vedge-generator` crate

The spec left "shared crate vs core+IPC" open. **Resolved to a new pure crate `vedge-generator`** that
compiles to **both** native and `wasm32`, so the WASM UI calls it with **zero IPC** (instant
regenerate, a meter running the identical engine) and future CLI/server shells reuse the same code.
This satisfies the research note's *one code path* rule literally — the same Rust computes the secret
and its entropy.

The enabling fact: the repo is on the **getrandom 0.4** era, where the browser RNG backend is selected
by the **`wasm_js` crate feature alone** — no RUSTFLAGS / `.cargo/config.toml` cfg (the spec assumed
the 0.3-era `getrandom_backend` flag). The crate declares `rand = "0.10"` plus a wasm-target-gated
`getrandom = { version = "0.4", features = ["wasm_js"] }`; feature-unification lights up the browser
backend. `getrandom 0.4.2` + `rand 0.10.1` were already in `Cargo.lock`, so this adds **zero** new
crate versions and the supply-chain gate is untouched.

## What shipped

### Engine — new `crates/vedge-generator`

- **Stateless API:** `generate_random(&RandomConfig) -> Result<GeneratedSecret, GenError>` and
  `random_entropy_bits(&RandomConfig) -> Result<f64, GenError>`, plus `entropy_band(f64) -> u8`
  (1..=4). `RandomConfig` is all-`Copy` (length + 4 char-class bools + `require_each_selected` +
  `exclude_ambiguous`) so the UI holds it in one signal. `GeneratedSecret.secret` is a
  `Zeroizing<String>` (wiped on drop; intentionally not `Debug`).
- **One code path for entropy:** both public fns compute the reported bits from the same private
  `entropy::bits(length, class_sizes, require_each)` — the meter physically can't disagree with the
  generator. Base `length × log2(A)`; with `require_each` and ≥2 classes, an exact inclusion-exclusion
  correction `+ log2(Σ_{S⊆classes} (-1)^|S| · ((A − Σ_{i∈S} a_i)/A)^length)` (≤16 terms) — an honest
  *reduction*, computed from the effective alphabet **after** ambiguous exclusion.
- **Unbiased sampling:** each character drawn via `rand::seq::IndexedRandom::choose` (rejection-sampled
  index — no `% len` modulo bias) from the OS/browser CSPRNG (`rand::rng()`). `require_each` enforced by
  **reject-and-redraw** the whole string (keeps the draw uniform over the constrained set, so the
  inclusion-exclusion count stays exact); a `MAX_DRAW_ATTEMPTS` guard bounds the loop (unreachable in
  practice — `MIN_LEN=4 ≥` the ≤4 classes). Fixed, documented `SYMBOLS` and `AMBIGUOUS` (`O0oIl1|`)
  constants keep entropy accounting stable.
- **Lint stance:** opts into `[lints] workspace = true`; the entropy module carries a documented
  `#![allow(clippy::float_arithmetic, arithmetic_side_effects, cast_*, suboptimal_flops)]` (bounded
  math — mirrors the `vedge-tauri/src/pdf/emergency_kit.rs` precedent). `#[cfg_attr(test, allow(...))]`
  relaxes the test module.

### Panel — `crates/vedge-app`

- **New `features/generator/generator_panel.rs`** (`GeneratorPanel`) + a thin `GeneratorPage`
  (`pages/v/manage/generator.rs`) at route **`/v/generator`**, reachable from the sidebar. Design-system
  components only (§7): `Slider` (length 4..128), six `Toggle`s (classes + exclude-ambiguous +
  require-each), a monospace `<code>` output with a reveal/mask `IconButton`, `CopyButton`, and a
  Regenerate `IconButton`. Entropy shows as a `PasswordStrengthMeter` (4-band `role="meter"`, entropy
  band labels) + a numeric "N bits" readout.
- **Reactivity:** config in one `RwSignal<RandomConfig>`; entropy is a `Memo` over it (live on every
  edit, even before Regenerate); the secret is a `RwSignal<Zeroizing<String>>` regenerated
  **synchronously** (no `spawn_local`) on click, seeded once at mount. Invalid config (no class) →
  `Err` → helper text + empty meter, no panic. All `t_string!` reads sit in `Signal::derive` / `move ||`
  / event-handler bodies.
- **`vedge-app` deps:** `vedge-generator` (path) + `zeroize`. New `generator` i18n namespace (en + vi,
  matching keys) + `nav.generator`. `mise wasm` extended to isolate-check the generator crate on wasm32.

## Guardrails recorded

- **Copy is a placeholder.** `CopyButton` uses the browser clipboard (`navigator.clipboard.write_text`)
  and its countdown is cosmetic — there is **no OS-clipboard auto-clear or platform no-history/no-cloud
  hardening on this path yet**. Slice **3.2** reroutes it through a hardened native `copy_text`.
- **Do not reuse `features/vault/password_strength.rs::score()` (zxcvbn) for this meter.** Generated-
  secret entropy is charset math; user-entered-password guessability is a separate Phase-4 concern with
  a separate vocabulary (per the research note).
- **DOM/clipboard residual:** the plain `String` that reaches the DOM/clipboard for display/copy is
  outside Rust's zeroize control — documented, per the memory-hygiene note.

## Tests (+8, all in `vedge-generator`)

`entropy_random_matches_formula` (incl. `exclude_ambiguous` shrinking the alphabet),
`generate_respects_length_and_classes` (exact length; only-enabled classes; `require_each` guarantees
≥1 of each), `no_class_selected_errs`, `length_out_of_range_errs`, `sampling_is_unbiased` (seeded RNG,
distribution ≈ uniform — guards modulo-bias regression), `preview_matches_generate` (the one-code-path
guarantee — exact `==`), `require_each_reduces_entropy`, `entropy_band_thresholds`.

## Deviations

- **getrandom 0.4 (feature-only), not the spec's 0.3-era RUSTFLAGS cfg** — simpler and requires no build
  config. Recorded in the tracking note.
- **`require_each` via reject-and-redraw** (the spec's first-listed option) with exact inclusion-
  exclusion entropy — chosen over guaranteed-slots+shuffle so entropy accounting stays exact.
- **Copy left as the browser-clipboard placeholder** the 3.2 spec explicitly anticipates — not wired to
  a native command in this slice.
