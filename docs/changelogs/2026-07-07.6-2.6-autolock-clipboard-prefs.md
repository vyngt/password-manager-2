# Slice 2.6 — Auto-lock & Clipboard Security Prefs

The first real **Settings** content plus the vault's idle-security behavior. One
commit on `feature/2.6-autolock-clipboard-prefs`; one PR. **`vedge-app`-only** —
no `vedge-core` / `vedge-ipc` / `vedge-tauri` change (backend session-TTL and OS
screen-lock detection are deferred per spec).

Spec: `04 Implementation/Phase 2 .../Specs/2.6 - Auto-lock and Clipboard Security
Prefs`. Mockup: `06 - The Design/Mockups/2.6 - Settings Security`.

## What shipped

### Security prefs model + context

- **NEW `features/settings/security_prefs.rs`** — `SecurityPrefs { auto_lock_minutes:
  u32 /*0=off*/, lock_on_blur: bool, clipboard_clear_seconds: u32 }`. Every field is
  `#[serde(default = …)]` (missing key / partial blob → `15 / false / 30`), so it's
  additive and forward/backward compatible. Persisted in the generic `app_settings`
  KV store under one **fixed, app-global** key `security.prefs` (unlike 2.5.3's smart
  folders, which key by vault path — these prefs aren't vault-scoped). `load()` reads +
  parses (default on absent/unreadable); `save()` is a fire-and-forget `set_app_setting`.
  Pure `idle_ms(minutes) -> Option<u64>` (`0 → None`) drives the timer and is
  host-tested. A `SecurityPrefsCtx(RwSignal<SecurityPrefs>)` is **provided at the app
  root** (`app.rs`) and loaded once on start, so it survives lock/unlock and both copy
  sites, the AutoLock hook, and the Settings section all read one live copy.

### Auto-lock

- **NEW `features/vault/auto_lock.rs`** — a render-nothing `AutoLock` mounted in the
  `/v` layout (alive exactly while a vault is open). Reads the prefs reactively via two
  `Memo`s (`auto_lock_minutes`, `lock_on_blur`) so an unrelated edit (the clipboard
  delay) doesn't churn the timer. A **config `Effect`** arms an idle `deadline`
  (`chrono::Utc` ms — avoids the web-sys `Performance` feature) that `mousemove` /
  `keydown` / `click` / `scroll` window listeners push out (writing a non-reactive
  `StoredValue`, so no owner needed), polled by a 1 s `set_interval_with_handle`; on
  expiry it disarms (`deadline = i64::MAX`, killing the async-race double-fire) and
  bumps a `lock_trigger` ticket. If `lock_on_blur`, a window `blur` listener bumps the
  same ticket. A **prev-guarded lock `Effect`** (the `VaultUiState` request-ticket
  pattern) observes the ticket and runs the existing lock path — `api::vault::lock` →
  clear `ActiveVault` → `use_navigate()("/")` (created inside the Effect's owner). Every
  listener + the interval is torn down on config change **and** in `on_cleanup`, so
  re-entering `/v` never stacks handlers (mirrors the existing Ctrl-K listener).

### Settings — sectioned shell + Security section

- **`pages/v/manage/settings.rs`** — replaces the `"Settings"` stub with a **Security |
  Appearance** tab shell (Appearance is a placeholder 2.6.1's Theme Manager fills without
  a rewrite). The Security section renders the mockup: an **Auto-lock** `Select` (Off / 1
  / 5 / 15 / 30 / 60 min), a **Lock on window blur** `Toggle`, and a **Clear clipboard**
  `Select` (15 / 30 / 45 / 60 s), plus a "✓ Saved" line. Each edit updates the context
  signal and `save()`s immediately. `Select` option lists are built inside reactive
  `{move || …}` closures (the `vault_filters` house pattern) so the `t_string!` label
  reads are tracked (no owner-less warning) and relocalize on a language switch.

### Clipboard clear-delay wired to both copy sites

- **`vault.rs` `on_copy`** and **`command_palette.rs` `copy_selected`** now read
  `clipboard_clear_seconds` from the context (untracked, in the handler) and pass
  `Some(secs)` instead of the hardcoded `Some(30)`. The now-misleading `vault.copied`
  string ("…clears in 30s") is genericized to a duration-free "Copied to clipboard"
  (en) / "Đã sao chép vào bảng nhớ tạm" (vi) — the countdown returns with 2.9's toast.

### i18n

- **NEW `locales/{en,vi}/settings.yaml`** (`security`, `appearance`, `appearance_soon`,
  `auto_lock`(+`_desc`/`_off`), `minutes`, `lock_on_blur`(+`_desc`), `clipboard_clear`
  (+`_desc`), `seconds`, `saved`); `"settings"` registered in `build.rs`
  `.add_namespaces([…])` (regenerates `src/i18n.rs`). `vault.copied` genericized in both
  locales.

## Manual smoke (human — `cargo tauri dev`; not runnable headless)

- Set auto-lock to 1 min → idle → the vault locks back to launch; `Off` disables it.
- Toggle lock-on-blur → switch apps → it locks; disabled leaves it open.
- Set clipboard to 15 s → copy a field (row/detail **and** palette) → it clears at 15 s.
- All three prefs persist across an app restart; Settings tabs render per the mockup;
  the console stays warning-free throughout.

## Deferred (per spec)

Backend session-TTL (`vedge-tauri`), OS screen-lock detection, and the full clipboard
"clears in Ns" toast countdown (waits on 2.9's `ToastProvider`).
