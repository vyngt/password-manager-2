# Slice 5.2.0 — Vault Home (the foundational layout refactor)

The foundation the rest of Phase 5's 5.2.x slices sit on. A vault stops being a `.vdb`
file with scattered siblings and becomes **one folder** — `<name>.vedge/` = `vault.vdb` +
`blobs/` + `snapshots/` — and the OS keychain is re-keyed off the intrinsic `vault_uuid`
so a moved/renamed vault still unlocks. 🟢 The `.vbk` archive was **already** this layout
(`manifest.json` + `vault.vdb` + `blobs/`), so the format never moved: **no
`format_version` bump, no archive change, a 5.2a-era `.vbk` still restores.**

Spec: `.../Phase 5 - Data Safety & Recovery/Specs/5.2.0 - Vault Home` (Decisions ①–⑥).

## What shipped

1. **Keychain re-key `vault:{path}` → `secret:{uuid}`.** The `KeychainProvider` Secret-Key
   trio takes a `vault_uuid: &str` (the baseline pair already did); `os.rs` accounts on
   `secret:{uuid}` (mirroring 5.2c's `counter:{uuid}`). 🔴 **Fixes a live bug:** the entry
   used to be keyed on the file path, so *any* move/rename lost it and dumped the user into
   the Emergency Kit. The uuid is a plaintext `vault_config` column, in hand at every call
   site: `create_vault` mints it; `unlock_vault` reads it off the loaded config **before**
   the KDF; post-unlock sites (`recover`, `change_password`, `export_emergency_kit`,
   `biometric::enroll`) read it off `VaultSession::vault_uuid()`.

2. **`VaultId` = the home directory.** `VAULT_FILE`/`BLOBS_DIR`/`SNAPSHOTS_DIR` consts +
   `VaultId::{vault_file,blobs_dir,snapshots_dir}`. **`derive_blob_root` + `BLOB_DIR_SUFFIX`
   deleted — the stem trap dies.** The blob store roots at `home/blobs` and is now
   **fail-closed**: it never synthesizes an empty `blobs/`; a home whose `vault.vdb` exists
   but whose `blobs/` is missing fails loudly (the Retro lesson — an empty dir where
   documents belong is a lie). Only **two** paths open the `.vdb` directly and join
   `vault_file()`: the sqlite factory and `backup/target.rs`. `create_vault` provisions the
   three home members up front.

3. **Restore journal 4 states → 3.** A vault is one directory, so the swap is one directory
   rename: `RestoreState::{Staged, HomeAside, Swapped}`, `SwapPaths` collapsed to
   `home`/`home.old`/staged-home/journal, `-wal`/`-shm` travel *inside* the home. **Every
   5.2b hardening preserved** — write-ahead journaling, `move_if_needed` recover-by-probing,
   `.old` destroyed last, corrupt-staged rollback, `recover_if_pending` at the factory
   chokepoint, and the crash matrix (now 6 checkpoints, at parity coverage). `restore_vault`
   always provisions a complete staged home (`blobs/` + `snapshots/`) so a no-blob backup
   still restores to a valid, fail-closed home.

4. **`recent_vaults`: path → home + a `vault_uuid` column.** The first additive
   `alter_table` in the app DB (`m20260714_090007_add_recent_vault_uuid`, nullable text,
   mirroring the vault-DB `add_vault_uuid`). `RecentVault` gains the field through struct /
   SeaORM model / mapper / upsert. The exists-probe and `add_recent_vault`'s SQLite-header
   check now look at `home/vault.vdb` (a home "exists" when its `vault.vdb` is a readable
   file). *(Population of the uuid from the open flow is deferred to 5.2.2's dedup; the
   column + plumbing are in place.)*

5. **Directory pickers + the dialog-free harness seam.** `OpenDialogOptions` gains a
   `directory` flag (plugin 2.7.0 `open({directory:true})`). The three vault dialogs go
   folder-mode (create's "Choose…", launch's Locate + Open…); the six file dialogs
   (`.vbk`/`.pdf`/documents) stay file-mode. Create composes `<parent>/<name>.vedge` and
   normalizes the typed path to a `.vedge` home (`ensure_vedge_home`); `display_name_from_path`
   strips `.vedge` (and legacy `.vdb`). The e2e text-field seam (`#vault-path`) is unchanged.

6. **Layout migration (crash-safe, cannot strand a vault).** `migrate_vault_layout` +
   the `convert_vault` command + a **Convert** action on legacy-`.vdb` recents rows. It is
   **copy-then-atomic-rename**: the original `.vdb` + sibling blobs stay fully intact until a
   single directory rename commits the home, then the originals are reaped. So a crash
   *before* the commit leaves the old layout working (the `.migrate-tmp` scratch is reaped on
   retry); a crash *after* is finished by a re-run (idempotent). The keychain is re-keyed
   from the legacy `vault:{old_path}` entry to `secret:{uuid}` via a new
   `KeychainProvider::migrate_secret_key` — **store → verify → delete-old**, so a crash mid
   re-key never loses the key. A pre-4.6 vault gets a `vault_uuid` minted first.

## Decisions honored / drifts

- **Copy-based migration (drift from the spec's literal "rename").** Spec §⑤ describes
  renaming the members into `tmp/`; that would move `work.vdb` out from under the original,
  contradicting the spec's own "crash before the commit ⇒ the old layout is untouched"
  guarantee. Copying honors that guarantee (the 🔴 "cannot strand a vault" criterion) at the
  cost of transient double-disk — cheap for a one-shot conversion. Proven by a crash-at-every-
  step host test.
- **Picker self-heal via the manual pickers (drift).** The automatic "probe for `<stem>.vedge/`
  and silently re-point a missing `.vdb` row" is deferred; the directory-picker **Locate** and
  the **Convert** button both re-point a stale row, so a moved/converted vault is always
  recoverable in the UI.
- **e2e `open_old_layout_vault_and_convert` deferred (drift).** Seeding an old-layout *recents
  row* can't go through `add_recent_vault` (it now refuses a non-home `.vdb` path), so the
  scenario needs raw `app.db` seeding — out of proportion here. The migration is covered by
  **5 host tests** (happy path, crash-before-commit, crash-after-commit rerun, moved-home keeps
  its key, pre-4.6 uuid mint). The e2e *fixture sweep* landed (`e2e.vdb` → `e2e.vedge`).
- **Fail-closed blob store (addition).** Beyond the spec: unlock no longer creates an empty
  `blobs/`. A missing companion is a broken vault, surfaced as an error.
- **`recent_vaults.vault_uuid` population deferred to 5.2.2.** The schema + plumbing ship now;
  filling it from the vault config is 5.2.2's dedup concern.
- **🔴 Frozen-surface amendment.** The Iteration Plan froze *"the `.vdb` + sibling
  `.vedge_blobs/` layout"*; this slice deliberately breaks it. The new frozen surface is **the
  vault home** (`<name>.vedge/` = `vault.vdb` + `blobs/` + `snapshots/`). `.vbk` format,
  `magic = "VEDG"`, `schema_version = 1`, the `A3-` string and the at-rest `EntryPayload` JSON
  are all untouched.

## Tests

- `application/vault/use_cases/migrate_vault_layout.rs` (+5) — the migration crash-safety
  matrix + keychain re-key + moved-home invariance + pre-4.6 uuid mint.
- `infrastructure/backup/journal.rs` — the crash matrix ported to the 3-state home swap
  (6 checkpoints), plus corrupt-staged rollback, orphan-staging reap, cross-restore reconcile,
  intact-original-at-`HomeAside`, and rollback-drops-new-blobs.
- `blob/factory.rs` — opens the home's `blobs/`; **fails loudly** on a missing one.
- Keychain re-key threaded through the whole vault test suite (harness seeds under the uuid;
  the two genuine 4.6a-backfill tests clear the uuid themselves). `crypto_keychain.rs` keys on
  uuid strings.
- `recent_vault_ops.rs` / `app_db.rs` — exists-probe + header-check + record now operate on the
  home; `+vault_uuid`.
