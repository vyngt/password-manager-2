# Slice 2.4 — Favorites & Tags UI

**Scope:** one small `vedge-core` vertical (`set_favorite`) threaded through `vedge-ipc` (a
`TagMetaDto` derive) / `vedge-tauri` / `vedge-app`, plus `vedge-app`-only tag UI. Builds the
**write + affordance** side of favorites and tags on top of 2.2's filters (favorites/tag filtering
already shipped) and 2.1's edit form.

Adds a **star toggle** (rows + detail) backed by a new `set_favorite` core use case that never
returns secrets to WASM, plus a **tag manager** (create/rename/delete), **tag chips** (rows +
detail), and a **tag-assignment widget** in the entry form (attach existing + create inline),
all on the already-shipped tag CRUD.

## Added / changed

### core (`vedge-core`)

- **`application/vault/use_cases/set_favorite.rs`** (new) — mirrors `move_entry`'s
  decrypt→mutate→re-encrypt (fresh nonce, version bump, `Unknown`-reject, index refresh, `Updated`
  audit); the sole difference is `payload.meta_mut().is_favorite = favorite` and dropping the
  folder-ref validation. `is_favorite` already lives on `CommonMeta` and is projected by
  `IndexEntry::from_payload`, so no index/domain change was needed. Re-exported from `use_cases.rs`
  + the crate-root prelude.

### shell (`vedge-tauri` / `vedge-ipc`)

- **`commands/entry.rs`** — new `set_favorite(vault_path, entry_id, favorite: bool) -> ()` command
  (mirror of `move_entry`), registered in `lib.rs`'s `generate_handler!`. New `#[cfg(test)]`
  happy-path test (`test_support::unlocked_vault` → create entry → `set_favorite` → assert index).
- **`vedge-ipc/src/tag.rs`** — `TagMetaDto` gains `PartialEq, Eq` (so the app's `tag_id -> meta`
  `Memo` can gate re-runs). No new DTO — `set_favorite`'s args are primitives.

### app (`vedge-app`)

- **`api/entry.rs`** — `set_favorite` wrapper (`call_void`, `favorite: bool`).
- **`features/vault/tag_assign.rs`** (new) — `TagAssign(data)` mounted once in `EntryForm`
  (`col-span-2`), so both create and edit get it. Removable chips over `EntryFormData.tag_ids`, an
  "attach existing" `Select` (`available_tags` = catalog − assigned), and an inline "create tag"
  (`create_tag` → append). Self-loads the tag catalog on mount (no extra `EntryForm` prop). Pure
  host-tested helpers: `toggle_tag`, `available_tags`.
- **`features/vault/tag_manager.rs`** (new) — `TagManager(open, tags, on_changed)` on `vedge_ui`'s
  `Dialog`; create + a `TagManagerRow` child with inline rename (`rename_tag`) and a two-step
  delete confirm (`delete_tag`). Every mutation pings `on_changed` (the page refresh), which
  re-runs `list_tags` and flows the catalog back through the `tags` prop. Reachable via a
  "Manage tags" `TooltipIconButton` in the vault toolbar.
- **`features/vault/vault_table.rs`** — leading **star** `IconButton` (`FaStarSolid`/`FaStarRegular`,
  `stop_propagation` like Delete) + **tag chips** under the name (resolved via a new
  `tags: Signal<HashMap<String, TagMetaDto>>` prop; unresolved ids skipped). The `<For>` key is now
  `(id, is_favorite, updated_at)` so an optimistic favorite flip or a post-edit change repaints the
  row (a keyed `<For>` otherwise keeps stale children).
- **`features/vault/vault_detail.rs`** — header **star** + a read-view **Tags** row (same new props).
- **`pages/v/manage/vault.rs`** — a `tag_lookup` `Memo` (`id -> TagMetaDto`, keeps color) threaded
  to table + detail; an `on_favorite` callback that **optimistically** flips `is_favorite` in
  `items` (no loading-spinner flash) then persists via `set_favorite`, reverting on error; the
  Manage-tags trigger + `<TagManager>` mount (`on_changed` = the existing refresh).
- **`locales/{en,vi}/vault.yaml`** — `favorite`/`unfavorite`, `tags_label`, `tag_add`/`tag_new`/
  `tag_create`/`tag_remove`/`tag_manage`/`tag_manager_title`/`tag_empty`/`tag_rename`/`tag_delete`/
  `tag_delete_confirm`, and `err_favorite`/`err_tag_create`/`err_tag_rename`/`err_tag_delete` (both
  locales, key-aligned); `src/i18n.rs` regenerated.

## Deviations from the spec (see the 2.4 slice tracking note)

1. **Composite `<For>` keys** — `vault_table` keys by `(id, is_favorite, updated_at)` and the tag
   manager list by `(id, name)`, not id alone. A keyed `<For>` caches children per key, so the star
   (optimistic flip) and the chips / renamed tag names wouldn't repaint on an id-only key. The id
   stays the stable identity; the extra fields force a re-render only when content changes.
2. **Optimistic favorite (no full `refresh()`)** — the star flips `items` in place + persists in the
   background (revert on error), avoiding the whole-table `loading` flash a refetch would cause. The
   "Updated" column for a favorited row lags its persisted `updated_at` until the next real refresh.
3. **Tags are name-only** — the create paths set `color: None` (RenameTagDto exposes no color; the
   i18n set has no color key). Chips honor a tag's `color` if present, but there's no color-picker
   UI. Recolor/reorder deferred.
4. **Palette "Toggle favorite" command deferred** (spec marks it optional) — `VaultUiState` remains
   the surface a follow-up can hang it on.
