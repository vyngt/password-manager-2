# Slice 2.4 — Favorites & Tags UI

**Scope:** two small `vedge-core` verticals (`set_favorite`, `set_tags`) threaded through
`vedge-ipc` (a `TagMetaDto` derive) / `vedge-tauri` / `vedge-app`, plus `vedge-app`-only tag UI.
Builds the **write + affordance** side of favorites and tags on top of 2.2's filters
(favorites/tag filtering already shipped) and 2.1's edit form.

Adds a **star toggle** (rows + detail) backed by a new `set_favorite` core use case, a **tag
manager** (create/rename/delete), **tag chips** (rows + detail), and a **tag-assignment widget in
the detail panel** — tagging is decoupled from the edit form and persists through a new `set_tags`
core use case, so it works for **any** entry type (Document included) and neither favorite nor tag
writes ever return secrets to WASM.

## Added / changed

### core (`vedge-core`)

- **`application/vault/use_cases/set_favorite.rs`** + **`set_tags.rs`** (new) — both mirror
  `move_entry`'s decrypt→mutate→re-encrypt (fresh nonce, version bump, `Unknown`-reject, index
  refresh, `Updated` audit); the sole difference is the one mutated field
  (`meta.is_favorite` / `meta.tag_ids`) and dropping the folder-ref validation. Both fields already
  live on `CommonMeta` and are projected by `IndexEntry::from_payload`, so no index/domain change
  was needed. `set_tags` works for every type (Document's blob sidecar is untouched) and returns no
  secrets — that's what lets tagging live outside the edit form. Re-exported from `use_cases.rs` +
  the crate-root prelude.

### shell (`vedge-tauri` / `vedge-ipc`)

- **`commands/entry.rs`** — new `set_favorite(vault_path, entry_id, favorite: bool) -> ()` and
  `set_tags(vault_path, entry_id, tag_ids: Vec<String>) -> ()` commands (mirrors of `move_entry`),
  registered in `lib.rs`'s `generate_handler!`. New `#[cfg(test)]` happy-path test
  (`test_support::unlocked_vault` → create entry → `set_favorite` → assert index).
- **`vedge-ipc/src/tag.rs`** — `TagMetaDto` gains `PartialEq, Eq` (so the app's `tag_id -> meta`
  `Memo` can gate re-runs). No new DTO — the command args are primitives.

### app (`vedge-app`)

- **`api/entry.rs`** — `set_favorite` (`favorite: bool`) and `set_tags` (`tag_ids: &[String]`)
  wrappers (`call_void`).
- **`features/vault/tag_assign.rs`** (new) — `TagAssign(entry_id, initial, catalog, on_tags,
  on_catalog)` mounted in the **detail panel's read view** for every type (Document included), so
  tagging never needs edit mode. Removable chips, an "attach existing" `Select` (`available_tags` =
  catalog − assigned), and inline "create tag" (`create_tag` → attach). Persists through the page's
  `on_tags` (optimistic `items` + `set_tags`); inline create also pings `on_catalog`. Pure
  host-tested helpers: `toggle_tag`, `available_tags`.
- **`features/vault/tag_manager.rs`** (new) — `TagManager(open, tags, on_changed)` on `vedge_ui`'s
  `Dialog`; create + a `TagManagerRow` child with inline rename (`rename_tag`) and a two-step
  delete confirm (`delete_tag`). Every mutation pings `on_changed` (a **catalog-only** reload —
  no entries refetch, no flash). Reachable via a "Manage tags" **text button** in the toolbar (an
  earlier tooltip-icon-button rendered a cramped, wrapped tooltip at the viewport edge).
- **`features/vault/vault_table.rs`** — leading **star** `IconButton` (`FaStarSolid`/`FaStarRegular`,
  `stop_propagation` like Delete) + read-only **tag chips** under the name (resolved via a new
  `tags: Signal<HashMap<String, TagMetaDto>>` prop; unresolved ids skipped). The `<For>` key is now
  `(id, is_favorite, tag_ids, updated_at)` so an optimistic favorite/tag flip or a post-edit change
  repaints the row (a keyed `<For>` otherwise keeps stale children).
- **`features/vault/vault_detail.rs`** — header **star**; the read view mounts `<TagAssign>` (the
  editable tag section, all types) instead of a read-only chips row.
- **`pages/v/manage/vault.rs`** — a `tag_lookup` `Memo` (`id -> TagMetaDto`, keeps color) for row
  chips; an `on_favorite` and an `on_tags` callback that **optimistically** flip `items` in place
  (no loading-spinner flash) then persist via `set_favorite`/`set_tags`, reverting on error; a
  `refresh_tags`/`on_catalog` (catalog-only reload); the Manage-tags trigger + `<TagManager>` mount.
- **`locales/{en,vi}/vault.yaml`** — `favorite`/`unfavorite`, `tags_label`, `tag_add`/`tag_new`/
  `tag_create`/`tag_remove`/`tag_manage`/`tag_manager_title`/`tag_empty`/`tag_rename`/`tag_delete`/
  `tag_delete_confirm`, and `err_favorite`/`err_tag_assign`/`err_tag_create`/`err_tag_rename`/
  `err_tag_delete` (both locales, key-aligned); `src/i18n.rs` regenerated.

## Deviations from the spec (see the 2.4 slice tracking note)

1. **Tagging is decoupled from the edit form** (spec put the assignment widget "in the entry form").
   The widget lives in the **detail read view** and persists through a dedicated `set_tags` core
   command, so it works for **non-editable types (Document)** and never needs the payload-reveal
   edit path. `EntryFormData.tag_ids` stays a carry-through (edits still preserve tags), but there's
   no in-form tag UI — tags are assigned per-entry from the detail.
2. **Composite `<For>` keys** — `vault_table` keys by `(id, is_favorite, tag_ids, updated_at)` and
   the tag manager list by `(id, name)`, not id alone. A keyed `<For>` caches children per key, so
   the star / chips / renamed tag names wouldn't repaint on an id-only key. The id stays the stable
   identity; the extra fields force a re-render only when content changes.
3. **Optimistic favorite + tag writes (no full `refresh()`)** — both flip `items` in place + persist
   in the background (revert on error), avoiding the whole-table `loading` flash a refetch would
   cause. The "Updated" column lags its persisted `updated_at` until the next real refresh.
4. **Tags are name-only** — the create paths set `color: None` (RenameTagDto exposes no color; the
   i18n set has no color key). Chips honor a tag's `color` if present, but there's no color-picker
   UI. Recolor/reorder deferred.
5. **Palette "Toggle favorite" command deferred** (spec marks it optional) — `VaultUiState` remains
   the surface a follow-up can hang it on.

## Manual smoke (human — `cargo tauri dev`; not runnable headless here)

Star a row / detail → persists (`set_favorite`), appears under the Favorites filter, survives
lock/unlock, no full-table flash. Select an entry → the detail's **Tags** section attaches an
existing tag + creates one inline → chips show on the row + detail (no edit mode) — including for a
**Document**. Open **Manage tags** → create / rename / delete (delete is confirmed). Console stays
warning-free.
