# Slice 5.2.1 — Snapshots (the TIME half of Decision ⑦)

This is what "backup & restore" actually means. 5.2 shipped the machinery and drew the
boundary wrong — one verb doing two jobs. 5.2.1 takes the **TIME** half: **snapshot** this
vault locally, cheaply, repeatedly, and **revert** it *in place* — undoably, because a revert
auto-snapshots first. And it makes 5.2's Definition of Done — *"a corrupted `.vdb` is
survivable"* — **true in the product** (finding **H0**): a corrupt vault is now restorable
from the launch screen, by a person, with no debugger.

Spec: `04 Implementation/Phase 5 - Data Safety & Recovery/Specs/5.2.1 - Snapshots` (Decisions
⑧–⑰). Builds on 5.2 (whose journal + `VACUUM INTO` it reuses) and 5.2.0 (the vault-home layout).

## What shipped

### The store (Decisions ⑪/⑫)

- **`infrastructure/snapshot/{store,manifest}`** — a snapshot is a *directory* in the home's
  `snapshots/` store (NOT a `.vbk` tar — Decision ⑨: you cannot patch a tar), described by a
  `manifest.json` written last (the commit marker) and committed by an atomic rename.
- **Content-addressed object pool** `snapshots/objects/b3-<hash>.blob`, keyed on the
  **ciphertext** (Decision ⑫ — convergent encryption rejected; no cross-entry dedup). Dedups
  the same blob across snapshots and nothing more.
- 🔴 **Mark-and-sweep GC, NEVER a refcount** (Decision ⑪): the reachable set is the union of
  every complete snapshot's manifest hashes; everything else is swept. Proven never to delete
  a referenced object, including one referenced only by the oldest snapshot.

### Snapshot + revert (Decisions ⑭/⑮/⑰)

- **`create_snapshot`** — "Snapshot now": `VACUUM INTO` + dedup each blob into the pool; sets
  `last_snapshot_at` (🔴 NOT `last_backup_at` — Decision ⑧); one `BackupCreated` audit row
  (REUSED — no new `AuditAction`). A session-less `write_snapshot` core is shared with the
  pre-restore auto-snapshot.
- **`revert_to_snapshot`** — verify (self-verifying: each object's BLAKE3 == its filename) →
  ⑭ **auto-snapshot** the current vault (`reason: pre-restore`, skipped only if the target is
  unreadable) → journaled swap → reopen + `BackupRestored` + re-baseline (all L1 best-effort).
- 🔴 **§A — `snapshots/` survives the swap** (Decision ⑮). Since 5.2.0 put `snapshots/`
  *inside* the home, the 5.2b whole-home swap would delete the store on every revert.
  `journal::commit_preserving(&[SNAPSHOTS_DIR])` moves it from the `.old` original into the new
  home after the swap-in, with a `SubdirsPreserved` checkpoint, a roll-forward re-drive, and a
  **symmetric reclaim on rollback** so even a torn post-swap vault never deletes the safety net.

### Rewrap on credential change (Decision ⑬)

- **`rewrap_snapshots`**, hooked into `change_password` **AFTER** its own commit (the old KEK
  is kept in `Zeroizing` past the commit). Each snapshot's `vault.vdb` is rewrapped in one
  transaction (unwrap DEK with old KEK, rewrap with new, stamp `verify_hash`). The **object
  pool is never touched** and **snapshot DEKs are never rotated**. A failed rewrap **warns, is
  reported, and never fails the credential change** (L1); the snapshot keeps its old
  credentials and is badged stale.

### Retention + surfaces

- **⑯ opt-in retention** on the existing 4.6a maintenance job: `backup_keep_count` unset ⇒
  keep everything; when set, prune whole snapshot dirs to it — **floored at 3, never the
  newest, never a `pre-restore`, never a stale-credential snapshot** — plus an unconditional
  object sweep.
- **`/v/snapshots` page** (its own page, like `/v/health` — Decision ⑰): Take snapshot · list
  (date · reason · counts · ⚠ stale badge) · Delete · Revert (inline confirm). Decision-⑧
  honesty copy in the subtitle; the word "backed up" appears nowhere.
- 🔴 **H0 — launch-screen restore.** The picker now probes each recent for openability; a
  present-but-corrupt vault renders "⚠ can't be opened" + **Restore**, which reverts it to its
  newest snapshot (no session needed — manifests are plaintext). The Settings-tab restore hack
  ("lock the vault, restore, then navigate") is **deleted** — restore belongs where the vault
  is closed.

### Carried 5.2 findings

- **M1** — `journal::rename_retrying` (10×100 ms on a Windows sharing violation / os error 32).
- **M2** — snapshot + backup `entry_count` counts `all_active()`, not trashed-inclusive.
- **L1** — nothing after a commit point may fail the op (`backup_vault`, revert, rewrap).
- **L3** — dedicated `VaultError` variants (`SnapshotNotFound`, `SnapshotCorrupt`,
  `RollbackNotConfirmed`, …), each mapped to a distinct `CommandError`.

## Decisions & drifts

- 🔴 **Store location** — the spec's `<stem>.vedge_backups/` sibling is superseded by
  `home/snapshots/` (5.2.0 put the store inside the home; `VaultId::snapshots_dir()` already
  reserved it).
- 🔴 **The journal is NOT reused "verbatim"** — §A had to extend it (see above). `.vbk`
  restore keeps the old whole-home behaviour (empty preserve list).
- **Restore refuses an unlocked target** (like `restore_vault`), and the `/v/snapshots` page
  revert locks → reverts → returns to the launch screen. The spec's ⑰ "seamless in-place
  revert" (via `unlock_with_kek`) is **deferred** — the disaster-path acceptance test (H0)
  only needs the refuse-unlocked path, which ships and is verified.
- **Launch-screen restore reverts to the NEWEST snapshot** (one-click disaster recovery)
  rather than a pick dialog; the `/v/snapshots` page offers the full per-snapshot revert.
- **⑥-vs-⑧ cross-slice note (for 5.2.2):** `create_snapshot` emits `BackupCreated`, but ⑧
  forbids a snapshot silencing "you have never backed up this vault." The future health card
  must key off the `last_backup_at` **config column** (written only by `backup_vault`), NOT
  `BackupCreated` audit rows.
- `api::backup::{inspect,restore}` are kept `#[allow(dead_code)]` — backend-complete wrappers
  for 5.2.2's "Open backup" UI (not dead wrappers to delete — the 2.10.1 lesson).
