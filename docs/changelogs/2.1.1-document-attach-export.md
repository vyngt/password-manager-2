# Slice 2.1.1 — Document Attach & Export

**Scope:** `vedge-tauri`, `vedge-app`. Sub-slice of 2.1 (Phase 2). **No `vedge-core` change; no new `vedge-ipc` type.**

Wires the ninth entry type — `Document` (a file with an encrypted blob sidecar, `{stem}.vedge_blobs/{entry_id}.blob`) — into the UI: **attach** a file into the vault and **export** it back to disk. The core `import_document`/`export_document` (+ blob store, 50 MiB cap) already existed but the shipped commands are **bytes-based** (route plaintext through WASM). This slice adds two thin **path-based** commands mirroring `write_emergency_kit_pdf`, so document bytes stay entirely in the backend (file ↔ core ↔ blob) and never cross into the renderer; no temp file. **No in-app open/preview** (deferred).

## Added / changed

### shell (`vedge-tauri`)
- **`commands/document.rs`** — two new commands:
  - `import_document_from_path(vault_path, src_path, meta) -> String` — backend `std::fs` reads the file (stat-guarding size **before** the read so an oversize file is never loaded), derives filename + MIME from the path, then calls core `import_document`.
  - `export_document_to_path(vault_path, entry_id, dest_path) -> ()` — core `export_document` then `std::fs::write` to the dialog-picked path (`Zeroizing<Vec<u8>>` drops at scope end). IO errors map manually to `CommandError::Storage` (there is no `From<std::io::Error>`).
  - Testable helpers factored out of the `#[tauri::command]` wrappers: `filename_from_path`, `mime_from_extension` (small dependency-free extension→MIME table), `read_document_for_import` (stat-guard + read), `import_from_path_into`/`export_to_path_from` (operate on `&mut/&VaultSession`, no Tauri runtime).
  - Both registered in `generate_handler!` (`lib.rs`).
- **`test_support.rs`** (new, `#[cfg(test)] pub(crate)`) — shared session fixture (`state_fixture`, `fast_params`, `unlocked_vault`) lifted out of `state.rs`'s private test module so command tests can build a live session. `state.rs` tests now import it (duplication removed, existing tests unchanged).

### app (`vedge-app`)
- **`api/document.rs`** — `import_document_from_path` / `export_document_to_path` wrappers (mirror `emergency_kit::write_pdf`; `call` / `call_void`). Bytes never cross into WASM.
- **`features/vault/document_attach.rs`** (new) — `DocumentAttach` panel: **Choose file** (`dialog::open`, single file) → confirm a display **name** (prefilled from the filename via the host-tested `file_basename`; Documents aren't editable afterward, so this is the only chance to name it) → `import_document_from_path`. `DocumentTooLarge` (collapses to `Invalid` on the wire) is surfaced as the localized `err_document_too_large`.
- **`pages/v/manage/vault.rs`** — an **Attach document** button beside **New** (each toggle closes the other panel); mounts `<DocumentAttach>`, reusing the existing `on_created`/`refresh`.
- **`features/vault/vault_detail.rs`** — for `Document` entries: reveal metadata once on open via `api::entry::get_entry` (metadata only — the blob stays in the sidecar; audited `Viewed`) to render **file name / file type / size**, plus an **Export** button (`dialog::save` defaulting to the real filename → `export_document_to_path`). Edit stays hidden (Document isn't field-editable).
- **`features/vault/entry_view.rs`** — new host-tested `human_size(u64)` helper for the size row.
- **`locales/{en,vi}/vault.yaml`** — `attach_document`, `attach_title`, `attach_choose_file`, `attach_confirm`, `export`, `document_filename`, `document_type`, `document_size`, `err_document_too_large`, `err_import`, `err_export` (both locales); `src/i18n.rs` regenerated.

## Deviations from the spec (see the 2.1.1 slice tracking note)

1. **`mime_from_extension` lives in the shell**, not app-side — the backend reads the file, so filename/MIME derivation for the stored payload belongs there (tested via `cargo test -p vedge-tauri`). The app-host "filename helper" is `file_basename` (for the name prefill), tested in `document_attach`.
2. **Size-error detection is a message string-match** (`ApiError::Invalid` where message contains "too large") — `DocumentTooLarge` collapses to the generic `Invalid` kind on the wire, so there's no dedicated error kind to match; adding one was out of scope.
3. **Document detail reveals metadata on open** (one `get_entry`, audited `Viewed`) to show file name/type/size per the spec — a view-time (not just export-time) reveal. Exposes no secret bytes (blob stays encrypted in the sidecar).
4. **Added `attach_confirm` i18n key** (the panel's Attach button) beyond the spec's listed keys.
5. Import stat-guards before the read but **after** acquiring the session lock (lock is held microseconds during a reject) — the spec's intent ("don't load a huge file") is met; reject-before-lock wasn't required.
