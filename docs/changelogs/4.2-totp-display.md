# Slice 4.2 — TOTP Display

Lights up TOTP end-to-end and **closes the door on the seed**: the second factor stops sharing a
trust domain with the password. A Login with a TOTP shows a live rotating 6–8-digit code with a
countdown ring; enrol by pasting an `otpauth://` URI or a bare Base32 secret; all generation lives in
Rust behind **one** parameterized code path, and only the ephemeral code crosses to WASM. Spec:
`.../Phase 4 - TOTP & Security Hygiene/Specs/4.2 - TOTP Display`.

## Headline decision — hand-rolled engine, `totp-rs` dropped

Per the reconciled spec + a follow-up call, **both** the `otpauth://` parser *and* the code generator
are hand-rolled. `totp-rs` is removed entirely. RFC 6238 generation is built directly on the crypto
core's existing RustCrypto primitives (`hmac 0.13` + `sha1 0.11` + `sha2 0.11`) + `data-encoding` for
Base32 — ~50 lines whose **sole** correctness gate is the RFC 4226/6238 test vectors (incl. the
Errata-2866 SHA-256/512 seeds and the Errata-5130 last-byte truncation offset). This drops the
OTP-specific wrapper *and* `constant_time_eq` (validation-only — Vedge generates, never verifies),
gives full control of the decoded seed's lifetime in our own `Zeroizing<Vec<u8>>`, and collapses the
duplicate `hmac 0.12`/`sha2 0.10` versions `totp-rs` was pulling.

## What shipped

### `vedge-core` — engine, parser, reveal, door merges
- `domain/vault/totp.rs` (NEW): `TotpAlgorithm`/`TotpParams`/`TotpCode` + `generate(seed, params, now)`
  with an **injected** clock (the countdown physically can't disagree with the code); `TotpUpdate`
  enrolment intent. `TotpCode` is deliberately not `Debug`/`PartialEq` — the code never reaches a log.
- `domain/vault/otpauth.rs` (NEW, zero deps): `parse_totp_input` — an `otpauth://totp/...` URI **or** a
  bare Base32 secret; honors `algorithm`/`digits`/`period` (never coerces), issuer-param-beats-label,
  hand-rolled `%XX` percent-decode; HOTP / `otpauth-migration://` / out-of-range params yield **distinct**
  errors (new `VaultError::{HotpNotSupported, TotpMigrationNotSupported, InvalidTotpParams}`).
- `application/vault/use_cases/reveal_totp.rs` (NEW): decrypt one entry, generate, zeroize, return
  **only** the code. Audited **once per (session, entry)** via a `revealed_totp` set on `VaultSession`
  (dies on lock); period-boundary refreshes are audit-silent; does **not** bump `accessed_at`.
- `copy_field.rs`: deletes the hardcoded `generate_totp` — the `TotpCode` field now calls the shared
  engine with the payload's params + an injected `now` (threaded from the command boundary; also into
  `copy_history_field`). Copy + reveal are the same code path (`copy_and_reveal_share_engine`).
- `update_entry.rs`: `UpdateEntryInput` gains a `TotpUpdate`. **The door's merge:** since the seed no
  longer crosses to WASM, `Unchanged` (the default) carries the stored seed forward by decrypting the
  existing payload here (reusing the already-unwrapped DEK); `Set`/`Clear` enrol/remove.
  `restore_from_history` translates the snapshot's seed into an explicit `Set`/`Clear` so a restore
  reverts the *old* TOTP.
- `payloads/login.rs`: `LoginPayload` gains `totp_params: TotpParams` (serde-default; pre-4.2 payloads
  read as SHA-1/6/30 — additive, no `payload_schema` bump). `AuditAction::TotpRevealed` added.

### `vedge-ipc` / `vedge-tauri` — the wire + commands
- `vedge-ipc/src/totp.rs` (NEW): `TotpAlgorithmDto`/`TotpCodeDto`/`TotpEnrolmentDto`/`TotpUpdateDto`.
  **The door:** `LoginPayloadDto` loses `totp_secret`, gains `has_totp` (non-invertible presence flag) +
  params + a `totp` intent (ignored outbound). Pinned by `login_dto_omits_totp_secret`.
- `vedge-tauri`: `dto/totp.rs` converters; `commands/totp.rs` — `reveal_totp` (reads host clock) +
  `parse_totp_enrolment` (**first stateless command**, no session). `update_entry` threads the intent;
  `copy_field`/`copy_history_field` inject the host clock. `audit_action_mapping_is_total` bumped
  **15 → 16** (the compile-time tripwire); `From<VaultError>` maps the new TOTP errors to `Invalid`.

### `vedge-ui` — `TotpDisplay` (secret-agnostic) + playground
- `foundation/totp_display.rs` (NEW): takes `code` + `seconds_remaining` signals — **it cannot
  generate** (no IPC / no core dep), correcting the design spec. Grouped digits, a `stroke-dashoffset`
  ring driven by `seconds_remaining` (never `animation: linear`), dim ≤ 5 s, `role="timer"` (no
  per-second SR spam), ring `aria-hidden`, `prefers-reduced-motion`. Mandatory playground page.

### `vedge-app` — reveal wiring + enrolment form
- `api/totp.rs` (NEW). `features/vault/totp_reveal.rs` (NEW): a "Show one-time code" button →
  `reveal_totp` → `TotpDisplay` + a 1 s ticker that re-invokes the reveal at the boundary; **Copy TOTP**
  routes through the 3.2-hardened backend clipboard (`FieldSelectorDto::TotpCode` — first construction
  in the app; adopts the orphaned `vault.copy_totp` key). `entry_form.rs`: the `totp: String` field
  becomes a `TotpUpdate` intent + presence + params; paste an `otpauth://` URI / secret → parse →

## Decisions

- **Full hand-roll (drop `totp-rs`)** — the headline above.
- **`has_totp` gate = explicit reveal, graceful** (Option A). The read detail view fetches no payload
  (so no password crosses to WASM), and `has_totp`-on-`IndexEntry` is deferred; a first-reveal failure
  degrades to a muted "no code" note. A proper presence gate (+ an entry-row badge) rides the deferred
  index change — backlog.
- **`TotpDisplay` is secret-agnostic** — it renders a live inline code, a genuinely new pattern in the
  read view (secrets were previously *never* rendered, only copied). Intentional: the code is a
  permitted derivative (short-lived, non-invertible, worthless expired); the seed never renders.
- **`update_entry` gains a conditional decrypt** (Login + `Unchanged`) — the caller (WASM) no longer
  holds the seed, so the carry-forward moves server-side.
- **Distinct parser errors** as dedicated `VaultError` variants (HOTP / migration / bad-params) so the
  UI + tests can tell them apart.

## Security

The **TOTP seed flows WASM → core only** (enrolment — the user pasted it) and **never core → WASM**.
The 6–8-digit code is a permitted derivative. `reveal_totp` decrypts server-side, generates, zeroizes,
and returns only the code; the wire test `login_dto_omits_totp_secret` pins that no `totp_secret` key
crosses. `ARCHITECTURE.md`'s egress rule is amended for the seed-vs-derivative split. The decoded seed
lives its whole life inside a `Zeroizing` buffer we own.
