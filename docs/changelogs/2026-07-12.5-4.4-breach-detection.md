# Slice 4.4 — Breach Detection (HIBP)

An **opt-in, off-by-default** HaveIBeenPwned *Pwned Passwords* check folded into
the existing `/v/health` scan. Rust computes SHA-1 of a credential-like secret,
sends **only the uppercase 5-hex prefix** to `api.pwnedpasswords.com/range/{prefix}`,
matches the suffix **locally**, and surfaces a `Breached { count }` finding. The
password and the full hash never leave the process; only the prefix egresses, and
only with explicit consent the **backend** verifies. Spec:
`.../Phase 4 - TOTP & Security Hygiene/Specs/4.4 - Breach Detection`.

Deliberately thin — **one PR, zero new dependencies, zero migrations, zero new
`AuditAction` variants** (the check runs inside the existing `HealthScanned` run;
`assert_eq!(all.len(), 17)` untouched).

## What shipped

### Core (`vedge-core`)
- **`domain/vault/health.rs`**: `FindingKind::Breached { count }` (severity always
  `High`), `HealthSummary.breached`, `HealthReport.breach_check_failed`. New pure
  helper `sha1_upper_hex` (+ `HIBP_PREFIX_LEN`) — uppercase-hex SHA-1, returned
  `Zeroizing` (it is a full password hash); unit-tested against a known vector.
- **`application/vault/ports/breach.rs`** (NEW): the `#[async_trait] BreachChecker`
  port (`range(prefix) -> Vec<(suffix, count)>`) with the error-mapping doc-contract
  (all failures → `VaultError::BreachLookup`; the caller degrades). `async-trait`
  was already a core dep — **no new dependency**.
- **`infrastructure/breach/{noop,memory}.rs`** (NEW): `NoopBreachChecker` and
  `MemoryBreachChecker` (corpus built from known-breached plaintext, hashed like the
  real checker; **records the prefixes it was asked** so a test can prove only the
  5-hex prefix crosses). `VaultError::BreachLookup`.
- **`use_cases/scan_health.rs`**: third param `Option<&dyn BreachChecker>` (`None`
  ⇒ skip the network phase; keeps `HealthScanInput` `Copy`). The SHA-1 is stashed
  **inside** the decrypt loop (gated on `WeakPolicy::Scored`) while the plaintext is
  live; the network phase runs **after** the loop (peak plaintext still one payload)
  and **before** `emit_reuse_findings` moves `groups`. Dedupe by **prefix**; a
  failed lookup sets `breach_check_failed` and emits zero `Breached` — never fails
  the scan.

### Wire (`vedge-ipc`)
- `FindingKindDto::Breached { count }`, `HealthSummaryDto.breached`,
  `HealthReportDto.breach_check_failed` (both `#[serde(default)]`). Extended
  `health_dtos_carry_no_secrets` to assert **no 40-hex SHA-1 fragment** ever appears
  in the serialized report, plus the wasm wire test (`wire_wasm.rs`) — verified with
  `cargo check -p vedge-ipc --target wasm32 --tests` (the trap `mise ci` can't run).

### Shell (`vedge-tauri`)
- **`breach/hibp.rs`** (NEW): `HibpBreachChecker` over `tauri_plugin_http::reqwest`
  (already compiled — **no new dep**). `Add-Padding: true`, a `VEdge/<version>`
  User-Agent, a 10 s timeout; `SUFFIX:COUNT` parsing is CRLF-tolerant and **discards
  `count == 0` padding rows**. Pure `parse_range_body` is unit-tested.
- **`AppState.breach`** + `resolve_breach()` env-gated seam (mirrors
  `resolve_biometric`): production always uses `HibpBreachChecker`; under a debug
  build **and** `VEDGE_E2E_BREACH_MEMORY` the e2e harness gets an offline
  `MemoryBreachChecker`. Wired through `compose` / `compose_test_state` /
  `test_support`.
- **`commands/health.rs`**: the **backend** reads `security.prefs.breach_check_enabled`
  from `app_settings` (a minimal `BreachPref` deser; missing/malformed → disabled,
  fail-safe) and passes `Some(&checker)` / `None`. Renderer never asserts consent.
- `dto/health.rs` mappers extended; `error.rs` maps `BreachLookup` (defensive — the
  scan degrades it internally). **Free cleanup:** removed the duplicate `http:default`
  in `migrated.json`; the HTTP capability scope stays **empty** (the Rust `reqwest`
  path bypasses the webview ACL — Decision 4).

### App (`vedge-app`)
- `SecurityPrefs.breach_check_enabled` (`#[serde(default)]`, off by default) + a
  Settings **Security** `<Toggle>` row whose copy names the egress plainly.
- `HealthTable` gains a `Breached` arm (`kind` badge = Danger, detail = `N exposures`);
  `HealthSummary` gains a Danger `Breached` badge; the page shows a **"breach check
  unavailable"** notice gated on `breach_check_failed`. i18n keys in **en + vi**.

### e2e
- `scan_health_shows_breached`: seeds a login with the offline double's known
  password, enables the opt-in (`set_app_setting`, the setup-via-invoke precedent),
  runs the scan from `/v/health`, asserts a row renders (DOM) + a `Breached` finding
  and `summary.breached == 1` (invoke). `VEDGE_E2E_BREACH_MEMORY` added to the harness
  launch env.

## Deviations / DRIFT from the spec
- **Scored-only fan-out (self-review, two-reviewer-confirmed).** Spec §2 step 3 says
  "emit a `Breached` finding for EVERY member of `groups[digest]`." Restricted to
  **`WeakPolicy::Scored`** members: a group can also hold policy-exempt fields (a card
  PIN / CVV / note that merely shares a value with a breached password), and labelling
  a 4-digit PIN a "breached password" is noise — the same Decision-5 rationale that
  exempts them from weak-scoring; the value-sharing is already surfaced by the Reuse
  dimension. Pinned by `breach_flags_only_scored_member_of_shared_group`.
- **`breach_checked` added to the report (self-review).** Not in the spec's type list.
  Without it, a `breached: 0` badge for the off-by-default case reads as a false
  all-clear ("HIBP confirmed clean") when no check ran. The summary badge is now gated
  on `breach_checked`; the disabled path is observable in tests.
- **Deterministic finding order (self-review).** `Breached` findings are collected and
  sorted by the stable `(entry, field)` key before emission (the per-scan HMAC digest
  is random), matching `emit_reuse_findings`' determinism.
- **DRIFT (spec said 11):** `tests/health.rs` had **10** `scan_health` call sites (now
  20 with the new breach tests), each taking `, None`/`Some(&…)`.
- **All-or-nothing degrade is intended** (spec §2 `break` on first `Err`): one mid-scan
  lookup failure discards partial hits rather than reporting incomplete results;
  `breach_check_failed` communicates the incompleteness.
- The age model stays **2-tier** (`Exact | Estimated`, 4.3a DRIFT); ipc DTO churn is the
  four breach fields (`FindingKindDto::Breached`, `HealthSummaryDto.breached`,
  `HealthReportDto.breach_checked`, `HealthReportDto.breach_check_failed`).

## Self-review outcomes
Five adversarial finder angles (correctness/line-by-line, cross-file/wire parity,
reactive-context, security/privacy egress, test-quality/altitude). Reactive-context,
cross-file, and security/privacy came back clean (only-prefix-egresses,
backend-verified consent, Scored-only hashing, capability not widened, no new
`AuditAction` all verified). **Five fixes applied:**
- **Fan-out to exempt fields** (2 finders): restricted to Scored members (see DRIFT).
- **False all-clear "Breached: 0"**: added `breach_checked`, gated the summary badge.
- **Nondeterministic `Breached` order**: collect + sort before emitting.
- **Tautological test assertion** (`breach_disabled_makes_no_network_call` inspected a
  checker the scan never received): rewritten to assert the observable
  `!breach_checked`.
- **Weak no-secrets tripwire**: the `windows(40)` check missed a 35-hex suffix leak →
  lowered to `windows(20)` (above the fixture's 17-char hex run, catches suffix + full
  hash).
**Accepted as intended:** the all-or-nothing degrade (spec-mandated); the e2e DOM
assertion is entry-name-based (breach-specificity comes from the compile-time
exhaustive match + the `invoke` finding-shape assertion).
