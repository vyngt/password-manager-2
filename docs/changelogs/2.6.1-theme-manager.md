# Slice 2.6.1 — Theme Manager (Appearance)

Fills the **Appearance** tab of 2.6's settings shell and wires the (already
complete, playground-proven) theme backend into the real app. **`vedge-app`-only**
— no `vedge-core` / `vedge-ipc` / `vedge-tauri` change. One commit on
`feature/2.6.1-theme-manager`; one PR.

Spec: `.../Specs/2.6.1 - Theme Manager`. Mockups: `.../Mockups/2.6.1 - Settings
Appearance` (theme list) + `2.6.1b - New Theme Editor`. The CRUD/preview flow is
an adapt of `pages/playground/theme.rs` + `theme_api.rs`.

## What shipped

### Startup injection — `app.rs`

The app now boots into the **saved** active theme: after providing `ThemeState`,
a one-shot `Effect` reads `api::settings::get_active_theme()` and
`theme.commit(&theme_config_from_dto(dto))` — which re-derives, injects the
`--color-*` cascade (whole-app recolor), and syncs the active-tokens signal. Falls
back to the seeded light config on error. Active-theme persistence stays **id-based**
via `set_active_theme` (the `commit_fn`/`revert_fn` stubs remain no-ops).

### Pure helpers — NEW `features/settings/theme_util.rs`

Host-tested converters/selectors bridging the IPC DTOs (`root_*`/`*_base`) and the
engine `ThemeConfig` (`background`/…/`danger`/…): `theme_config_from_dto`,
`config_from_fields` (blank optional → `None`), `create_input_from` /
`update_input_from`, `theme_swatches` (optional → engine default), `is_active`, and
`headline_contrast` (picks the blocking text-on-background + text-on-primary checks
by `pair_label` substring — a label rename trips the test rather than silently
mis-reporting).

### Theme list — NEW `features/settings/theme_list.rs` (the Appearance section)

`ThemeList` loads `list_themes` + `get_active_theme`, partitions by `is_built_in`
into **Built-in · read-only** / **Your themes**, and renders rows (`<For>` keyed by
`(id, updated_at)` so an edit repaints; the active radio/highlight is a per-row
`Memo` over `active_id`). Each row: active radio, five-swatch preview, name, type
`Badge`, and per-type `IconButton`s. Clicking a row applies it live
(`set_active_theme` → `ThemeState::commit`). **Built-in → Duplicate only; custom →
Edit / Duplicate / Delete** (a confirm `Dialog`; deleting the active theme falls
back to `builtin-light`). Actions stop-propagation so they don't also apply the row.

### Color editor — NEW `features/settings/theme_editor.rs`

A `Dialog` (mirrors 2.5.1 `folder_customize` — ColorPicker-in-dialog works since the
portal fix) with the six `ThemeConfig` inputs (3 required + 3 optional) as
`ColorPicker`s, a name field, a **scoped live preview**, headline contrast badges,
and Save. The preview is scoped: a `Memo` re-derives tokens on each change and a
subset of `--color-*` values are set as **inline custom properties** on a preview
container, so only that box renders in the draft theme (custom properties inherit to
its children) — the rest of the app is untouched, no commit/revert dance. Contrast
badges come from `validate_tokens` → `headline_contrast`. Save → `create_custom_theme`
(New/Duplicate) or `update_custom_theme` (Edit) → refresh.

### Wiring + i18n

- `settings.rs`: the `Appearance` tab arm now renders `<ThemeList/>` (dropped the
  `appearance_soon` placeholder).
- `locales/{en,vi}/settings.yaml`: theme + color keys added; `appearance_soon`
  removed. **No `build.rs` change** — the `settings` namespace already exists.

## Deviations (recorded in the tracking note)

1. **Duplicate opens the editor** (pre-filled, name "{x} copy", Save →
   `create_custom_theme`) rather than the one-click backend `duplicate_theme` — honors
   the acceptance criteria "New/Duplicate open the color editor"; `duplicate_theme`
   is left available for a future one-click path.
2. **Scoped preview** (inline `--color-*` on a preview container) instead of the
   playground's global `ThemeState::preview` + revert — matches the mockup's sample
   box and avoids whole-app flicker while editing an unsaved theme.
3. **Contrast shown as two headline badges** (text-on-background, primary) via
   `headline_contrast`, not the full 10-check list — matches the mockup; the engine
   still validates every pair.
4. The preview box's "Save / Input / Web" labels are static decorative sample chrome
   (a color swatch, not functional UI), so they're not i18n-wired.
