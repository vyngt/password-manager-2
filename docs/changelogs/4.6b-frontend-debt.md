# Slice 4.6b — Frontend Debt (Debt Paydown, part 2 of 2)

The frontend half of the phase's debt slice: a post-await disposal guard, a `<Select>`
that relocalizes without discarding its state, and a `<Pagination>` that renders a
**localized** summary. The backend half — 4.6a (Core & Scheduler) — shipped in PR #46.
Spec: `.../Phase 4 - TOTP & Security Hygiene/Specs/4.6 - Debt Paydown` (§§B1–B3).

**No new crate.** One `Select` prop type change (component-library) + a `Pagination`
prop surface extension; `interpolate_display` turned on as a **build-config option**
(not a Cargo feature — see B3). The pickup scan re-verified every anchor and corrected
the spec on three material points (called out below).

## B1 — the `try_*` disposal sweep (and the spec's panic premise was ⅓ true)

Component-scoped `StoredValue` accessors can be touched *after* an `.await`, by which
point the component may have unmounted (sidebar nav, idle auto-lock, OS screen-lock —
4.5a/4.5b manufactured new mid-flight unmount paths). The spec framed this as a panic
sweep across `get_value` / `set_value` / `update_value` and asked to **verify the
`set_value` claim before committing**.

- 🔴 **Verified against `reactive_graph 0.2.14`: only `get_value()` panics** on a
  disposed value (doc-commented `# Panics`). `set_value()` / `update_value()` delegate
  to their `try_*` form and **discard the result → a silent no-op**, not a panic. So the
  spec's "`totp_reveal.rs` is a live crash path" is **false for this leptos version.**
- **The one genuine panic fix:** `pages/v/manage/audit.rs:119` — `req_gen.get_value()`
  post-await → `try_get_value() != Some(token)` (exact twin of `health.rs:159`).
- **The five already-safe sites** (`totp_reveal.rs:68/76/107`, `auto_lock.rs:175/177`)
  were still converted to `try_*` — **behavior-preserving explicitness** that makes
  "this may run post-disposal" legible and future-proofs against a leptos semantics
  change. Decision recorded as DRIFT; the sweep's acceptance box is satisfied honestly.
- 🔴 **The auto_lock trap:** the conversions there are **discard-only, NOT early-returns.**
  An early-return on a disposed guard would skip the app-level toast + `lock_trigger`
  — dropping backend-lock propagation when the poller unmounts mid-`await`. The guards
  are local re-entrancy flags; the lock must still propagate.
- 🔴 **Review caught a wider gap in the same handler:** the post-await path also reads
  `expired_msg`/`dismiss_msg` — component-local **`Memo`s**, whose reads *panic* on a
  disposed value (only writes no-op). The fix **hoists those reads before the `await`**
  (while mounted) and moves the strings into the future — the totp_reveal `err_prefix`
  pattern. `lock_trigger` is a component `RwSignal` (`.update` no-ops on disposal), so it
  stays inside; the earlier comment that called it "app-level" is corrected.

## B2 — `Select` live-relocalize

`Select`'s `options: Vec<SelectItem>` was consumed by value into a `StoredValue` at
mount, so every localized call site wrapped the whole `<Select>` in a `{move || …}` that
**remounted** the component on a locale switch — discarding its open/highlight/type-ahead
state. Fixed by making the option list reactive.

- `options` → `#[prop(into)] options: Signal<Vec<SelectItem>>`; the trigger label + option
  list read `options` reactively. The panel/highlight/type-ahead state lives in the
  component body and **survives** because the instance is no longer remounted.
- 🟢 **Coercion verified:** `impl<T: Send+Sync+'static> From<T> for Signal<T>`
  (`reactive_graph/src/wrappers.rs:730`) makes a bare `Vec<SelectItem>` coerce to
  `Signal::stored(vec)` — so **all 23** `<Select>` call sites compile unchanged.
- 🔴 **Review caught an O(n²) regression + fixed it:** a first cut made `flat_options` an
  un-memoized `Signal::derive` read *once per option* in `render_option` → re-flattening
  the whole list per option (O(n²) allocations per open; a heavy `t_string!` constant on
  the audit filter). Fixed two ways: `flat_options` is now a **`Memo`** (`SelectOption`
  gains `PartialEq`; re-flattens only when `options` changes, for the keyboard/trigger
  reads), and `render_items` **threads each option's flat index via a running counter**
  (the render order matches `flatten_options`), so `render_option` no longer reads/scans
  the flat list at all.
- **Consumers rewired to gain the benefit:** `audit.rs:169/208` (dropped the `{move||}`
  remount wrappers → `Signal::derive`); `generator_panel.rs:804` (the `separator_options`
  `StoredValue`+`untrack` → a `Signal::derive`, which also relocalizes its labels and
  drops the eager-read `untrack`); `pagination.rs:74` (bare `Vec`, compiles unchanged).
- **DRIFT — scope cut:** the scan found **10 more** call sites (`settings.rs` ×3,
  `vault_filters.rs` ×3, `folder_move.rs` ×2, `tag_assign.rs`, `entry_form_body.rs`)
  sharing the identical `{move||}`-remount idiom. The spec's acceptance requires only the
  audit workaround deleted; converting the other 10 is a mechanical relocalize follow-up
  and was **deferred** to avoid sprawl.

## B3 — `Pagination` localizable summary (D2-Alt — see the pivot note)

`Pagination`'s summary/labels were hardcoded English `format!`s. 4.6b makes the summary
**localizable as a component capability**, and deliberately does **not** move the audit
page's summary into it (a `/code-review`-driven course change — see below).

- **Pagination stays locale-agnostic** (vedge-ui rule): the center-zone summary becomes a
  `TextProp` the *consumer* supplies, with an English `text_or` fallback that preserves
  standalone use — `summary` (e.g. "Showing 1–20 of 57") and `summary_empty` ("0 of 0").
  The built-in numeric `format!` is the fallback when the props are empty. Playground
  `pg_pagination` gains a section exercising both.
- **The audit page is unchanged** — it keeps its own localized `<p>` result-count summary
  (already correct, rendered via `t!` above the table). B1's `try_get_value` guard and
  B2's reactive-`Select` relocalize on the audit page are kept.

### 🔴 Pivot: D2-full → D2-Alt (the `/code-review` course change)

The plan's D2-full ("move the audit summary into `Pagination`, delete the `<p>`") was
implemented, then **reverted** after it accumulated disproportionate cost — all traced to
that one move:

- **A Windows rust-lld linker crash.** D2-full needs `interpolate_display` so the audit
  summary can cross as a `t_string!` **`String`** into a `TextProp`. (Correction to the
  spec: `interpolate_display` is **not a Cargo feature** in `leptos_i18n 0.6.2` — it's a
  `build.rs` codegen option, `ParseOptions::interpolate_display`.) Enabling it regrows
  `i18n.rs` / the wasm binary, which **deterministically crashes `rust-lld` (`0xC0000005`)
  on the local full-debuginfo wasm link** (`cargo check`/CI-Linux are unaffected — they
  don't link). Reverting `interpolate_display` removed the crash.
- **Overlapping paging state** — the consumer had to pass `total_items` + `page_size`
  **and** a baked-number summary (three props for the same numbers).
- **A11y / layout regressions** — the summary moved below the table, restyled, gained an
  `aria-live` that re-announced on every page change, and always-mounting left an empty
  "Pagination" nav landmark for single/empty results.

**D2-Alt** delivers the durable component fix (Pagination *can* render a localized summary)
without any of that. **DRIFT vs the spec's "delete the `<p>`":** the `<p>` stays; moving it
is a poor trade for those costs, and the component is now capable if a future layout
reconciles it. `interpolate_display` stays OFF; the compact `page_label` + per-button
`page_aria_label` localizations (spec §B3's `:129`/`:189`) are **dropped** — compact mode
has no product consumer and the aria prefix-concat is word-order-unsafe (both flagged by
the review); those two sites stay English (deferred).

## Tests — reality vs. the spec's test plan

**DRIFT:** vedge-ui has **no component-test harness** (no `wasm-bindgen-test`, no
`[dev-dependencies]`), and the e2e suite is **deliberately locale-independent**
(`data-testid`, never asserts translated text). So the spec's `select_relocalizes_without_remount`
and `pagination_summary_localizes` can't be in-process unit tests without new infra (its
own slice). They fall to the **manual smokes** the spec already lists. The existing pure
host tests (`build_page_window`, `pagination.rs`) are kept; the `en` e2e (`daily_loop`,
which drives audit pagination + Select via `data-testid`) is the no-regression bar.

- **The 10 sibling `<Select>` remount sites** and the audit `<p>` deletion — deferred/DRIFT
