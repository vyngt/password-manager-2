# 5.3.1a — DataTable, hardened (2026-07-16)

The first of slice 5.3.1's four PRs (**a** `DataTable` hardened · **b** the `vault_table` migration · **c**
selection + the action bar · **d** filters, relocation & export scope). This one touches **`vedge-ui` only** and
adds **zero app behaviour** — it grows the four capabilities the rest of the slice needs, so they can be
reviewed in isolation before any of the main screen changes.

`DataTable` already had the hard parts of an accessible grid — selection keyed by a **stable row id**, a
tri-state header checkbox, `role="grid"`, `aria-selected`/`aria-rowindex`/`aria-rowcount`, roving `tabindex`
with native focus sync, and shift-**click** ranges. This PR fills the four gaps that a selectable, drag-reorderable
main table (5.3.1b/c) requires.

## What it adds

- **`Ctrl/Cmd+A` — select all visible rows.** New pure `logic::select_all(keys)`; wired into the row keydown
  handler (guarded on `selectable`, so a non-selectable grid lets the browser keep the shortcut).
- **Keyboard `Shift+↑/↓` — range extend.** New pure `logic::extend_range(current, keys, anchor, target)` that
  unions the inclusive anchor→target range into the selection (the same union semantics as the existing
  shift-click, refactored to share one code path). The anchor is seeded from the focused row on first use and
  preserved across successive Shift+Arrows so the range pivots on it.
- **A row-drag hook.** New props `on_row_reorder: Option<Callback<(String, String)>>` (fires
  `(moved_key, target_key)`) + `reorder_enabled: Signal<bool>`. When enabled, each `<tr>` becomes `draggable`
  with the `text/plain` dataTransfer idiom (mirroring the hand-rolled `vault_table`) and a `--drag-over` inset
  drop-indicator. 🔴 **The payload is the stable `row_key`, never the index** (⓪) — a reorder can't mis-target
  after a re-sort.
- **Per-row attributes.** New prop `row_testid: Option<StringFn<T>>` renders `data-testid` on each `<tr>` — the
  backlog's "per-row `data-testid` is impossible today" item, which 5.3.1b's e2e needs.

All four are **additive props** with defaults, so the existing consumers (`audit_table`, `health_table`) are
untouched.

## ⓪ — the bug a reviewer will not see, made a unit test

Selection is a `Vec<String>` of `row_key`s, so it tracks the **entry**, not the row position — a re-sort of the
underlying `rows` cannot change which entries are selected. `logic.rs`'s
`selection_is_by_key_not_index_so_it_survives_a_resort` pins it, and the playground's Kitchen-sink section
demonstrates it live (select rows → click a sort header → the same entries stay checked). *(The index-scoped
`anchor`/`focus` still point at positions, but they only seed the next range/focus — never the current set.)*

## Playground

`pg_data_table.rs` gains a **Drag reorder** section (drag a row onto another; the order readout updates via the
stable-key hook) and the Kitchen-sink section documents the new keys + carries per-row `data-testid`.
