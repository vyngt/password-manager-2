# Slice 1.9 — Phase 1 Close-out

**Scope:** `vedge-app` only (cleanup + i18n + gates + docs). **Zero net-new features.** Ties off Phase 1 (create → add → list/detail/copy/delete → launch/unlock/lock).

## Changed

### Legacy / dead-code cleanup
- Deleted `features/vault/types.rs` (the `VaultItem` trio was already retired in 1.5; only the unused `Pagination*` types remained) and dropped `pub mod types;`.
- Removed the unused `pub use error::ApiError;` re-export from `api.rs`.
- Annotated the **not-yet-consumed typed IPC surface** (`api::{device,document,emergency_kit,entry,maintenance,password,recent,recovery,settings,tag,vault}`) with a module-level `#[allow(dead_code)]` + rationale — the wrappers are a complete mirror of the shell's command surface, kept for later phases.
- Fixed an `into_iter_on_ref` on the sidebar const slice (`layout.rs`).

### i18n completion (en + vi parity)
- **New `onboarding` namespace** — the create-vault wizard (`vault_setup.rs`) is fully localized (~32 keys: steps, heading, field labels/placeholders, strength labels, reveal/hide, Emergency-Kit help/warning, checkbox, and all error/status messages). Its "Copy is English literals for now" note is resolved.
- **New `nav` namespace** — the sidebar `Vault`/`Settings` labels (`layout.rs`).
- **`vault` additions** — `col_created`, the 10 entry-type labels (`type_login … type_other`), `loading`, and `err_load`/`err_delete`/`err_copy`. The pure `type_label(&EntryTypeDto) -> &'static str` became `type_label_i18n(i18n, …) -> String` (a `match` over `t_string!` keys), used by `vault_table.rs` + `vault_detail.rs`.
- **`unlock` additions** — `loading`, `err_recents`, `err_open` for the launch screen.
- Registered `onboarding` + `nav` in `build.rs::add_namespaces`; `src/i18n.rs` regenerates. Locale-dependent strings used inside `spawn_local` are read in the handler body first (the reactive-owner rule).
- No hardcoded user-facing strings remain in the store-data UI (dialog filter names / file extensions / default filenames / route paths / dev `console` logs excepted).

## Deviations (recorded)

1. **Lint gate scoped.** `vedge-core/ipc/tauri` pass full `-D warnings`; `vedge-app` passes `--no-deps -D warnings` at its **current** lint level. **Full `[lints] workspace = true` adoption on `vedge-app` is deferred** to a dedicated UI lint-adoption slice — measured at **408** pedantic/nursery/arithmetic warnings (99 `must_use`, 37 `match ()`, 28 `Self`, wildcard-import churn, …). `--no-deps` is required because `vedge-ui` (a dependency) carries **66** of its own pedantic warnings that `-D warnings` would otherwise promote to errors; that cleanup is also out of Phase-1 scope. This is the Cargo.toml's own `TODO(lint-adoption)` "UI-layer cleanup pass."
2. **Restore is API-only.** No trash/restore UI (Phase 3); `restore_entry` works via devtools. The close-out cycle's restore step is command-level (documented in the smoke).
3. **Manual GUI smoke unrun by me** (no headless Tauri). The automated layers prove create/unlock/entries/lock/persistence; the human click-path is in `docs/smokes/phase-1-create-vault.md`.
4. Entry-type labels moved from a pure `&'static str` fn to an i18n `match` (dropped one host test: 23 → 22).
