# Select

**Status:** Canonical · **Version:** 1.0 · **Layer:** Tier 1 — Atomic

---

## Purpose

A single-choice dropdown for selecting one value from a predefined list. Select is the correct component when the option set is fixed and known at design time, the number of options is too large for RadioGroup (more than ~5), or the choice is secondary and does not need all options visible simultaneously.

Select is not an Input with autocomplete. It is not a multi-select. It is not a combobox. If the user needs to type to filter options, use a future Combobox component.

---

## The three ownership boundaries

**The token system decides:** trigger appearance (matches Input visually), dropdown elevation tokens, option hover colors, and all transition timing.

**The Select decides:** how the trigger reflects the selected value vs. placeholder, how the dropdown positions itself (same rules as Tooltip: preferred side, flip, 8px offset), keyboard navigation within the option list, and trailing area content (chevron icon, always present).

**The consumer decides:** `value`, `options` list, `placeholder`, `size`, `disabled`, `status`, and `onChange`.

## Anatomy

```
[select-root]
  [trigger — looks identical to Input]
    [leading-icon?]        ← optional, same as Input
    [value or placeholder] ← flex:1
    [chevron-icon]         ← always present, replaces trailingIcon slot

  [dropdown-panel — portal, Level 3 elevation]
    [option × n]
    [separator?]           ← optional grouping
    [option-group-label?]  ← overline role
```

The trigger is visually identical to an Input component — same height, padding, border, and state colors. This is intentional: forms with Input and Select fields look cohesive because they share the same visual language.

The chevron icon always occupies the trailing area. Unlike Input, Select has no `trailingIcon` prop — the chevron is not overridable.

## Trigger states

Identical to Input states — same token mapping:

| State | Border | Background |
| --- | --- | --- |
| default | `--color-border` | `--color-surface-1` |
| hover | `--color-border-strong` | `--color-surface-1` |
| open (focus) | `--color-primary`  • focus ring | `--color-surface-1` |
| error | `--color-danger` (instant) | `--color-surface-1` |
| disabled | opacity 0.4 | `--color-surface-1` |

Chevron rotates 180° when the dropdown is open:

```
closed: rotate(0deg)
open:   rotate(180deg)
duration: var(--duration-fast) ease-out
```

## Sizes

Matches Input exactly. Same height tokens, same padding, same font size.

| Size | Height | Font | Padding X |
| --- | --- | --- | --- |
| `sm` | 28px | `text-xs` 12px | 10px |
| `md` | 36px | `text-sm` 14px | 12px |
| `lg` | 44px | `text-base` 16px | 16px |

---

## Dropdown panel

**Elevation:** Level 3 — `--color-surface-4`, `0.5px --color-border-strong`, `--shadow-md`.

**Width:** Matches trigger width minimum. May be wider if option text is long — never narrower.

**Max height:** 240px. Scrollable beyond that. The user should see ~6 options before scrolling.

**Option height:** 32px. Padding `0 10px`. Font `text-sm` regular.

**Option hover:** background `--color-surface-2`.

**Option selected:** background `--color-primary-muted`, text `--color-primary`, checkmark icon on the right.

**Motion:**

```
open:  translateY(-4px) + opacity(0) → translateY(0) + opacity(1)
       duration: var(--duration-fast) 150ms, ease-out
close: opacity(1) → opacity(0)
       duration: 100ms, ease-in
```

**Portal:** Dropdown renders outside the DOM flow (appended to body), same as Tooltip. Prevents clipping by `overflow:hidden` ancestors.

## Keyboard navigation

| Key | Action |
| --- | --- |
| Space / Enter | Opens dropdown (when trigger focused) |
| ↑ / ↓ | Moves focus between options |
| Enter / Space | Selects focused option, closes dropdown |
| Escape | Closes dropdown, returns focus to trigger |
| Home / End | Jumps to first / last option |
| Type characters | Jumps to first option matching typed string |

## Options data shape

```tsx
type Option = {
  value: string
  label: string
  disabled?: boolean
}

type OptionGroup = {
  label: string
  options: Option[]
}

type SelectOptions = (Option | OptionGroup)[]
```

## Props API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `options` | `SelectOptions` | — | **Required.** Flat list of options or grouped options. |
| `value` | `string` | — | Controlled selected value. |
| `defaultValue` | `string` | — | Uncontrolled default. |
| `placeholder` | `string` | — | Shown when no value selected. Renders in `--color-text-tertiary`. |
| `size` | `"sm" / "md" / "lg"` | `"md"` | Matches Input size tokens exactly. |
| `status` | `"default" / "error" / "success" / "warning"` | `"default"` | Validation state. Same border behavior as Input. |
| `disabled` | `boolean` | `false` | Opacity 0.4, pointer-events none. |
| `onChange` | `(value: string) => void` | — | Fires when selection changes. |
| `class` | `string` | — | Layout overrides only: width, margin. |

## Accessibility requirements

- **`role="combobox"`** on the trigger. `aria-expanded` reflects open state. `aria-haspopup="listbox"`.
- **`role="listbox"`** on the dropdown panel. `aria-labelledby` points to trigger ID.
- **`role="option"`** on each option. `aria-selected` on the currently selected option.
- **`aria-disabled`** on disabled options.
- Focus stays on the trigger — not on individual options. Options receive `aria-activedescendant` as the user arrows through.

---

## Anti-patterns

**Using Select for 2–3 options.** RadioGroup is better — all options visible simultaneously, no click required to reveal them.

**Overriding the chevron.** The chevron communicates "this opens a dropdown." Replacing it with a different icon breaks the affordance.

**Select for filtering large datasets.** If the option list is dynamic, async, or requires text search, use a Combobox (future component).
