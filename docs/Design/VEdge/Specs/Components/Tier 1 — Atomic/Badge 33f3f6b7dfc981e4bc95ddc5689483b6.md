# Badge

**Status:** Canonical · **Version:** 1.0 · **Layer:** Tier 1 — Atomic

---

## Purpose

A compact inline label that communicates status, category, or count. Badge is purely informational — it never receives focus, never triggers an action, and never changes state in response to user interaction. Its only job is to present a small piece of metadata alongside the content it annotates.

---

## The three ownership boundaries

**The token system decides:** background color, text color, border radius scale, font size, font weight, and padding. Badge reads semantic color tokens — never raw hex values.

**The Badge decides:** which padding to apply per size, how dot variant suppresses text, how the shape prop maps to border radius tokens, and how outline appearance maps border color to the variant's base token instead of its muted token. These are internal rules.

**The consumer decides:** `variant` (semantic color), `size`, `shape`, `appearance` (solid or outline), and whether to render as a dot. The consumer never passes a `color` prop.

---

## Anatomy

```
[badge-root — inline-flex]
  [dot?]     ← 6px circle, shape="dot" only
  [text]     ← label string, text-xs medium
```

Badge has no slots for icons or interactive elements. If a badge needs an icon, reconsider whether Badge is the right component — a chip or tag component (future Tier 2) is more appropriate.

---

## Variants

Five variants. Each maps directly to the semantic color group system.

| Variant | Background | Text | When to use |
| --- | --- | --- | --- |
| `default` | `--color-surface-3` | `--color-text-secondary` | Neutral metadata, category labels, counts |
| `info` | `--color-primary-muted` | `--color-primary` (or primary-800 for contrast) | Informational status, selected filter, active tag |
| `success` | `--color-success-muted` | `--color-success-text` | Confirmed, synced, verified, active |
| `warning` | `--color-warning-muted` | `--color-warning-text` | Expiring, needs attention, weak |
| `danger` | `--color-danger-muted` | `--color-danger-text` | Breached, compromised, expired, error count |

Default variant uses surface tokens, not semantic color tokens — it is intentionally neutral and does not communicate any valence. Use it for purely categorical labels ("Login", "Card", "Note") where semantic color would be misleading.

---

## Sizes

Two sizes. Badge does not have a `lg` size — a larger badge is competing for attention it should not have.

| Size | Height | Font | Padding | Use |
| --- | --- | --- | --- | --- |
| `sm` | 18px | `text-xs` 12px / medium | `2px 6px` | Sidebar counts, dense list metadata, table cells |
| `md` | 22px | `text-xs` 12px / medium | `4px 8px` | Default. Entry detail panel, settings rows, card headers |

Both sizes use `text-xs` — the font does not scale with size, only the padding and height change. Default is `md`.

---

## Shape

Two shapes, controlled by the `shape` prop.

**`pill`** (default) — `border-radius: var(--radius-full)` (9999px). Use for status labels, category tags, and any text-based badge where the rounded edges signal "label."

**`square`** — `border-radius: var(--radius-sm)` (4px). Use for numeric counts and version strings where the rectangular shape signals "number" or "code."

**`dot`** — No text. A 6×6px filled circle. Use in sidebar navigation to indicate an item has an unread notification or requires attention. Dot ignores `size` — it is always 6px.

```
pill:   [  Active  ]    ← rounded ends
square: [ 12 ]          ← 4px corners, numeric
dot:    ●               ← 6px circle, no text
```

---

## Appearance

Two appearances, controlled by the `appearance` prop.

**`solid`** (default) — muted background fill with matching text. The standard badge. Lower visual weight than a button, higher than plain text.

**`outline`** — transparent background with a 1px border in the variant's base color. Use when the solid muted background would blend with the surface behind it (e.g., badge inside a `surface-3` card), or to communicate "inactive" vs. "active" in a pair of badges.

```
solid:    [  Active  ]    ← muted fill, colored text
outline:  [  Active  ]    ← transparent, colored border + text
```

The `outline` appearance uses the variant's **base token** for both border and text — not the muted token. This ensures sufficient contrast on any surface.

`appearance` is ignored when `shape="dot"` — a dot is always a solid filled circle. An outlined dot would be too small to read.

---

## States

Badge has no interactive states. It does not respond to hover, focus, or active. It does not animate.

If a badge's variant or text needs to change in response to data updates, the parent component drives the change by re-rendering with new props. Badge does not own or animate the transition between variants.

---

## Props API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `"default" / "info" / "success" / "warning" / "danger"` | `"default"` | Semantic color. Drives background and text color. |
| `size` | `"sm" / "md"` | `"md"` | Physical scale. Height and padding only — font stays text-xs. |
| `appearance` | `"solid" / "outline"` | `"solid"` | Fill style. `solid` uses muted background; `outline` uses transparent background with a 1px border. Ignored when `shape="dot"`. |
| `shape` | `"pill" / "square" / "dot"` | `"pill"` | Border radius style. `dot` renders a circle with no text. |
| `children` | `string` | — | The label text. Plain string only. Not rendered when `shape="dot"`. |
| `class` | `string` | — | Layout overrides only: margin, flex-shrink. Not for color or padding. |

## CSS implementation reference

```css
.badge {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  font-family: var(--font-sans);
  font-size: var(--text-xs);
  font-weight: var(--font-weight-medium);
  line-height: 1;
  white-space: nowrap;
  user-select: none;
}

/* Sizes */
.badge--sm { height: 18px; padding: 0 6px; }
.badge--md { height: 22px; padding: 0 8px; }

/* Shapes */
.badge--pill   { border-radius: var(--radius-full); }
.badge--square { border-radius: var(--radius-sm); }
.badge--dot    {
  width: 6px; height: 6px;
  padding: 0;
  border-radius: var(--radius-full);
}

/* Variants — solid (default) */
.badge--default { background: var(--color-surface-3);     color: var(--color-text-secondary); }
.badge--info    { background: var(--color-primary-muted); color: var(--color-primary); }
.badge--success { background: var(--color-success-muted); color: var(--color-success-text); }
.badge--warning { background: var(--color-warning-muted); color: var(--color-warning-text); }
.badge--danger  { background: var(--color-danger-muted);  color: var(--color-danger-text); }

/* Variants — outline */
.badge--outline { background: transparent; border: 1px solid; }

.badge--outline.badge--default { color: var(--color-text-secondary); border-color: var(--color-border-strong); }
.badge--outline.badge--info    { color: var(--color-primary);        border-color: var(--color-primary); }
.badge--outline.badge--success { color: var(--color-success-text);   border-color: var(--color-success); }
.badge--outline.badge--warning { color: var(--color-warning-text);   border-color: var(--color-warning); }
.badge--outline.badge--danger  { color: var(--color-danger-text);    border-color: var(--color-danger); }
```

## Anti-patterns

**Using badge variant to color-code non-semantic categories.** Making "Login" green and "Card" blue because they are different entry types — not because one is more successful than the other — breaks the semantic meaning of variants. Use `default` for categorical labels and reserve semantic variants for actual status.

**Clickable badge.** A badge that triggers an action is a Button or a filter chip (Tier 2), not a Badge. If a badge needs `onClick`, the component is wrong.

**Long text in a badge.** Badge text should be 1–3 words. "Compromised" is fine. "Password was compromised in a data breach" is not — that belongs in helper text or a toast.

**Using badge for icons.** Badge has no icon slot. An icon + label combination is a chip/tag component.

**Outline badge on dot shape.** `appearance="outline"` is ignored when `shape="dot"`. A 6px circle with a 1px border and no fill is not legible. Dot is always solid.
