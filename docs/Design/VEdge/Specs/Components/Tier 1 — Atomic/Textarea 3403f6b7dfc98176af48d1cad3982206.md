# Textarea

**Status:** Canonical · **Version:** 1.0 · **Layer:** Tier 1 — Atomic

---

## Purpose

Multi-line text entry with auto-resize and max-height constraint. Wraps the native `<textarea>` element with the design token system, consistent sizing, and automatic height expansion as the user types.

Use Textarea wherever the expected input spans more than one line: secure notes, entry descriptions, SSH key paste, certificate PEM blocks, steganography text payload. For single-line input of any kind, use Input.

---

## The three ownership boundaries

**The token system decides:** border color per state, font size per size, padding, border radius, transition duration and easing, placeholder color.

**Textarea decides:** auto-resize behavior (expand on input, stop at `max_rows`), layout-shift prevention on focus border change, `resize: none` to disable the browser native drag handle.

**The consumer decides:** value, placeholder, initial height (`rows`), max height (`max_rows`), size, status, disabled, read-only.

---

## Anatomy

```
┌─────────────────────────────────────┐
│ text content                        │
│                                     │  ← grows with content
│                                     │  ← scrolls when max_rows reached
└─────────────────────────────────────┘
```

No leading or trailing slots. The text area is the entire component — unlike Input, there is no room for icons or action buttons inside the boundary.

Height is dynamic: starts at `rows × line-height + vertical-padding`, grows as the user types, stops scrolling at `max_rows × line-height + vertical-padding`. Beyond max-height, the content scrolls vertically.

---

## Sizes

Sizes control font size and padding. Height is dynamic — it is not fixed by size.

| Size | Font | Padding Y | Padding X | Use |
| --- | --- | --- | --- | --- |
| `sm` | 12px (`text-xs`) | 6px | 10px | Compact inline note fields |
| `md` | 14px (`text-sm`) | 8px | 12px | Default. All general text fields. |
| `lg` | 16px (`text-base`) | 10px | 16px | Prominent standalone areas: SSH key, cert paste |

Default size is `md`. Padding matches Input at each size — form layouts mixing Input and Textarea stay visually aligned.

## States

| State | Border | Background | Timing |
| --- | --- | --- | --- |
| `default` | `--color-border` (1px) | `--color-background` | — |
| `hover` | `--color-border-strong` (1px) | `--color-background` | 150ms ease-out |
| `focus` | `--color-focus-ring` (2px) | `--color-background` | **0ms — instant** |
| `error` | `--color-danger` (1px) | `--color-background` | **0ms — instant** |
| `success` | `--color-success` (1px) | `--color-background` | **0ms — instant** |
| `warning` | `--color-warning` (1px) | `--color-background` | **0ms — instant** |
| `disabled` | `--color-border` (1px) | `--color-background` | **0ms — instant** |
| `read_only` | `--color-border` (1px) | `--color-surface-1` | — |

**Focus border shift:** when the border changes from 1px (default) to 2px (focus), the content would shift by 1px without compensation. To prevent layout shift, padding is reduced by 1px on each side when focused — the total visual inset stays identical.

**`disabled` vs `read_only`:** disabled removes the field from tab order and sets `opacity: 0.4`. Read-only stays in tab order (content can be selected and copied), uses `--color-surface-1` background to signal non-editable, and does not change opacity.

No `active` state — Textarea has no press action.

No `loading` state — Textarea is synchronous.

---

## Keyboard

| Key | Behavior |
| --- | --- |
| `Tab` | Move focus to next focusable element. **Never trapped.** |
| `Shift+Tab` | Move focus to previous element |
| `Enter` | Insert newline |
| `Escape` | No effect on Textarea itself — propagates to parent |

`Tab` must not be intercepted to insert a tab character. This is a common anti-pattern that breaks keyboard-only navigation. If the consumer's content requires literal tab characters (e.g. code editors), that use case requires a dedicated code editor component, not Textarea.

## Props API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | — | Controlled value |
| `default_value` | `string` | `""` | Uncontrolled default |
| `placeholder` | `string` | — | Placeholder text. Renders in `--color-text-tertiary`. |
| `rows` | `u32` | `3` | Initial visible row count. Determines min-height. |
| `max_rows` | `u32` | `10` | Maximum rows before scrolling begins. |
| `size` | `"sm" / "md" / "lg"` | `"md"` | Font size and padding scale. |
| `status` | `"default" / "error" / "success" / "warning"` | `"default"` | Validation state. Drives border color. Instant (0ms). |
| `disabled` | `bool` | `false` | Inerts field. `opacity: 0.4`, removed from tab order. |
| `read_only` | `bool` | `false` | Content not editable. Stays in tab order. Surface-1 background. |
| `on_change` | `Callback<String>` | — | Fires on every input event with current value |
| `class` | `string` | — | Layout overrides only: margin, width, flex. Visual overrides not permitted. |

## Accessibility

- Native `<textarea>` element — no ARIA role needed
- Connected to Label via `id` / `for` pairing (or `aria-labelledby`)
- Connected to HelperText via `aria-describedby` — required when HelperText is present
- `aria-invalid="true"` when `status="error"`
- `aria-required` set by the parent Form Field when the field is required
- `disabled` via HTML `disabled` attribute — removes from tab order automatically
- `readonly` via HTML `readonly` attribute — stays in tab order, content selectable
- Min-height of `rows=2` ensures screen readers can identify the field as a multi-line input (single-row textareas are ambiguous with Input)

---

## Do not use

- For single-line input of any kind — use `Input`. Even if the value might occasionally be long (e.g. a URL, an email), use Input with appropriate width.
- For code, keys, or PEM certificates where **monospace font** is semantically required — apply `font-mono` via the `class` prop, or use a dedicated code field component if syntax highlighting is needed.
- For rich text with formatting (bold, links, lists) — Textarea accepts plain text only. Use a dedicated rich text editor.
- For short fixed-length inputs (PIN, OTP, verification code) — these have strict length constraints and specialized UX (one-character-per-box); Textarea's free-form model is wrong for them.

## CSS implementation

```css
.textarea {
  display: block;
  width: 100%;
  border: 1px solid var(--color-border);
  border-radius: var(--radius);
  background: var(--color-background);
  color: var(--color-text-primary);
  font-family: var(--font-sans);
  line-height: 20px; /* --text-sm line-height — matches md default */
  resize: none;      /* auto-resize via JS; browser handle disabled */
  overflow-y: auto;
  transition: border-color var(--duration-fast) var(--ease-out);

  /* Progressive enhancement: auto-resize without JS in supporting browsers */
  field-sizing: content;
}

/* Size variants — font + padding */
.textarea--sm {
  font-size: var(--text-xs);
  padding: 6px 10px;
  line-height: 16px;
}

.textarea--md {
  font-size: var(--text-sm);
  padding: 8px 12px;
  line-height: 20px;
}

.textarea--lg {
  font-size: var(--text-base);
  padding: 10px 16px;
  line-height: 24px;
}

/* Placeholder */
.textarea::placeholder {
  color: var(--color-text-tertiary);
}

/* Hover */
.textarea:hover:not(:focus):not(:disabled):not([readonly]) {
  border-color: var(--color-border-strong);
}

/* Focus — border 1px → 2px, padding compensates to prevent layout shift */
.textarea:focus {
  outline: none;
  border: 2px solid var(--color-focus-ring);
  transition: none; /* instant */
}

.textarea--sm:focus { padding: 5px 9px; }  /* 6-1, 10-1 */
.textarea--md:focus { padding: 7px 11px; } /* 8-1, 12-1 */
.textarea--lg:focus { padding: 9px 15px; } /* 10-1, 16-1 */

/* Status variants — instant */
.textarea--error   { border-color: var(--color-danger); }
.textarea--success { border-color: var(--color-success); }
.textarea--warning { border-color: var(--color-warning); }

/* Disabled */
.textarea:disabled,
.textarea--disabled {
  opacity: 0.4;
  cursor: not-allowed;
  pointer-events: none;
}

/* Read-only */
.textarea[readonly] {
  background: var(--color-surface-1);
  cursor: default;
}

@media (prefers-reduced-motion: reduce) {
  .textarea { transition-duration: 0.01ms !important; }
}
```

**Auto-resize JS** (fallback for browsers without `field-sizing: content`):

```jsx
function autoResize(el, maxRows, lineHeight) {
  el.style.height = 'auto';
  const maxHeight = maxRows * lineHeight + getPaddingY(el);
  el.style.height = Math.min(el.scrollHeight, maxHeight) + 'px';
}

// Wire on input event in Leptos component
```

`field-sizing: content` is the modern CSS-only solution. Use it as primary, JS as fallback. Do not use both simultaneously.
