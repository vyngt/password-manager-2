# Input

**Status:** Canonical · **Version:** 1.0 · **Layer:** Tier 1 — Atomic

---

## Purpose

The primary text entry primitive. Every form field where the user types a value — passwords, URLs, usernames, notes — uses Input. It is structurally more complex than Button because its internal layout must accommodate optional leading icons, trailing icons, prefix text, suffix text, and action slots without breaking the alignment contract or introducing layout shift.

Input's complexity lies in state machine depth: seven distinct states (default, hover, focus, error, success, disabled, read-only), status-driven border changes, and trailing area priority resolution.

---

## The three ownership boundaries

**The token system decides:** background color, border color per state, border radius, text colors, placeholder color, focus ring appearance, transition durations, and easing curves.

**The Input decides:** how border color changes per state and status, how internal layout accommodates optional slots, trailing content priority (spinner > clear > reveal toggle > user-supplied icon), and how read-only differs visually from disabled.

**The consumer decides:** `status`, `size`, `disabled`, `readOnly`, `loading`, `type`, `placeholder`, `value`/`defaultValue`, icon slots, prefix/suffix text, and event handlers. The consumer always chooses intent, never value. `status="error"` is correct. `borderColor="red"` is not permitted.

## Anatomy

```
[input-root — wrapper div, holds border + background]
  [leading-icon?]    ← 16×16 SVG, currentColor, flex-shrink:0
  [prefix-text?]     ← short read-only text: "https://", "$"
  [input]            ← native <input>, flex:1, transparent
  [trailing-area]    ← exactly one: spinner | status-icon | clear-btn | reveal-toggle | trailingIcon | empty
```

The root is a `<div>` with the visual border and background. The native `<input>` sits inside with `flex: 1`, no border, no background.

### Trailing area priority

At most one element occupies the trailing area. When multiple conditions apply simultaneously:

```
loading  >  status-icon  >  clearable  >  reveal-toggle  >  trailingIcon
```

This priority is internal. The consumer does not manage it.

### Leading area

`leadingIcon` (16×16 icon) and `prefix` (text string) are mutually exclusive. Both provided → dev assertion.

## Sizes

Heights are derived from the typography system, not chosen independently.

```
height = line-height(font-size) + (2 × padding-y)

sm:  28px = 16px (text-xs)    + (2 × 6px)
md:  36px = 20px (text-sm)    + (2 × 8px)   ← default
lg:  44px = 24px (text-base)  + (2 × 10px)
```

| Size | Height | Font | Padding X | Icon size | Use |
| --- | --- | --- | --- | --- | --- |
| `sm` | 28px | 12px | 10px | 14×14 | Compact forms, inline table edits |
| `md` | 36px | 14px | 12px | 16×16 | Default. All general form fields. |
| `lg` | 44px | 16px | 16px | 16×16 | Master password unlock, prominent search |

Default is `md`. Specifying `size="md"` explicitly is redundant.

## Status

Input uses `status` instead of `variant`. Status describes validation state — a property that changes dynamically in response to user input.

| Status | Border color | Trailing icon | Transition | When to use |
| --- | --- | --- | --- | --- |
| `default` | `--color-border` | none | 150ms | Resting, no validation outcome yet |
| `error` | `--color-danger` | AlertCircle in `--color-danger-text` | **0ms (instant)** | Validation failed |
| `success` | `--color-success` | CheckCircle in `--color-success-text` | 150ms | Validation passed |
| `warning` | `--color-warning` | AlertTriangle in `--color-warning-text` | 150ms | Valid but needs attention |

Error is instant (0ms) — the user has just submitted and is waiting for feedback. Any delay before the red border communicates "nothing happened."

Background stays `--color-surface-1` in all status states. Background changes on validation would be visually loud.

## States

Seven states. All required. Skipping any state is a bug.

### Default

```
background:   var(--color-surface-1)
border:       1px solid var(--color-border)
text:         var(--color-text-primary)
placeholder:  var(--color-text-tertiary)
```

### Hover

Border shifts to stronger color — communicates interactivity before focus. Background does not change.

```
border-color: var(--color-border-strong)
transition:   border-color 150ms ease-out
```

### Focus

Two simultaneous signals with different timing:

```
border-color:    var(--color-primary)              150ms ease-out
outline:         2px solid var(--color-focus-ring)  0ms  (instant)
outline-offset:  2px
caret-color:     var(--color-primary)
```

The `outline` is the accessibility signal — always instant, never suppressed. The border color change is visual polish that can ease in. They are independent.

When `status="error"`, the border stays `--color-danger` during focus. Error condition takes precedence over focus color. Focus ring still appears normally.

### Disabled

```
opacity:        0.4
cursor:         not-allowed
pointer-events: none (on root wrapper)
```

Applied via HTML `disabled` attribute on native input — not CSS class alone. Removes field from tab order. Appears at 0ms (instant).

### Read-only

Focusable and selectable but not editable.

```
background:     var(--color-surface-2)   slightly more tinted
cursor:         text                      can select and copy
pointer-events: auto                      stays in tab order
```

No hover border change. Focus ring still shows (keyboard can still copy). Use for revealed passwords, auto-filled values, display-mode fields. Use `disabled` only when the field is locked and irrelevant.

### Loading

```
trailing area:  spinner (13px sm/md, 15px lg), 700ms linear
pointer-events: none on native input
opacity:        1.0 (visible, not dimmed)
```

Loading is not disabled: field stays in tab order, value is visible, opacity unchanged.

## Supported input types

### Tier 1 — Enhanced

Component detects these types and adds behavior beyond the browser.

**`type="password"`** — Trailing area always contains a reveal toggle (eye/eye-off icon) that switches between `type="password"` and `type="text"` via JS. Changing the attribute (not CSS) ensures the browser's password manager observes state correctly. `aria-label` on toggle updates dynamically: "Show password" ↔ "Hide password".

**`type="search"`** — When field has a value, trailing area shows clear button (×). Fires `onChange("")` + refocuses input on click. Priority lower than status icon and spinner.

### Tier 2 — Pass-through

Component contributes its chrome; browser handles type-specific rendering.

| Type | Notes |
| --- | --- |
| `text` | Default. General single-line text entry. |
| `email` | Browser validates format, shows email keyboard on mobile. |
| `tel` | Numeric keyboard on mobile. No browser-side format validation. |
| `url` | Browser validates URL format. |

### Tier 3 — Out of scope

These types require fundamentally different UI. Each must be its own dedicated component.

| Type | Component | Reason |
| --- | --- | --- |
| `number` | NumberInput | Browser spin buttons not styleable cross-platform. Needs custom increment controls, min/max/step enforcement, optional unit label. |
| `date` | DatePicker | Browser native picker inherits OS styling, not token colors. Appearance differs across macOS/Windows/Linux. |
| `time` | TimePicker | Same reason as `date`. Needs custom hour/minute selectors. |
| `datetime-local` | DateTimePicker | Combines problems of both `date` and `time`. |
| `month` / `week` | DatePicker variant | Niche granularity, handled as DatePicker variant. |
| `range` | Slider | Custom track, thumb, and value tooltip cannot fit inside Input's border container. |
| `file` | FileUpload | Requires drag zone, file list preview, progress state, remove affordance. |
| `color` | ColorPicker | Browser color picker UI is platform-specific and cannot be overridden. |
| `checkbox` | Checkbox | Custom toggle element, indeterminate state, different label wiring. |
| `radio` | RadioGroup | Mutual exclusivity logic, group management, layout variants. |
| `hidden` | (none) | No UI — use `<input type="hidden">` directly. |

Passing any Tier 3 type to Input triggers a dev assertion: `Input does not support type="checkbox". Use the Checkbox component instead.`

Full assertion list: `checkbox`, `radio`, `range`, `file`, `color`, `number`, `date`, `time`, `datetime-local`, `month`, `week`.

## Props API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"sm" | "md" | "lg"` | `"md"` | Physical scale. Height derived from typography system. |
| `status` | `"default" | "error" | "success" | "warning"` | `"default"` | Validation state. Drives border color, status icon, transition timing. |
| `type` | `string` | `"text"` | Native input type. Enhanced for `password`/`search`. Pass-through for `text`/`email`/`tel`/`url`. Dev assertion for all Tier 3 types. |
| `value` | `string` | — | Controlled value. |
| `defaultValue` | `string` | — | Uncontrolled default. |
| `placeholder` | `string` | — | Renders in `--color-text-tertiary`. |
| `disabled` | `boolean` | `false` | Via HTML `disabled` attribute. Removes from tab order. |
| `readOnly` | `boolean` | `false` | Via HTML `readonly`. Stays in tab order, not editable. |
| `loading` | `boolean` | `false` | Spinner in trailing area. Input non-editable, opacity unchanged. |
| `leadingIcon` | `Slot` | — | 16×16 SVG before input text. Mutually exclusive with `prefix`. |
| `trailingIcon` | `Slot` | — | 16×16 SVG after input text. Replaced by higher-priority trailing elements. |
| `prefix` | `string` | — | Read-only text before input, e.g. `"https://"`, `"$"`. Mutually exclusive with `leadingIcon`. |
| `suffix` | `string` | — | Read-only text after input, e.g. `".com"`, `"USD"`. |
| `id` | `string` | — | Effectively required. Must match Label's `for` attribute. |
| `aria-describedby` | `string` | — | Points to HelperText element ID. Required when helper/error text is present. |
| `class` | `string` | — | Layout overrides only: margin, width, flex. Not for color, border, padding. |

### By state

| State | Property | Token |
| --- | --- | --- |
| default | background | `--color-surface-1` |
| default | border-color | `--color-border` |
| default | text color | `--color-text-primary` |
| default | placeholder | `--color-text-tertiary` |
| hover | border-color | `--color-border-strong` |
| focus | border-color | `--color-primary` |
| focus | outline | `2px solid --color-focus-ring`, offset 2px |
| error | border-color | `--color-danger` |
| error | status icon | `--color-danger-text` |
| success | border-color | `--color-success` |
| success | status icon | `--color-success-text` |
| warning | border-color | `--color-warning` |
| disabled | opacity | 0.4 |
| read-only | background | `--color-surface-2` |

### Motion tokens consumed

```
--duration-instant   0ms    focus ring, error status, disabled state
--duration-fast    150ms    hover border, focus border, success/warning status
--ease-out         cubic-bezier(0.16, 1, 0.3, 1)
```

## Composability

Input is designed to be used inside a **FormField** compound. It does not manage its own label, helper text, or error message.

```
FormField [flex-col]
  Label        [for="field-id", status="error"]    ← margin-bottom: 6px
  Input        [id="field-id",  status="error"]
  HelperText   [status="error"]                     ← margin-top: 4px
```

Inputs without a visible Label still need `aria-label` on the Input or a visually hidden label element. An Input with no label at all is an accessibility failure.

Input never has margin props. Spacing between form groups is owned by the form layout, not the component.

---

## Accessibility requirements

- **`id` matches Label's `for`.** Without association, screen readers cannot announce the label on focus.
- **`aria-describedby` connects to HelperText.** Screen readers read helper text after the label on focus.
- **`aria-invalid="true"` when `status="error"`.** Border color change is visual-only.
- **`aria-required="true"` for required fields.** The asterisk on Label is `aria-hidden`.
- **Focus ring never suppressed** — not for read-only, not for any type.
- **Reveal toggle is keyboard accessible.** In tab order after the input. `aria-label` updates with state. Operable with Space and Enter.
- **`autocomplete` attribute.** Use `current-password`, `new-password`, `username`, `one-time-code` for sensitive fields.

---

## Anti-patterns

**Setting `border-color` via `class`.** Use `status="error"` — not a class override.

**Using `placeholder` as a label.** Placeholder disappears on type. Every input needs a persistent visible label or `aria-label`.

**Animating the error state.** `status="error"` appears at 0ms. Error must be instant.

**Two trailing icons.** The trailing area holds exactly one element. The priority system resolves conflicts.

**Using `disabled` for display-mode fields.** `disabled` removes from tab order. Use `readOnly` if the user needs to read or copy.

**Manually handling password reveal.** Set `type="password"` and let Input manage the reveal toggle internally.

**Setting `width` directly.** Width belongs to the parent layout.
